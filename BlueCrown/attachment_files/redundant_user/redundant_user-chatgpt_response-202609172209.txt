Yes. I would replace both earlier versions with a more disciplined **audit → review → purge → verify** utility.

The GitHub version is a useful improvement, particularly its `--execute --yes`, `--user-id`, CLI-only restriction, transaction, and dynamic table/column checks. However, I would change several things before using it on Buzzjuice:

* **Do not count the same row multiple times** when it has multiple orphan references.
* Keep the **authoritative `Wo_DeleteUser()` reference map**, but also perform a **schema discovery audit**.
* Do **not automatically purge discovered-but-unconfirmed columns**.
* Generate a persistent **JSON audit report**.
* Support `--table`, `--user-id`, and `--limit`.
* Use **per-table transactions**, rather than one potentially huge transaction across the entire database.
* Re-audit after deletion.
* Record **actual row counts**, not "reference matches".
* Preserve the distinction between **confirmed references** and **possible/unmapped references**.
* Never touch `Wo_Users`.
* Never touch files/S3/WordPress/QuickDate.
* Correct the `from_id ` typo noted in the original WoWonder deletion function.
* Detect table/column names from the actual database, because WoWonder installations can differ.
* Add protection against accidentally treating arbitrary `id`, `owner_id`, `member_id`, etc. columns as user references.
* Make the dry run useful enough that we can inspect it before permitting deletion.

The existing Buzzjuice `db_helpers.php` exposes `get_wowonder_db()` and loads the WoWonder credentials from the environment, so the utility can use the existing connection infrastructure rather than duplicating credentials. ([GitHub][1]) The current `functions_one.php` is also very large, so I would avoid modifying it for this maintenance operation. ([GitHub][2])

# Updated architecture

I recommend:

```text
                     Wo_Users
                        │
                        ▼
              Existing User-ID Set
                        │
             ┌──────────┴──────────┐
             │                     │
             ▼                     ▼
     Confirmed Wo_DeleteUser   Schema Discovery
        reference map             audit
             │                     │
             ▼                     ▼
       CONFIRMED ORPHANS      POSSIBLE REFERENCES
             │                     │
             └──────────┬──────────┘
                        ▼
                  JSON + CLI Report
                        │
                  HUMAN REVIEW
                        │
                        ▼
               --execute --yes
                        │
                        ▼
                Per-table purge
                        │
                        ▼
                  Second audit
```

The important architectural decision is that **schema discovery is advisory only**. A column being called `owner_id` does not prove that it references `Wo_Users.user_id`.

```php
function bzj_get_tables(
    mysqli $conn
): array {

    $tables = [];

    $result = bzj_query(
        $conn,
        "SHOW TABLES"
    );

    while ($row = $result->fetch_row()) {

        if (
            isset($row[0]) &&
            is_string($row[0])

            $tables[] = $row[0];
        }
    }

    return $tables;

function bzj_get_columns(
    mysqli $conn,
    string $table
): array {

    $quotedTable =
        bzj_quote_identifier($table);

    $result = bzj_query(
        $conn,
        "SHOW COLUMNS FROM {$quotedTable}"
    );

    $columns = [];

    while ($row = $result->fetch_assoc()) {

        if (
            !isset($row['Field'])
        ) {
            continue;
        }

        $name = (string) $row['Field'];

        $columns[
            strtolower($name)
        ] = [
            'name' => $name,
            'type' => $row['Type'] ?? '',
            'null' => $row['Null'] ?? '',
            'key' => $row['Key'] ?? '',
        ];
    }

    return $columns;
}

/**
 * Creates a temporary indexed set of currently existing user IDs.
 *
 * This is substantially more efficient than repeatedly doing:
 *
 * NOT IN (SELECT user_id FROM Wo_Users)
 *
 * for every column in every table.
 */
function bzj_prepare_existing_users(
    mysqli $conn
): void {

    bzj_query(
        $conn,
        "DROP TEMPORARY TABLE IF EXISTS
         `bzj_existing_user_ids`"
    );


    bzj_query(
        $conn,
        "
        CREATE TEMPORARY TABLE
        `bzj_existing_user_ids` (
            `user_id` BIGINT UNSIGNED NOT NULL,
            PRIMARY KEY (`user_id`)
        ) ENGINE=InnoDB
        "
    );


    bzj_query(
        $conn,
        "
        INSERT INTO
        `bzj_existing_user_ids`
        (`user_id`)
        SELECT DISTINCT
            CAST(`user_id` AS UNSIGNED)
        FROM `Wo_Users`
        WHERE `user_id` IS NOT NULL
          AND CAST(`user_id` AS UNSIGNED) > 0
        "
    );
}


function bzj_existing_user_count(
    mysqli $conn
): int {

    $result = bzj_query(
        $conn,
        "
        SELECT COUNT(*) AS `total`
        FROM `bzj_existing_user_ids`
        "
    );

    $row =
        $result->fetch_assoc();

    return (int) (
        $row['total'] ?? 0
    );
}


/* ==============================================================
 * ORPHAN CONDITIONS
 * ============================================================== */

/**
 * Build the canonical orphan condition.
 *
 * A value is considered an orphan user reference when:
 *
 * - it is not NULL
 * - it is not empty
 * - its numeric value is > 0
 * - that numeric value is absent from Wo_Users
 *
 * Existing values such as 0 are deliberately ignored.
 */
function bzj_orphan_condition(
    string $column,
    ?int $filterUserId = null
): string {

    $quotedColumn =
        bzj_quote_identifier($column);


    $condition = "
        {$quotedColumn} IS NOT NULL
        AND {$quotedColumn} <> ''
        AND CAST({$quotedColumn} AS UNSIGNED) > 0
        AND NOT EXISTS (
            SELECT 1
            FROM `bzj_existing_user_ids` AS `existing_users`
            WHERE
                existing_users.`user_id`
                =
                CAST(
                    {$quotedColumn}
                    AS UNSIGNED
                )
        )
    ";


    if ($filterUserId !== null) {

        $condition .= "
            AND CAST(
                {$quotedColumn}
                AS UNSIGNED
            ) = "
            . (int) $filterUserId;
    }


    return $condition;
}

/**
 * Resolve the actual table existing in this installation.
 */
function bzj_resolve_table(
    mysqli $conn,
    string $logicalTable
): ?string {

    foreach (
        bzj_table_aliases($logicalTable)
        as $candidate
    ) {

        if (
            bzj_table_exists(
                $conn,
                $candidate
            )
        ) {
            return $candidate;
        }
    }


    return null;
}

/**
 * Determine which configured columns actually exist.
 */
function bzj_available_reference_columns(
    mysqli $conn,
    string $table,
    array $configuredColumns
): array {

    $columns =
        bzj_get_columns(
            $conn,
            $table
        );


    $available = [];


    foreach (
        $configuredColumns
        as $configuredColumn
    ) {

        $key =
            strtolower(
                $configuredColumn
            );


        if (
            isset(
                $columns[$key]
            )
        ) {

            $available[] =
                $columns[$key]['name'];
        }
    }


    return $available;
}


/**
 * Count DISTINCT physical rows that contain at least one orphan
 * reference.
 *
 * This is the important correction over the GitHub implementation:
 *
 * A single row with both follower_id and following_id orphaned is
 * ONE orphan row, not TWO.
 */
function bzj_count_orphan_rows(
    mysqli $conn,
    string $table,
    array $columns,
    ?int $filterUserId = null
): int {

    if (empty($columns)) {
        return 0;
    }


    $conditions = [];


    foreach (
        $columns
        as $column
    ) {

        $conditions[] =
            '('
            . bzj_orphan_condition(
                $column,
                $filterUserId
            )
            . ')';
    }


    $where =
        implode(
            ' OR ',
            $conditions
        );


    $quotedTable =
        bzj_quote_identifier($table);


    $result =
        bzj_query(
            $conn,
            "
            SELECT COUNT(*) AS `total`
            FROM {$quotedTable}
            WHERE {$where}
            "
        );


    $row =
        $result->fetch_assoc();


    return (int) (
        $row['total'] ?? 0
    );
}


/**
 * Return per-column counts for reporting.
 */
function bzj_column_counts(
    mysqli $conn,
    string $table,
    array $columns,
    ?int $filterUserId = null
): array {

    $counts = [];


    $quotedTable =
        bzj_quote_identifier($table);


    foreach (
        $columns
        as $column
    ) {

        $condition =
            bzj_orphan_condition(
                $column,
                $filterUserId
            );


        $result =
            bzj_query(
                $conn,
                "
                SELECT COUNT(*) AS `total`
                FROM {$quotedTable}
                WHERE {$condition}
                "
            );


        $row =
            $result->fetch_assoc();


        $counts[$column] =
            (int) (
                $row['total'] ?? 0
            );
    }


    return $counts;
}


/**
 * Return distinct orphan user IDs.
 */
function bzj_get_orphan_user_ids(
    mysqli $conn,
    string $table,
    array $columns,
    ?int $filterUserId = null,
    int $limit = 20
): array {

    $ids = [];


    foreach (
        $columns
        as $column
    ) {

        $condition =
            bzj_orphan_condition(
                $column,
                $filterUserId
            );


        $quotedTable =
            bzj_quote_identifier($table);

        $quotedColumn =
            bzj_quote_identifier($column);


        $result =
            bzj_query(
                $conn,
                "
                SELECT DISTINCT
                    CAST(
                        {$quotedColumn}
                        AS UNSIGNED
                    ) AS `orphan_user_id`
                FROM {$quotedTable}
                WHERE {$condition}
                ORDER BY
                    `orphan_user_id`
                LIMIT "
                . (int) $limit
            );


        while (
            $row =
            $result->fetch_assoc()
        ) {

            $id =
                (int) (
                    $row['orphan_user_id']
                    ?? 0
                );


            if ($id > 0) {
                $ids[$id] = true;
            }
        }
    }


    $ids =
        array_keys($ids);

    sort($ids);


    return array_slice(
        $ids,
        0,
        $limit
    );
}

/**
 * Find columns that look like user references but are NOT part
 * of the confirmed Wo_DeleteUser() map.
 *
 * These findings are advisory only.
 */
function bzj_discover_unmapped_references(
    mysqli $conn,
    array $confirmedMap,
    ?string $filterTable = null,
    ?int $filterUserId = null,
    int $sampleLimit = 10
): array {

    $confirmed = [];


    foreach (
        $confirmedMap
        as $logicalTable => $columns
    ) {

        $actualTable =
            bzj_resolve_table(
                $conn,
                $logicalTable
            );


        if ($actualTable === null) {
            continue;
        }


        foreach (
            $columns
            as $column
        ) {

            $confirmed[
                strtolower($actualTable)
            ][
                strtolower($column)
            ] = true;
        }
    }


    $tables =
        bzj_get_tables($conn);


    $findings = [];


    foreach (
        $tables
        as $table
    ) {

        if (
            $filterTable !== null &&
            strcasecmp(
                $table,
                $filterTable
            ) !== 0
        ) {
            continue;
        }


        /*
         * Never inspect Wo_Users as an orphan-reference table.
         */
        if (
            strcasecmp(
                $table,
                BZJ_USERS_TABLE
            ) === 0
        ) {
            continue;
        }


        $columns =
            bzj_get_columns(
                $conn,
                $table
            );


        foreach (
            $columns
            as $column
        ) {

            $columnName =
                $column['name'];


            $columnKey =
                strtolower(
                    $columnName
                );


            /*
             * Candidate must match our conservative list.
             */
            if (
                !in_array(
                    $columnKey,
                    BZJ_DISCOVERY_COLUMN_PATTERNS,
                    true
                )
            ) {
                continue;
            }


            /*
             * Skip confirmed references.
             */
            if (
                isset(
                    $confirmed[
                        strtolower($table)
                    ][$columnKey]
                )
            ) {
                continue;
            }


            /*
             * Skip obvious primary ID columns.
             */
            if (
                $columnKey === 'id' ||
                $column['key'] === 'PRI'
            ) {
                continue;
            }


            try {

                $condition =
                    bzj_orphan_condition(
                        $columnName,
                        $filterUserId
                    );


                $quotedTable =
                    bzj_quote_identifier(
                        $table
                    );


                $result =
                    bzj_query(
                        $conn,
                        "
                        SELECT COUNT(*) AS `total`
                        FROM {$quotedTable}
                        WHERE {$condition}
                        "
                    );


                $row =
                    $result->fetch_assoc();


                $count =
                    (int) (
                        $row['total']
                        ?? 0
                    );


                if ($count <= 0) {
                    continue;
                }


                $sampleIds =
                    bzj_get_orphan_user_ids(
                        $conn,
                        $table,
                        [$columnName],
                        $filterUserId,
                        $sampleLimit
                    );


                $findings[] = [
                    'table' => $table,
                    'column' => $columnName,
                    'count' => $count,
                    'sample_user_ids' =>
                        $sampleIds,
                    'automatic_purge' => false,
                ];

            } catch (Throwable $e) {

                bzj_log(
                    "Schema discovery failed for "
                    . "{$table}.{$columnName}: "
                    . $e->getMessage()
                );
            }
        }
    }


    return $findings;
}

/**
 * Delete orphan rows for ONE table in ONE transaction.
 *
 * This is intentionally table-scoped.
 *
 * A huge transaction across dozens of tables can create unnecessary
 * locking, undo-log growth, and rollback cost.
 */
function bzj_delete_table_orphans(
    mysqli $conn,
    string $table,
    array $columns,
    ?int $filterUserId = null
): int {

    if (empty($columns)) {
        return 0;
    }


    $conditions = [];


    foreach (
        $columns
        as $column
    ) {

        $conditions[] =
            '('
            . bzj_orphan_condition(
                $column,
                $filterUserId
            )
            . ')';
    }


    $where =
        implode(
            ' OR ',
            $conditions
        );


    $quotedTable =
        bzj_quote_identifier($table);


    $sql = "
        DELETE FROM {$quotedTable}
        WHERE {$where}
    ";


    $conn->begin_transaction();


    try {

        bzj_query(
            $conn,
            $sql
        );


        $affected =
            $conn->affected_rows;


        $conn->commit();


        return $affected;

    } catch (Throwable $e) {

        $conn->rollback();

        throw $e;
    }
}


/* ==============================================================
 * JSON REPORT
 * ============================================================== */

function bzj_write_report(
    string $path,
    array $report
): void {

    $directory =
        dirname($path);


    if (
        !is_dir($directory)
    ) {

        if (
            !@mkdir(
                $directory,
                0750,
                true
            )
        ) {

            throw new RuntimeException(
                "Unable to create report directory: "
                . $directory
            );
        }
    }


    $json =
        json_encode(
            $report,
            JSON_PRETTY_PRINT
            | JSON_UNESCAPED_SLASHES
        );


    if ($json === false) {

        throw new RuntimeException(
            "Unable to encode JSON report: "
            . json_last_error_msg()
        );
    }


    if (
        @file_put_contents(
            $path,
            $json . PHP_EOL,
            LOCK_EX
        ) === false
    ) {

        throw new RuntimeException(
            "Unable to write report: {$path}"
        );
    }
}

}


$report[
    'execution'
][
    'remaining_orphan_rows'
] =
    $remaining;


/* ==============================================================
 * FINAL REPORT UPDATE
 * ============================================================== */

$report[
    'completed_at'
] =
    date('c');


$report[
    'summary'
] = [
    'confirmed_orphan_rows_before_purge' =>
        $totalOrphanRows,

    'deleted_rows' =>
        $totalDeleted,

    'remaining_confirmed_orphan_rows' =>
        $remaining,

    'discovered_unmapped_references' =>
        count(
            $report[
                'discovered'
            ][
                'references'
            ]
        ),

    'failed_operations' =>
        count(
            $report[
                'execution'
            ][
                'failed_tables'
            ]
        ),
];


if ($reportPath !== null) {

    try {

        bzj_write_report(
            $reportPath,
            $report
        );

    } catch (Throwable $e) {

        bzj_print(
            "WARNING: Final JSON report update failed: "
            . $e->getMessage()
        );
    }
}


/* ==============================================================
 * FINAL RESULT
 * ============================================================== */

bzj_section(
    'FINAL RESULT'
);


bzj_print(
    "Rows deleted: "
    . number_format(
        $totalDeleted
    )
);


bzj_print(
    "Confirmed orphan rows remaining: "
    . number_format(
        $remaining
    )
);


bzj_print(
    "Unmapped candidate references: "
    . number_format(
        count(
            $report[
                'discovered'
            ][
                'references'
            ]
        )
    )
);


bzj_print(
    "Failed operations: "
    . number_format(
        count(
            $report[
                'execution'
            ][
                'failed_tables'
            ]
        )
    )
);


if ($remaining === 0) {

    bzj_print();


    bzj_print(
        "CONFIRMED ORPHAN CLEANUP COMPLETE."
    );


} else {

    bzj_print();


    bzj_print(
        "WARNING: Some confirmed orphan rows remain."
    );


    bzj_print(
        "Review the JSON report and failed-table information."
    );
}


bzj_log(
    "PURGE COMPLETE; deleted="
    . $totalDeleted
    . "; remaining="
    . $remaining
);


bzj_print();
```

## What this version changes

### 1. It fixes the biggest reporting problem

Suppose this exists:

```text
Wo_Followers

follower_id   following_id
-----------   ------------
217           218
```

and neither user exists.

The GitHub implementation can report:

```text
follower_id: 1
following_id: 1
```

and therefore appear to have two orphan references.

But there is only **one physical row to delete**.

The updated script reports:

```text
Wo_Followers: 1 orphan row
    follower_id: 1 reference
    following_id: 1 reference
```

That distinction matters enormously when we are deciding whether the purge result is correct.

---

### 2. It uses the existing Buzzjuice DB infrastructure

The script calls:

```php
get_wowonder_db();
```

rather than introducing another database configuration. That function is already provided by `shared/db_helpers.php` and reads:

```text
WOWONDER_DB_HOST
WOWONDER_DB_USER
WOWONDER_DB_PASS
WOWONDER_DB_NAME
```

from the existing environment. ([GitHub][1])

So there is **no database password or hostname in this script**.

---

### 3. It builds an indexed existing-user set

Instead of repeatedly doing:

```sql
NOT EXISTS (
    SELECT ...
    FROM Wo_Users
)
```

against every table, it creates:

```text
bzj_existing_user_ids
```

as a temporary indexed table.

Conceptually:

```text
Wo_Users
   │
   └──► bzj_existing_user_ids
             │
             ├── 1
             ├── 2
             ├── 3
             ├── 7
             ├── 8
             └── ...
```

Then every orphan test can efficiently ask whether the referenced ID exists in that indexed set.

---

### 4. It does not automatically trust schema discovery

This is important.

The script will detect something like:

```text
Wo_SomePlugin.owner_id
    14 possible orphan rows
```

but it will **not delete those rows**.

Why?

Because:

```text
owner_id
```

might refer to:

* a WoWonder user
* a page
* a group
* a product
* an administrator
* an external entity

The schema discovery report is therefore a **candidate list for us to review**, not an automatic deletion mechanism.

---

### 5. It uses the actual database schema

The original WoWonder function uses constants such as:

```php
T_NOTIFICATION
T_EVENTS_INT
T_LIVE_SUB
T_AGORA
```

Those constants resolve to physical table names inside a particular WoWonder installation.

The cleanup utility doesn't have access to those PHP constants because we intentionally don't load the entire WoWonder application.

Instead it checks the actual database and supports common table-name variations.

That makes the utility considerably safer as an independent CLI tool.

---

### 6. It does not modify `Wo_Users`

This is deliberate.

The utility's entire premise is:

> `Wo_Users` is the surviving source of truth.

Therefore:

```text
Wo_Users
    │
    ├── existing user → valid
    │
    └── absent user → possible orphan
```

The cleaner never attempts to "fix" `Wo_Users`.

---

# Particularly important: posts, pages and groups

There is a subtle difference between the original `Wo_DeleteUser()` and this cleaner.

The original function does things such as:

```php
Wo_DeletePage()
Wo_DeleteGroup()
Wo_DeletePost()
Wo_DeleteForumThread()
```

Those functions may perform **secondary cleanup**.

For example:

```text
Deleted user
   │
   └── Post
        │
        ├── Comments
        ├── Reports
        ├── Reactions
        └── Media
```

Simply doing:

```sql
DELETE FROM Wo_Posts
WHERE user_id = 217;
```

does not necessarily reproduce everything `Wo_DeletePost()` would have done.

The supplied `Wo_DeleteUser()` also explicitly deletes media and S3 objects in several places.

Therefore this utility intentionally stays within the safer boundary:

> **database orphan-reference cleanup only.**

It does **not** pretend to be a complete replacement for WoWonder's application-level deletion routines.

---

# Why I would not delete media in this first utility

Your original concern is that users were directly deleted from the database.

There are potentially now two classes of remnants:

```text
Deleted user
│
├── Database remnants
│   ├── followers
│   ├── messages
│   ├── posts
│   ├── comments
│   ├── notifications
│   └── ...
│
└── File remnants
    ├── avatar
    ├── cover
    ├── post media
    ├── message media
    ├── certification PDF
    └── S3 objects
```

The database portion can be safely audited against `Wo_Users`.

The filesystem/S3 portion is different because a file may potentially be shared or referenced elsewhere.

So I would **not combine those two jobs**.

# Phase 5 — Full purge

After the audit is satisfactory and a full backup of the WoWonder database exists:

```bash
php bzj-orphan-user-cleaner.php --execute --yes
```

The cleaner processes each table separately.

For example:

```text
Wo_Followers
    BEGIN
    DELETE
    COMMIT

Wo_Messages
    BEGIN
    DELETE
    COMMIT

Wo_Posts
    BEGIN
    DELETE
    COMMIT
```

This is preferable to one enormous transaction covering the entire database.

If one table fails:

```text
Wo_Followers       SUCCESS
Wo_Messages        SUCCESS
Wo_Posts           FAILED
Wo_Comments        SUCCESS
```

the successful tables remain cleaned while the failed table is rolled back independently and reported.

# One thing I would **not** do yet

I would **not schedule this as a recurring automatic purge**.

First run it manually and examine the schema-discovery output.

Once we've confirmed that the discovered candidates correspond to genuine WoWonder user references, we can promote selected ones into:

```php
bzj_confirmed_reference_map()
```

Then they become eligible for automatic cleanup.

That gives us a controlled progression:

```text
Unknown
   ↓
Schema discovery
   ↓
Human verification
   ↓
Confirmed reference
   ↓
Automatic audit
   ↓
Automatic purge
```

rather than:

```text
Column name looks like user ID
        ↓
DELETE
```

which would be too dangerous.

## Bigger-picture improvement for Buzzjuice

There is also a longer-term architectural fix worth implementing after this cleanup.

Since Buzzjuice now has **BuddyBoss as the canonical account/relationship authority**, WoWonder should ideally never again be allowed to accumulate orphaned accounts silently.

I would eventually add a lightweight **WoWonder account-integrity monitor** that periodically checks:

```text
BuddyBoss/WP canonical users
          │
          ├── wo_user_id
          │
          ▼
      Wo_Users
          │
          ├── exists → OK
          │
          └── missing → quarantine/report
```

and, independently:

```text
Wo_Users
   │
   └── referenced data
          │
          ├── valid user → OK
          └── missing user → orphan report
```

That gives Buzzjuice two-way integrity checking rather than waiting until somebody manually deletes a database row and discovers the consequences later.

The current Buzzjuice database helper is already structured appropriately for this kind of shared infrastructure, while the WoWonder application code remains separate. ([GitHub][1])

**I would run the new script in dry-run mode first and not execute the purge until we have examined its actual report.**
