The evidence points to **session continuity and session-namespace problems**, not a follow-system defect.

The existing logs show repeated creation of new `hash_id` and `main_hash_id` values, often associated with different PHP session fingerprints. That means some requests are not resuming the same server-side session. The browser cannot display `$_SESSION['hash_id']`; it only displays the session cookie, such as `BUZZSTREAMSESSID` or `PHPSESSID`.

The most important findings are:

1. `streams/assets/init.php` currently starts the PHP session before configuring a dedicated Streams session.
2. QuickDate uses the generic PHP session namespace.
3. Streams and QuickDate can therefore compete for `PHPSESSID`.
4. `follow_user.php` expects `$hash_id`, but the follow JavaScript does not send one.
5. `Wo_RegisterFollow()` optimistically changes the button before the AJAX request succeeds.
6. If `Wo_CheckMainSession($hash_id)` fails, the visible button changes temporarily, but the database is not updated.
7. The previous logs show session creation/reuse patterns consistent with different requests receiving different sessions.
8. The diagnostic log was probably absent because the logger used an incorrect root path, the directory was not writable, or the relevant code was never reached.

The log results may be incomplete because the supplied GitHub log files contain truncated records. The full files can be viewed here:

- [Session debug log](https://github.com/cupidblack/Koware_Management/blob/main/BlueCrown/attachment_files/connection_sync/streams_follow_issue/streams-session-debug_log-202609221818.txt)
- [Hash debug log](https://github.com/cupidblack/Koware_Management/blob/main/BlueCrown/attachment_files/connection_sync/streams_follow_issue/streams-hash-debug_log-202609221817.txt)

Do **not** leave `Wo_CheckMainSession()` returning `true`. That removes an anti-CSRF/session-integrity check from multiple protected operations.

    function bz_session_value_diagnostic($value)
    {
        if (!is_scalar($value)) {
            $value = '';

        $value = (string) $value;

        return array(
            'present' => ($value !== ''),
            'length' => strlen($value),
            'fingerprint' => ($value !== '')

                : '',
            'format' => ($value === '')

                        : 'non_hexadecimal'

if (!function_exists('bz_session_cookie_diagnostics')) {
    function bz_session_cookie_diagnostics()
    {
        $names = array(
            'BUZZSTREAMSESSID',
            'BUZZSOCIALSESSID',
            'PHPSESSID',
            'buzz_sso',
            'buzz_access',
            'buzz_refresh',
            'user_id',
            'JWT'
        );

        $result = array();

        foreach ($names as $name) {
            $present = isset($_COOKIE[$name]);

            $result[$name] = array(
                'present' => $present,
                'length' => $present
                    ? strlen((string) $_COOKIE[$name])
                    : 0,
                'fingerprint' => $present
                    ? hash('sha256', (string) $_COOKIE[$name])
                    : ''
            );
        }

        return $result;
    }

    function bz_session_safe_request_uri()
    {
        $uri = isset($_SERVER['REQUEST_URI'])
            ? (string) $_SERVER['REQUEST_URI']
            : '';

        if ($uri === '') {
            return '';

        return preg_replace(
            '/([?&](?:hash_id|hash|sso_token|buzz_access|buzz_refresh|token|password)=)[^&]*/i',
            '$1[REDACTED]',
            $uri
        );
    }

if (!function_exists('bz_safe_session_start')) {
    function bz_safe_session_start()
    {
        if (!function_exists('session_status')) {
            bz_stream_session_log(
                'session_start_failed',
                array(
                    'reason' => 'session_status_unavailable'
                )
            );

            return false;
        }

        if (session_status() === PHP_SESSION_ACTIVE) {
            bz_stream_session_log(
                'session_already_active'
            );

            return true;
        }

        if (session_status() !== PHP_SESSION_NONE) {
            bz_stream_session_log(
                'session_start_failed',
                array(
                    'reason' => 'session_not_startable',
                    'session_status' => session_status()
                )
            );

            return false;
        }

        if (headers_sent($headers_file, $headers_line)) {
            bz_stream_session_log(
                'session_start_failed',
                array(
                    'reason' => 'headers_already_sent',
                    'headers_file' => $headers_file,
                    'headers_line' => $headers_line
                )
            );

            return false;
        }

        $before_id = function_exists('session_id')
            ? (string) session_id()
            : '';

        try {
            $started = session_start();
        } catch (Throwable $exception) {
            bz_stream_session_log(
                'session_start_exception',
                array(
                    'exception_class' => get_class($exception),
                    'exception_message' => $exception->getMessage()
                )
            );

            return false;
        }

        $active = (
            $started &&
            session_status() === PHP_SESSION_ACTIVE
        );

        bz_stream_session_log(
            $active
                ? 'session_started'
                : 'session_start_failed',
            array(
                'start_return_value' => (bool) $started,
                'before_session_id' =>
                    bz_session_value_diagnostic($before_id),
                'after_session_id' =>
                    bz_session_value_diagnostic(
                        function_exists('session_id')
                            ? session_id()
                            : ''
                    ),
                'last_error' => error_get_last()
            )
        );

        return $active;
    }
}

if (!function_exists('Wo_EnsurePhpSession')) {
    function Wo_EnsurePhpSession()
    {
        if (!function_exists('session_status')) {
            Wo_SessionDiagnosticLog(
                'php_session_unavailable'
            );

            return false;
        }

        if (session_status() === PHP_SESSION_ACTIVE) {
            return true;
        }

        if (session_status() !== PHP_SESSION_NONE) {
            Wo_SessionDiagnosticLog(
                'php_session_not_startable',

                'php_session_headers_already_sent',
                array(
                    'headers_file' => $headers_file,
                    'headers_line' => $headers_line

            return false;
        }

        try {
            $started = session_start();
        } catch (Throwable $exception) {
            Wo_SessionDiagnosticLog(
                'php_session_start_exception',
                array(
                    'exception_class' => get_class($exception),
                    'exception_message' => $exception->getMessage()

            return false;

            $started &&
            session_status() === PHP_SESSION_ACTIVE

                : 'php_session_start_failed',

                    'existing' =>
                        Wo_SessionValueDiagnostics($existing)
                )
            );
        }

        try {
            $hash = bin2hex(random_bytes(20));
        } catch (Throwable $exception) {
            Wo_SessionDiagnosticLog(
                'create_session_random_generation_failed',
                array(
                    'session_key' => 'hash_id',
                    'exception_class' => get_class($exception),
                    'exception_message' => $exception->getMessage()
                )
            );

            return '';
        }

        $_SESSION['hash_id'] = $hash;

        Wo_SessionDiagnosticLog(
            'create_session_created',
            array(
                'session_key' => 'hash_id',
                'old_value' =>
                    Wo_SessionValueDiagnostics($existing),
                'new_value' =>
                    Wo_SessionValueDiagnostics($hash),
                'session_write_pending' => true
            )
        );

        return $hash;
    }
}

    {

            $stored

            $provided_valid &&
            $stored_valid &&

                    Wo_SessionValueDiagnostics($stored),

## 4. Important limitation of function-level logging

This code can identify:

- Which request had the session.
- Which request lacked it.
- The session cookie name.
- The session ID fingerprint.
- The session save path.
- The session save handler.
- Whether a token was created or reused.
- Whether a supplied token matched.
- The request URI and PHP entry script.
- The call stack at every session-token operation.
- The final session state at shutdown.

It cannot automatically identify an arbitrary line such as:

```php
unset($_SESSION['main_hash_id']);
```

unless that line is explicitly instrumented. PHP does not provide a general hook for every write to `$_SESSION`.

However, if the token disappears, the shutdown record will show the missing key. The preceding request and subsequent request can then be correlated using:

- `session_id.fingerprint`
- `hash_id.fingerprint`
- `main_hash_id.fingerprint`
- `script_filename`
- `request_uri`
- timestamps
- trace data

# 5. QuickDate session isolation

The current QuickDate implementation is also risky because `social/core.php` defines and starts a generic PHP session:

```php
function SessionStart()
{
    ...
    bz_safe_session_start();
}
```

QuickDate should use its own cookie before starting the session. Add this configuration before QuickDate calls `SessionStart()` or `session_start()`.

A suitable replacement for the beginning of `social/core.php` is:

```php name=social/core.php
<?php

use Google\Cloud\Storage\StorageClient;

if (!function_exists('bz_social_session_configure')) {
    function bz_social_session_configure()
    {
        if (
            function_exists('session_status') &&
            session_status() !== PHP_SESSION_NONE
        ) {
            return;
        }

        @ini_set('session.name', 'BUZZSOCIALSESSID');
        @ini_set('session.cookie_path', '/social');
        @ini_set('session.cookie_domain', '.buzzjuice.net');
        @ini_set('session.cookie_secure', '1');
        @ini_set('session.cookie_httponly', '1');
        @ini_set('session.cookie_samesite', 'Lax');
        @ini_set('session.use_only_cookies', '1');
        @ini_set('session.use_strict_mode', '1');
        @ini_set('session.serialize_handler', 'php_serialize');
    }
}

if (!function_exists('SessionStart')) {
    function SessionStart()
    {
        bz_social_session_configure();

        if (session_status() === PHP_SESSION_ACTIVE) {
            return true;
        }

        if (session_status() !== PHP_SESSION_NONE) {
            return false;
        }

        return @session_start();
    }
}

SessionStart();

require_once __DIR__ . '/../shared/palmier/palmier_logger.php';
```

Do not define a generic `bz_safe_session_start()` in both applications unless the function is guarded with `function_exists()`. Otherwise, a request that loads both applications can produce a function redeclaration error.

Also note that the QuickDate cookie path should normally be `/social`, while the Streams cookie path is `/streams`. This prevents the browser from sending each application's session cookie to the other application.

# 6. Why the original log was not sufficient

The previous diagnostic logs showed events such as:

```text
create_session_created
create_main_session_created
create_session_reused
sso_bridge_session_bootstrap
```

But they did not consistently provide enough context to correlate every record. In particular, the diagnostic system needed to include:

- exact script filename
- request URI
- session cookie name
- session save path
- session save handler
- cookie presence
- session ID fingerprint
- token fingerprints
- request-local `$hash_id`
- session key list
- shutdown state
- stack trace

The replacement logger records all of these.

The presence of a new `hash_id` does not necessarily mean a token was deleted. It can also mean:

- a new session ID was received;
- the browser did not send the correct cookie;
- the cookie path was wrong;
- `session.name` changed after the session had already started;
- the session save path changed;
- the session handler could not read the old session;
- QuickDate and Streams shared `PHPSESSID`;
- the request entered through a different hostname or path;
- a session was destroyed or regenerated;
- the request reached a separate PHP-FPM pool or server with inconsistent session storage.

# 7. Browser testing procedure

After deploying the changes:

1. Delete these cookies for `buzzjuice.net`:
   - `PHPSESSID`
   - `BUZZSTREAMSESSID`
   - `BUZZSOCIALSESSID`
2. Log in again.
3. Open a Streams profile.
4. Before clicking Follow, confirm that the browser has:
   - `BUZZSTREAMSESSID` with path `/streams`
   - no reliance on `PHPSESSID` for Streams
5. Load the profile.
6. Check the log for:
   - `session_started`
   - `create_session_created` or `create_session_reused`
   - `create_main_session_created` or `create_main_session_reused`
7. Click Follow.
8. Check the AJAX request to `requests.php`.
9. Check whether the request has the Streams cookie.
10. Check the log for:
    - `check_main_session_passed`
    - or `check_main_session_failed`
11. Reload the page.
12. Compare the session fingerprint on the reload with the profile and AJAX requests.

The following should remain stable across the page request, AJAX request, and reload:

```text
session_name = BUZZSTREAMSESSID
session_id.fingerprint = the same value
main_hash_id.fingerprint = the same value
```

A different session fingerprint is expected only after a deliberate logout or session regeneration.

# 8. How to interpret the new records

### Healthy request

```text
session_name: BUZZSTREAMSESSID
session_id.fingerprint: A
hash_id.present: true
main_hash_id.present: true
check_main_session_passed: true
```

### Missing request token

```text
session_name: BUZZSTREAMSESSID
session_id.fingerprint: A
main_hash_id.present: true
request_hash_id.present: false
check_main_session_failed
```

This indicates that the browser/session was valid but `$hash_id` was not included in the request.

### Wrong session

```text
page session_id.fingerprint: A
AJAX session_id.fingerprint: B
```

This indicates a cookie, path, domain, session-name, load-balancer, or save-storage problem.

### Session data unavailable

```text
session_id.fingerprint: A
hash_id.present: false
main_hash_id.present: false
session_save_path: ...
session_save_handler: ...
```

If this occurs with the same session fingerprint as a previous request, investigate the session storage backend and whether another request destroyed or replaced the session data.

### Session-token replacement

```text
create_main_session_created
old_value.present: true
old_value.length: 20
new_value.length: 20
```

This means application code encountered an invalid existing value and replaced it. Search the trace from that record first.

# 9. Additional issue to keep in mind

Your provided `requests.php` extracts `$hash_id` only from request data:

```php
$hash_id = '';
if (!empty($_POST['hash_id'])) {
    $hash_id = $_POST['hash_id'];
} else if (!empty($_GET['hash_id'])) {
    $hash_id = $_GET['hash_id'];
} else if (!empty($_GET['hash'])) {
    $hash_id = $_GET['hash'];
} else if (!empty($_POST['hash'])) {
    $hash_id = $_POST['hash'];
}
```

The profile follow request shown in the supplied code does not visibly send `hash_id`. Therefore, even after session isolation is corrected, `Wo_CheckMainSession($hash_id)` may still log:

```text
request_hash_id.present = false
```

You requested that the theme and `follow_user.php` not be modified, so they should remain unchanged for this diagnostic deployment. However, if the new log confirms that the AJAX request has the correct `BUZZSTREAMSESSID` but `request_hash_id` is empty, then the remaining defect is not session storage; it is that the follow request does not provide the value required by the server-side check.

The first debugging deployment should establish which of these two cases is occurring:

1. **Wrong/missing Streams PHP session**, or
2. **Correct session but missing request hash**.

That distinction should be clear from `buzzjuice-session-debug.log` after the changes above.
