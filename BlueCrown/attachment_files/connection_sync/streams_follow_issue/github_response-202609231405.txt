## Conclusion

The follow operation is not the primary defect. The repository evidence indicates that the request is intermittently using a different or newly created PHP session.

`hash_id` and `main_hash_id` are server-side `$_SESSION` values. They are not expected to appear as separate browser cookies. The browser only stores the session identifier, currently:

```text
BUZZSTREAMSESSID
```

The native WoWonder values are:

```text
hash_id      = approximately 40-character SHA-1 value
main_hash_id = approximately 20-character value
```

The 64-character values shown in the debug output are SHA-256 fingerprints generated by the diagnostic code, not the actual WoWonder session values.

The strongest defect is in `streams/assets/init.php`:

```php
if (session_status() !== PHP_SESSION_ACTIVE) @session_start();
```

The session is started before selecting `BUZZSTREAMSESSID`. Consequently, Streams can inherit another session configuration, including `PHPSESSID`.

There is also a second serious problem in `streams/ww-sso-bridge.php`:

```php
if (!$wordpress_logged_in) {
    $_SESSION = [];
    session_unset();
    @session_destroy();
}
```

Because the bridge loads `assets/init.php`, this can destroy the active Streams session. That removes `hash_id`, `main_hash_id`, login state, and other session values.

The password format is unlikely to be the cause of the changing `main_hash_id`. A password is used to authenticate or register a user; `main_hash_id` is generated and stored in the PHP session. The fact that user `66` works consistently is more consistent with that account already having a stable session/mapping path than with a special password format.

The current WoWonder hash functions are also still the unmodified versions:

```php

    $hash = sha1(rand(1111, 9999));
    if (!empty($_SESSION["hash_id"])) {
        $_SESSION["hash_id"] = $_SESSION["hash_id"];
        return $_SESSION["hash_id"];
    }
    $_SESSION["hash_id"] = $hash;
    return $hash;
```

```php
function Wo_CheckMainSession($hash = "") {
    if (!isset($_SESSION["main_hash_id"]) || empty($_SESSION["main_hash_id"])) {
        return false;
    }
    if (empty($hash)) {
        return false;
    }
    if ($hash == $_SESSION["main_hash_id"]) {
        return true;
    }
    return false;
}
```

The redundant assignments:

```php
$_SESSION["hash_id"] = $_SESSION["hash_id"];
$_SESSION["main_hash_id"] = $_SESSION["main_hash_id"];
```

do not preserve a session. They only assign a value to itself after the session has already been loaded.

The login endpoint also destroys the current session during account switching:

```php
session_unset();
$_SESSION['user_id'] = '';
session_destroy();
$_SESSION = array();
unset($_SESSION);
```

This is acceptable only if a new Streams session is deliberately started afterward. It is unsafe if another application session is active or if the subsequent request uses a different cookie path/name.

# 2. Required session architecture

The applications should use separate sessions:

| Application | Cookie | Path |
|---|---|---|
| WordPress / QuickDate | `PHPSESSID` | `/` |
| WoWonder Streams | `BUZZSTREAMSESSID` | `/streams` |

Streams must select its session configuration before `session_start()`.

The browser evidence already shows both cookies:

```text
BUZZSTREAMSESSID   path /streams
PHPSESSID          path /
```

That arrangement is valid. The problem is that Streams currently starts its session before explicitly selecting the Streams cookie.

```php name=streams/assets/init.php url=https://github.com/cupidblack/buzzjuice.net/blob/main/streams/assets/init.php
    {
        if (!is_scalar($value)) {
            $value = '';

        $value = (string)$value;

        return array(
            'present' => ($value !== ''),

            : '';

            ? basename((string)$_SERVER['SCRIPT_FILENAME'])
            : '';
        $context['host'] = isset($_SERVER['HTTP_HOST'])
            ? (string)$_SERVER['HTTP_HOST']
            : '';
        $context['session_state'] = bz_session_state_snapshot();
        $context['trace'] = bz_session_trace();

        $record = array(
            'event' => (string)$event,
            'context' => $context
        );

        $json = json_encode(
            $record,
            JSON_UNESCAPED_SLASHES |
            JSON_UNESCAPED_UNICODE |
            JSON_PARTIAL_OUTPUT_ON_ERROR
        );

        if ($json === false) {
            return false;
        }

        return @file_put_contents(
            $file,
            $json.PHP_EOL,
            FILE_APPEND | LOCK_EX
        ) !== false;
    }
}
```

```php name=streams/assets/includes/functions_two.php url=https://github.com/cupidblack/buzzjuice.net/blob/main/streams/assets/includes/functions_two.php#L5581-L5671
    }

    $_SESSION['hash_id'] = $hash;

    Wo_SessionHashLog(
        $old_value === ''
            ? 'hash_created'
            : 'hash_replaced_invalid_value',
        array(
            'hash_name' => 'hash_id',
            'old_value' => Wo_SessionHashFingerprint($old_value),
            'new_value' => Wo_SessionHashFingerprint($hash)
        )
    );

    return $hash;
}

function Wo_CheckSession($hash = '')
{
    if (!Wo_EnsureSessionActive()) {
        Wo_SessionHashLog(
            'hash_check_failed',
            array(
                'hash_name' => 'hash_id',
                'reason' => 'session_not_active',
                'request_value' => Wo_SessionHashFingerprint($hash)
            )
        );

        return false;
    }

    $stored = isset($_SESSION['hash_id'])
        ? $_SESSION['hash_id']
        : '';

    $valid = (
        is_string($hash) &&
        is_string($stored) &&
        $hash !== '' &&
        $stored !== '' &&
        hash_equals($stored, $hash)
    );

    Wo_SessionHashLog(
        $valid
            ? 'hash_check_passed'
            : 'hash_check_failed',
        array(
            'hash_name' => 'hash_id',
            'request_value' => Wo_SessionHashFingerprint($hash),
            'stored_value' => Wo_SessionHashFingerprint($stored),
            'reason' => $valid
                ? 'match'
                : (
                    $stored === ''
                        ? 'stored_value_missing'
                        : (
                            $hash === ''
                                ? 'request_value_missing'
                                : 'mismatch'
                        )
                )
        )
    );

    return $valid;
}

function Wo_CreateMainSession()
{
    if (!Wo_EnsureSessionActive()) {
        Wo_SessionHashLog(
            'hash_create_failed',
            array(
                'hash_name' => 'main_hash_id'
            )
        );

        return '';
    }

    if (
        isset($_SESSION['main_hash_id']) &&
        is_string($_SESSION['main_hash_id']) &&
        preg_match('/^[a-f0-9]{20}$/i', $_SESSION['main_hash_id'])
    ) {
        Wo_SessionHashLog(
            'hash_reused',
            array(
                'hash_name' => 'main_hash_id',
                'value' => Wo_SessionHashFingerprint(
                    $_SESSION['main_hash_id']
                )
            )
        );

        return $_SESSION['main_hash_id'];
    }

    $old_value = isset($_SESSION['main_hash_id'])
        ? $_SESSION['main_hash_id']
        : '';

    try {
        $hash = substr(
            hash('sha1', random_bytes(32)),
            0,
            20
        );
    } catch (Throwable $exception) {
        $hash = substr(
            sha1(
                uniqid('', true).
                microtime(true).
                mt_rand()
            ),
            0,
            20
        );
    }

    $_SESSION['main_hash_id'] = $hash;

    Wo_SessionHashLog(
        $old_value === ''
            ? 'hash_created'
            : 'hash_replaced_invalid_value',
        array(
            'hash_name' => 'main_hash_id',
            'old_value' => Wo_SessionHashFingerprint($old_value),
            'new_value' => Wo_SessionHashFingerprint($hash)
        )
    );

    return $hash;
}

function Wo_CheckMainSession($hash = '')
{
    if (!Wo_EnsureSessionActive()) {
```

This preserves real validation. It does not make `Wo_CheckMainSession()` universally return `true`, which would remove a CSRF/session-integrity control from every protected endpoint.

# 5. Important SSO bridge correction

The Streams bridge must not destroy the currently active Streams session merely because a WordPress cookie is absent.

The current block is unsafe:

```php
if (!$wordpress_logged_in) {
    if (session_status() === PHP_SESSION_ACTIVE) {
        $_SESSION = [];
        session_unset();
        @session_destroy();
    }

    header('Location: /wp-login.php?...');
    exit;
}
```

Replace it with this:

```php name=streams/ww-sso-bridge.php url=https://github.com/cupidblack/buzzjuice.net/blob/main/streams/ww-sso-bridge.php#L196-L215
if (!$wordpress_logged_in) {
    /*
     * Do not destroy the Streams session here.
     *
     * assets/init.php has already started BUZZSTREAMSESSID. Destroying
     * it here removes hash_id, main_hash_id and the current Streams login
     * state. WordPress authentication failure should result in a redirect,
     * not destruction of an unrelated application session.
     */
    if (function_exists('Wo_SessionDiagnosticLog')) {
        Wo_SessionDiagnosticLog(
            'sso_wordpress_authority_missing',
            array(
                'streams_session_preserved' => true
            )
        );
    }

    header(
        'Location: /wp-login.php?redirect_to=' .
        urlencode('/streams/ww-sso-bridge.php?last_url=' . $last_url)
    );
    exit;
}
```

The same rule applies to the QuickDate bridge. It must not destroy a session that it does not own.

The existing QuickDate code similarly performs:

```php
$_SESSION = [];
session_unset();
@session_destroy();
```

That should be removed from the “WordPress cookie missing” branch. Explicit logout may destroy the appropriate application session, but an SSO authorization failure should not destroy it.

# 6. Prevent social code from changing the Streams session

`social/core.php` contains its own `bz_safe_session_start()` implementation and calls:

```php
SessionStart();
```

The social application uses the default `PHPSESSID` session. It must not be included from a Streams request after Streams has started `BUZZSTREAMSESSID`.

The following files must not be included from a normal Streams page or Streams AJAX request:

```text
social/bootstrap.php
social/core.php
social/qd-sso-bridge.php
```

If a cross-application request is required, it should be a separate HTTP request or use an explicit API boundary. It should not reuse the same PHP process/session namespace.

Also check `streams/session.php`. It currently calls:

```php
@session_start();
```

That file bypasses the Streams bootstrap and can start the wrong session. Replace it with:

```php name=streams/session.php url=https://github.com/cupidblack/buzzjuice.net/blob/main/streams/session.php#L1-L10
<?php

require_once __DIR__ . '/assets/init.php';

header('Content-Type: text/plain; charset=utf-8');

echo 'session_name: ' . session_name() . PHP_EOL;
echo 'session_id_fingerprint: ' .
    json_encode(
        function_exists('bz_session_fingerprint')
            ? bz_session_fingerprint(session_id())
            : array(),
        JSON_UNESCAPED_SLASHES
    ) .
    PHP_EOL;
echo 'session.save_path: ' . ini_get('session.save_path') . PHP_EOL;
echo 'session.serialize_handler: ' . ini_get('session.serialize_handler') . PHP_EOL;
echo 'session_status: ' . session_status() . PHP_EOL;
echo 'session_keys: ' .
    json_encode(
        isset($_SESSION) && is_array($_SESSION)
            ? array_keys($_SESSION)
            : array(),
        JSON_UNESCAPED_SLASHES
    ) .
    PHP_EOL;
```

Do not expose the complete `$_SESSION` array in a public diagnostic page.

# 8. Correct test sequence

Use the single log:

```text
data/logs/buzzjuice-session-debug.log
```

Clear or archive the old diagnostic log before testing.

For one test account, perform this sequence:

1. Log out of WordPress and Streams.
2. Remove only the site cookies for `buzzjuice.net`.
3. Log in through the normal WordPress/SSO path.
4. Open `/streams`.
5. Refresh `/streams` several times.
6. Open `/streams/cupidblack`.
7. Refresh that profile several times.
8. Click `Follow`.
9. Refresh the profile.
10. Repeat with user `66`.

The expected log behavior is:

```text
session_name = BUZZSTREAMSESSID
cookie path  = /streams
hash_id      = present and unchanged within the session
main_hash_id = present and unchanged within the session
```

A successful request should contain events equivalent to:

```text
streams_session_ready_before_application_includes
hash_check_passed
request_shutdown_session_state_unchanged
```

A failing request should now identify the cause explicitly:

```text
session_start_failed
hash_check_failed: stored_value_missing
hash_check_failed: request_value_missing
hash_check_failed: mismatch
sso_wordpress_authority_missing
request_shutdown_session_state_changed
```

The most important comparisons are:

| Log field | Expected |
|---|---|
| `session_state.session_name` | `BUZZSTREAMSESSID` |
| `session_state.cookie_params.path` | `/streams` |
| `session_state.cookies.BUZZSTREAMSESSID.present` | `true` |
| `session_state.cookies.PHPSESSID.present` | allowed, but not used by Streams |
| `session_state.hash_id.present` | `true` after creation |
| `session_state.main_hash_id.present` | `true` after creation |
| `session_state.session_id.sha256` | unchanged across page refreshes |
| `hash_check_passed` | present during the follow AJAX request |

If the profile refresh still produces a different `session_id.sha256`, the problem is outside the follow implementation. It means that one of the following is still occurring:

- the browser is not sending `BUZZSTREAMSESSID` to that URL;
- the cookie path/domain differs between responses;
- another file starts the session before `assets/init.php`;
- the SSO bridge destroys or replaces the session;
- the profile request is redirected through a different host;
- a proxy/CDN is caching a session-dependent response;
- the PHP session save path is unavailable or inconsistent between workers.

# 9. Security warning about `return true`

This temporary test:

```php
function Wo_CheckMainSession($hash = '')
{
    return true;
}
```

confirms that the failure is related to validation, but it should not remain in production. It allows any caller that reaches the endpoint to bypass the main session check.

The correct permanent fix is to stabilize the Streams session and retain:

```php
hash_equals($stored, $hash)
```

The supplied browser evidence and repository code support a session-lifecycle/session-selection problem, not a defective follow implementation or an account-specific WoWonder password hash.
