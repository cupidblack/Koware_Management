## Diagnosis

The follow database logic is probably not the primary defect. The failure is caused by a broken request/session relationship:

1. `streams/assets/init.php` starts the default `PHPSESSID`.
2. QuickDate also uses PHP sessions and can reuse or destroy the same session.
3. `Wo_CheckMainSession($hash_id)` expects a token from the request.
4. `Wo_RegisterFollow()` currently calls:

```javascript
$.get(Wo_Ajax_Requests_File(), {
    f: 'follow_user',
    following_id: id
}, ...)
```

It does **not explicitly send `hash_id`**.
5. `streams/xhr/follow_user.php` rejects the request unless:

```php
Wo_CheckMainSession($hash_id) === true
```

6. The JavaScript changes the button optimistically before the server confirms success. Therefore, the user sees `Requested` even when the request was rejected.
7. The next page load reads the database state and returns the button to `Follow`.

Do not leave this in production:

```php
function Wo_CheckMainSession($hash = '') {
    return true;
}
```

That disables a security control used by follow requests and many other protected actions.

The previous logs also show multiple PHP session fingerprints and multiple new `hash_id`/`main_hash_id` values. The supplied log output is partially truncated, so it may not contain every request, but the visible records are consistent with session continuity and token transport problems rather than a failure of `random_bytes()` or token generation.

# 2. Use one diagnostic log file

All diagnostic events below write to:

```text
buzzjuice.net/data/logs/buzzjuice-session-debug.log
```

Do not write raw session IDs, `hash_id`, `main_hash_id`, JWTs, passwords, or cookies into the log. Only SHA-256 fingerprints are recorded.

The logger records:

- PHP session name
- PHP session ID fingerprint
- PHP session save path
- session cookie configuration
- whether the expected cookies were received
- request method and URI
- whether `hash_id` and `main_hash_id` exist
- token lengths and fingerprints
- whether session checks passed or failed
- selected call-stack function names
- session destruction and regeneration events
- session values before and after key operations

## Important correction

The previous implementation printed values directly:

```php
print_r('Wo_CreateSession: ' . $_SESSION["hash_id"]);
```

Do not do that. It can corrupt JSON responses and expose bearer tokens in HTML/AJAX responses. The logger above records fingerprints instead.

```php name=session-functions.php
if (!function_exists('Wo_EnsurePhpSession')) {
    function Wo_EnsurePhpSession()
    {
        if (!function_exists('session_status')) {
            Wo_SessionDiagnosticLog(
                'php_session_unavailable'
            );

            return false;
        }

        if (session_status() === PHP_SESSION_ACTIVE) {
            return true;
        }

        if (session_status() !== PHP_SESSION_NONE) {
            Wo_SessionDiagnosticLog(
                'php_session_not_startable',
                array(
                    'session_status' => session_status()
                )
            );

            return false;
        }

        if (headers_sent($headers_file, $headers_line)) {
            Wo_SessionDiagnosticLog(
                'php_session_headers_already_sent',
                array(
                    'headers_file' => $headers_file,
                    'headers_line' => $headers_line
                )
            );

            return false;
        }

        try {
            $started = session_start();
        } catch (Throwable $exception) {
            Wo_SessionDiagnosticLog(
                'php_session_start_exception',
                array(
                    'exception_class' => get_class($exception),
                    'exception_message' => $exception->getMessage()
                )
            );

            return false;
        }

        $active = $started &&
            session_status() === PHP_SESSION_ACTIVE;

        Wo_SessionDiagnosticLog(
            $active
                ? 'php_session_started'
                : 'php_session_start_failed',
            array(
                'start_return_value' => $started,
                'last_error' => error_get_last()
            )
        );

        return $active;
    }
}

    function Wo_CreateSession()
    {
        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'create_session_failed',

                    'session_key' => 'hash_id',

                    'exception_message' => $exception->getMessage()

        Wo_SessionDiagnosticLog(
            'create_session_created',
            array(
                'session_key' => 'hash_id',
                'old_value' => Wo_SessionValueDiagnostics($existing),
                'new_value' => Wo_SessionValueDiagnostics($hash)
            )
        );

        return $hash;
    }

if (!function_exists('Wo_CheckSession')) {
    function Wo_CheckSession($hash = '')
    {
        $provided = is_scalar($hash)
            ? (string) $hash
            : '';

        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'check_session_failed',
                array(
                    'session_key' => 'hash_id',
                    'reason' => 'php_session_not_active',
                    'provided' => Wo_SessionValueDiagnostics($provided)
                )
            );

            return false;
        }

        $stored = isset($_SESSION['hash_id'])
            ? (string) $_SESSION['hash_id']
            : '';

        $provided_valid = (bool) preg_match(
            '/^[a-f0-9]{40}$/i',
            $provided
        );

        $stored_valid = (bool) preg_match(
            '/^[a-f0-9]{40}$/i',
            $stored
        );

        $matched = $provided_valid &&
            $stored_valid &&
            hash_equals($stored, $provided);

        Wo_SessionDiagnosticLog(
            $matched
                ? 'check_session_passed'
                : 'check_session_failed',
            array(
                'session_key' => 'hash_id',
                'provided' => Wo_SessionValueDiagnostics($provided),
                'stored' => Wo_SessionValueDiagnostics($stored),
                'provided_valid' => $provided_valid,
                'stored_valid' => $stored_valid,
                'matched' => $matched
            )
        );

        return $matched;
    }
}

                    'session_key' => 'main_hash_id',
                    'exception_class' => get_class($exception),
                    'exception_message' => $exception->getMessage()
                )
            );

            return '';
        }

        $_SESSION['main_hash_id'] = $hash;

        Wo_SessionDiagnosticLog(
            'create_main_session_created',
            array(
                'session_key' => 'main_hash_id',
                'old_value' => Wo_SessionValueDiagnostics($existing),
                'new_value' => Wo_SessionValueDiagnostics($hash)
            )
        );

        return $hash;
    }
}

if (!function_exists('Wo_CheckMainSession')) {
    function Wo_CheckMainSession($hash = '')
    {
        $provided = is_scalar($hash)
            ? trim((string) $hash)
            : '';

        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'check_main_session_failed',
                array(
                    'session_key' => 'main_hash_id',
                    'reason' => 'php_session_not_active',
                    'provided' => Wo_SessionValueDiagnostics($provided)
                )
            );

            return false;
        }

        $stored = isset($_SESSION['main_hash_id'])
            ? (string) $_SESSION['main_hash_id']
            : '';

        $provided_valid = (bool) preg_match(
            '/^[a-f0-9]{20}$/i',
            $provided
        );

        $stored_valid = (bool) preg_match(
            '/^[a-f0-9]{20}$/i',
            $stored
        );

        $matched = $provided_valid &&
            $stored_valid &&
            hash_equals($stored, $provided);

        Wo_SessionDiagnosticLog(
            $matched
                ? 'check_main_session_passed'
                : 'check_main_session_failed',
            array(
                'session_key' => 'main_hash_id',
                'provided' => Wo_SessionValueDiagnostics($provided),
                'stored' => Wo_SessionValueDiagnostics($stored),
                'provided_valid' => $provided_valid,
                'stored_valid' => $stored_valid,
                'matched' => $matched
            )
        );

        return $matched;
    }
}
```

The previous code used:

```php
sha1(rand(1111, 9999))
```

That has a very small random input space. `random_bytes()` is appropriate for these request tokens.

# 13. Validation procedure

After deployment, clear existing cookies for `buzzjuice.net`, then perform this sequence.

## A. Verify cookie isolation

In browser developer tools, confirm:

```text
/streams:
  BUZZSTREAMSESSID

/social:
  BUZZSOCIALSESSID
```

There should not be an application-wide shared `PHPSESSID` controlling both systems.

## B. Verify the log path

Check:

```bash
ls -l data/logs/buzzjuice-session-debug.log
tail -f data/logs/buzzjuice-session-debug.log
```

The first request should contain events similar to:

```text
streams_session_configuration_before_start
session_started
streams_session_started_before_application_includes
create_session_created
create_main_session_created
streams_application_bootstrap_complete
```

## C. Verify a normal profile page

The page request should show:

```text
main_session_rendered
```

The fingerprint and length in that event must match the session's `main_hash_id`.

## D. Verify the Follow request

The Follow request should contain:

```text
request_router_token_selected
follow_user_received
check_main_session_passed
follow_user_session_check_passed
follow_user_register_result
follow_user_response
```

The following fields must match by fingerprint:

```text
request_hash_id.fingerprint
provided_hash_id.fingerprint
main_hash_id.fingerprint
stored_main_hash_id.fingerprint
```

## E. If it still fails

Interpret the events as follows:

| Log result | Likely cause |
|---|---|
| `session_cookie_present: false` | Browser did not send `BUZZSTREAMSESSID`; inspect cookie path/domain/secure settings |
| New PHP session fingerprint on every request | Cookie is not being persisted or session save path is not shared |
| `provided_hash_id` empty | JavaScript did not send `hash_id` |
| Provided fingerprint differs from stored fingerprint | Stale cached HTML or a different session |
| Stored `main_hash_id` absent | Session was destroyed, replaced, or loaded from a different save path |
| Session name is `PHPSESSID` | Streams initialization happened too late |
| `check_main_session_passed` but follow still fails | Inspect `Wo_RegisterFollow()` or database result |
| Follow returns `403` | Request token/session validation still failed |
| Follow returns `400` | The request passed session validation but hit a business rule such as the follow limit |

# 14. Final expected flow

The working flow should be:

```text
/streams page request
    |
    |-- configure BUZZSTREAMSESSID
    |-- session_start()
    |-- create/reuse hash_id
    |-- create/reuse main_hash_id
    |-- render .main_session
    |
Follow AJAX request
    |
    |-- browser sends BUZZSTREAMSESSID
    |-- browser sends hash_id=main_session_value
    |-- requests.php resolves $hash_id
    |-- follow_user.php calls Wo_CheckMainSession()
    |-- stored and provided fingerprints match
    |-- Wo_RegisterFollow() executes
    |-- JSON status 200 is returned
    |-- button remains synchronized with database
```

The essential fixes are therefore:

1. Separate Streams and QuickDate PHP session cookies.
2. Configure the Streams cookie before `session_start()`.
3. Initialize both session tokens after SSO and account switching.
4. Send `hash_id` explicitly with the Follow request.
5. Keep `Wo_CheckMainSession()` strict.
6. Log all events to one file: `data/logs/buzzjuice-session-debug.log`.
7. Never log raw session IDs or bearer tokens.
8. Do not optimistically leave the Follow button changed when the AJAX request fails.
