The primary fault is **not `Wo_GetMedia()`**. The repository shows three separate problems working together:

1. `init.php` destroys the PHP session and expires its cookie when `session_start()` fails.
2. `Wo_RegisterFollow()` changes `Follow` to `Requested` before the server confirms the operation.
3. The follow AJAX request does not send `hash_id`, although `requests.php` validates `Wo_CheckMainSession($hash_id)`.

The changing `BUZZSTREAMSESSID` values indicate an additional session-cookie or SSO problem. Changing `avatar_full` to `avatar` may avoid an image-processing problem, but it cannot itself regenerate a PHP session.

The following implementation keeps `Wo_CheckMainSession()` strict, preserves the authenticated session, sends the correct hash, and makes the server authoritative for the follow button.

```php name=streams/assets/includes/functions_two.php
function Wo_CreateSession()
{
    if (
        function_exists('session_status') &&
        session_status() !== PHP_SESSION_ACTIVE
    ) {
        if (function_exists('bz_streams_log')) {
            bz_streams_log(
                'application_session_hash_requested_without_active_session'
            );
        }

        return '';
    }

    if (
        isset($_SESSION['hash_id']) &&
        is_string($_SESSION['hash_id']) &&
        preg_match(
            '/^[a-f0-9]{40}$/i',
            $_SESSION['hash_id']
        )
    ) {
        return $_SESSION['hash_id'];
    }

    try {
        $hash = bin2hex(random_bytes(20));
    } catch (Throwable $exception) {
        $hash = sha1(
            uniqid((string) mt_rand(), true)
        );

        if (function_exists('bz_streams_log')) {
            bz_streams_log(
                'application_session_hash_random_bytes_fallback',
                array(
                    'exception' => $exception->getMessage()
                )
            );
        }
    }

    $_SESSION['hash_id'] = $hash;

    return $hash;
}

function Wo_CheckSession($hash = '')
{
    if (
        function_exists('session_status') &&
        session_status() !== PHP_SESSION_ACTIVE
    ) {
        return false;
    }

    if (
        $hash === null ||
        $hash === '' ||
        !isset($_SESSION['hash_id']) ||
        !is_string($_SESSION['hash_id']) ||
        $_SESSION['hash_id'] === ''
    ) {
        return false;
    }

    $hash = (string) $hash;

    if (!preg_match('/^[a-f0-9]{40}$/i', $hash)) {
        return false;
    }

    return hash_equals(
        (string) $_SESSION['hash_id'],
        $hash
    );
}

function Wo_CreateMainSession()
{
    if (
        function_exists('session_status') &&
        session_status() !== PHP_SESSION_ACTIVE
    ) {
        if (function_exists('bz_streams_log')) {
            bz_streams_log(
                'main_session_hash_requested_without_active_session'
            );
        }

        return '';
    }

    if (
        isset($_SESSION['main_hash_id']) &&
        is_string($_SESSION['main_hash_id']) &&
        preg_match(
            '/^[a-f0-9]{20}$/i',
            $_SESSION['main_hash_id']
        )
    ) {
        return $_SESSION['main_hash_id'];
    }

    try {
        $hash = bin2hex(random_bytes(10));
    } catch (Throwable $exception) {
        $hash = substr(
            hash(
                'sha256',
                uniqid((string) mt_rand(), true)
            ),
            0,
            20
        );

        if (function_exists('bz_streams_log')) {
            bz_streams_log(
                'main_session_hash_random_bytes_fallback',
                array(
                    'exception' => $exception->getMessage()
                )
            );
        }
    }

    $_SESSION['main_hash_id'] = $hash;

    return $hash;
}

function Wo_CheckMainSession($hash = '')
{
    if (
        function_exists('session_status') &&
        session_status() !== PHP_SESSION_ACTIVE
    ) {
        return false;
    }

    if (
        $hash === null ||
        $hash === '' ||
        !isset($_SESSION['main_hash_id']) ||
        !is_string($_SESSION['main_hash_id']) ||
        $_SESSION['main_hash_id'] === ''
    ) {
        return false;
    }

    $hash = (string) $hash;

    if (!preg_match('/^[a-f0-9]{20}$/i', $hash)) {
        return false;
    }

    return hash_equals(
        (string) $_SESSION['main_hash_id'],
        $hash
    );
}
```

`Wo_CheckMainSession()` should remain strict. Do not change it to accept an empty hash.

# 3. Harden hash extraction in `requests.php`

The current extraction logic is mostly correct, but it should trim the value and never accept an array value.

Replace the current `$hash_id` extraction block with this:

```php name=streams/requests.php
$hash_id = '';

$hash_candidates = array(
    isset($_POST['hash_id']) ? $_POST['hash_id'] : '',
    isset($_GET['hash_id']) ? $_GET['hash_id'] : '',
    isset($_GET['hash']) ? $_GET['hash'] : '',
    isset($_POST['hash']) ? $_POST['hash'] : ''
);

foreach ($hash_candidates as $hash_candidate) {
    if (!is_string($hash_candidate)) {
        continue;
    }

    $hash_candidate = trim($hash_candidate);

    if ($hash_candidate !== '') {
        $hash_id = $hash_candidate;
        break;
    }
}
```

For the main-session hash, the expected value is a 20-character hexadecimal string.

```javascript name=streams/themes/sunshine/layout/extra_js/content.phtml
function Wo_RegisterFollow(id, is_confirm, show_modal) {
    var followContainer = $('[id="Follow-' + id + '"]');

    if (!followContainer.length) {
        return false;
    }

    if (typeof is_confirm === 'undefined') {
        is_confirm = 0;
    }

    if (typeof show_modal === 'undefined') {
        show_modal = false;
    }

    if (show_modal === true) {
        $('#unfriend_btn').attr(
            'onclick',
            'Wo_RegisterFollow(' + id + ')'
        );

        $('#un_friend_modal').modal('show');

        return false;
    }

    $('#un_friend_modal').modal('hide');

    var button = followContainer.find('button').first();

    if (!button.length) {
        return false;
    }

    if (button.prop('disabled') === true) {
        return false;
    }

    /*
     * Preserve the exact server-rendered button. Do not replace it
     * with "Requested" before the server answers.
     */
    var previousHtml = followContainer.html();

    button.prop('disabled', true);
    button.attr('aria-busy', 'true');

    var mainSession = $('.main_session').first().val();

    if (
        typeof mainSession !== 'string' ||
        !/^[a-f0-9]{20}$/i.test(mainSession)
    ) {
        button.prop('disabled', false);
        button.removeAttr('aria-busy');

        if (typeof bzShowFollowError === 'function') {
            bzShowFollowError(
                'Your session is not ready. Please refresh the page.'
            );
        }

        return false;
    }

    $.ajax({
        url: Wo_Ajax_Requests_File(),
        type: 'POST',
        dataType: 'json',
        cache: false,
        data: {
            f: 'follow_user',
            following_id: id,
            hash_id: mainSession,
            is_confirm: is_confirm
        }
    })
    .done(function(data) {
        var status = data && parseInt(data.status, 10);
        var followState = data && data.follow_state
            ? String(data.follow_state)
            : '';

        if (
            status === 200 &&
            (
                followState === 'following' ||
                followState === 'follow'
            )
        ) {
            /*
             * The database is authoritative. Reloading causes
             * Wo_GetFollowButton() to render the correct state.
             */
            window.location.reload();
            return;
        }

        followContainer.html(previousHtml);

        var message = data && data.message
            ? String(data.message)
            : 'Unable to process follow request.';

        if (typeof bzShowFollowError === 'function') {
            bzShowFollowError(message);
        } else if (
            typeof $('#modal-alert').modal === 'function'
        ) {
            $('#modal-alert').modal('show');

            if (typeof Wo_Delay === 'function') {
                Wo_Delay(function() {
                    $('#modal-alert').modal('hide');
                }, 3000);
            }
        }

        if (typeof console !== 'undefined') {
            console.warn(
                'Follow request rejected:',
                status,
                message
            );
        }
    })
    .fail(function(xhr) {
        followContainer.html(previousHtml);

        if (typeof bzShowFollowError === 'function') {
            bzShowFollowError(
                'The follow request failed. Please try again.'
            );
        }

        if (typeof console !== 'undefined') {
            console.warn(
                'Follow request failed:',
                xhr.status,
                xhr.responseText
            );
        }
    })
    .always(function() {
        followContainer
            .find('button')
            .prop('disabled', false)
            .removeAttr('aria-busy');
    });

    return false;
}

function bzShowFollowError(message) {
    var alertModal = $('#modal-alert');

    if (!alertModal.length) {
        return;
    }

    var alertText = alertModal.find(
        '.modal-body, .alert-message, .alert-text'
    ).first();

    if (alertText.length) {
        alertText.text(message);
    }

    if (typeof alertModal.modal === 'function') {
        alertModal.modal('show');

        if (typeof Wo_Delay === 'function') {
            Wo_Delay(function() {
                alertModal.modal('hide');
            }, 3000);
        }
    }
}
```

The important behavior changes are:

- The button is not changed before the response.
- The request explicitly sends `hash_id`.
- The request uses `POST`.
- A successful response reloads the page.
- A failed response restores the original button.
- The button cannot be clicked repeatedly while the request is active.

```php name=streams/themes/sunshine/layout/timeline/content.phtml
} elseif (
    isset($wo['user_profile']['avatar_full']) &&
    is_string($wo['user_profile']['avatar_full']) &&
    $wo['user_profile']['avatar_full'] !== ''
) {
    $profile_avatar_source = Wo_GetMedia(
        $wo['user_profile']['avatar_full']
    );
}

$profile_avatar_url = Wo_GetMedia($profile_avatar_source);

if (
    $profile_avatar_url === '' &&
    !empty($wo['userDefaultAvatar'])
) {
    $profile_avatar_url = Wo_GetMedia(
        $wo['userDefaultAvatar']
    );
}

$profile_avatar_alt = isset($wo['user_profile']['name'])
    ? $wo['user_profile']['name']
    : 'avatar';

$profile_avatar_id = isset(
    $wo['user_profile']['user_id']
)
    ? (int) $wo['user_profile']['user_id']
    : 0;
?>

<img
    id="updateImage-<?php echo $profile_avatar_id; ?>"
    class="pointer"
    src="<?php echo htmlspecialchars(
        $profile_avatar_url,
        ENT_QUOTES,
        'UTF-8'
    ); ?>"
    data-image="<?php echo htmlspecialchars(
        $profile_avatar_url,
        ENT_QUOTES,
        'UTF-8'
    ); ?>"
    alt="<?php echo htmlspecialchars(
        $profile_avatar_alt,
        ENT_QUOTES,
        'UTF-8'
    ); ?>"
>
```

The key correction is that `src` and `data-image` both contain the same normalized URL.

However, this avatar change should be treated as an independent correction. It should not be relied upon as the session fix.

# 7. Do not replace `Wo_GetMedia()` with the previous oversized implementation blindly

`Wo_GetMedia()` is called from `Wo_UserData()`, which means it is executed frequently. It must remain:

- side-effect-free;
- free of `session_start()`;
- free of `session_destroy()`;
- free of `session_regenerate_id()`;
- free of cookie operations;
- free of SSO operations;
- free of database operations;
- free of diagnostic logging.

The current repository already shows that `Wo_UserData()` calls:

```php
$fetched_data['avatar'] = Wo_GetMedia(
    $fetched_data['avatar']
) . '?cache=' . $fetched_data['last_avatar_mod'];
```

Therefore, if `Wo_GetMedia()` is modified, retain the existing storage-provider behavior and only ensure that it does not mutate session state. Do not add session recovery logic to it.

# 8. Fix the SSO bridge logging location

The supplied `ww-sso-bridge.php` currently defines:

```php
define(
    'BUZZ_SSO_BRIDGE_LOG',
    __DIR__ . '/ww_sso_bridge.log'
);
```

That violates the requirement that diagnostic logging be kept in one file.

Change that definition to:

```php name=streams/ww-sso-bridge.php
if (!defined('BUZZ_SSO_BRIDGE_LOG')) {
    define(
        'BUZZ_SSO_BRIDGE_LOG',
        __DIR__
        . '/../data/logs/buzzjuice-streams.log'
    );
}
```

Also ensure that `bz_bridge_log()` in the shared bridge helper writes to `BUZZ_SSO_BRIDGE_LOG` and does not create another log file.

Do not log:

- the raw PHP session ID;
- `hash_id`;
- `main_hash_id`;
- JWT values;
- SSO secrets;
- cookies containing authentication tokens.

Use fingerprints or boolean presence values instead.

# 12. Log entries to expect

The central log should contain entries such as:

```text
/data/logs/buzzjuice-streams.log
```

For a successful follow:

```json
{
    "event": "follow_request_received",
    "context": {
        "following_id": 123,
        "logged_user_id": 45,
        "session_active": 1,
        "main_session_present": 1,
        "main_session_valid": 1,
        "hash_received": 1
    }
}
```

Then:

```json
{
    "event": "follow_request_response",
    "context": {
        "following_id": 123,
        "logged_user_id": 45,
        "status": 200,
        "follow_state": "following"
    }
}
```

For the original failure, you would expect to see:

```json
{
    "main_session_present": 0,
    "main_session_valid": 0,
    "hash_received": 0
}
```

If `main_session_present` is `1` but `main_session_valid` is `0`, the browser is sending a stale or incorrect hash.

If both are `0` after the page has loaded, the PHP session is being replaced, not merely failing follow validation.

If the profile request receives a new `Set-Cookie: BUZZSTREAMSESSID=...`, inspect the code path or web-server configuration that emits that header. The avatar code cannot cause that behavior.
