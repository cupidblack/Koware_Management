## Diagnosis

I reviewed the current repository files, the debug log, and the GitHub analysis together. The evidence points to a **session/token lifecycle problem**, not a problem with `Wo_RegisterFollow()` itself.

The most important evidence is in your debug log:

* Browser/request hash: **64 characters**
* `$_SESSION['hash_id']`: **40 characters**
* `$_SESSION['main_hash_id']`: **20 characters**
* The request therefore reaches `Wo_CheckMainSession()` with a token that **cannot possibly equal** the stored 20-character `main_hash_id`. ([GitHub][1])

The current repository confirms the underlying inconsistency. `Wo_CreateSession()` creates/reuses a 40-character SHA-1 value, while `Wo_CreateMainSession()` creates/reuses a 20-character value. 

More importantly, the current `ww-sso-bridge.php` only creates the WoWonder login session and sets:

```php
$_SESSION['user_id']
$_SESSION['wo_user_id']
$_SESSION['wp_Wo_SSO_Login']
```

It does **not** initialize `hash_id` or `main_hash_id` during SSO login. 

So your suspicion about the SSO bridge was correct.

However, I would **not blame `sso-session-sync.php` directly**. I checked it specifically for `Wo_CreateSession()`, `main_hash_id`, `session_start()`, `session_name()` and `PHPSESSID`; it does not create or manipulate these WoWonder request-security hashes. ([GitHub][2])

Its role is indirect: it establishes the WordPress/SSO state that causes the Streams bridge to run. The actual missing initialization is in `ww-sso-bridge.php`.

This also fixes the broader class of problems rather than bypassing `Wo_CheckMainSession()`.

# Important correction to the previous fix

I agree with GitHub's warning about the earlier approach that used:

```php
session_write_close();
session_start();
```

inside `Wo_CreateSession()` / `Wo_CreateMainSession()`.

**Do not use that.**

Closing and reopening the session during the same request introduces unnecessary race/staleness risks. The new implementation should ensure the session is active once, then read/write `$_SESSION` normally. GitHub specifically identified this as a security/correctness correction. ([GitHub][3])

Also, we should **never write the raw hashes to the log**. The diagnostic logger should record:

* presence
* length
* SHA-256 fingerprint
* first four characters
* last four characters
* format validity
* equality/mismatch

That is enough to correlate values without putting a usable session credential into `data/logs`. ([GitHub][3])

```php
/**
 * -------------------------------------------------------------------------
 * Buzzjuice / WoWonder PHP session and request-security diagnostics
 * -------------------------------------------------------------------------
 *
 * IMPORTANT:
 * - Never logs raw session credentials.
 * - hash_id remains a 40-character hexadecimal token.
 * - main_hash_id remains a 20-character hexadecimal token.
 * - Existing valid values are reused.
 * - Invalid/malformed values are replaced.
 * - PHP sessions are never closed/reopened here.

if (!function_exists('Wo_SessionDiagnosticRequestId')) {
    function Wo_SessionDiagnosticRequestId()
    {
        static $request_id = null;

        if ($request_id !== null) {
            return $request_id;
        }

        if (!empty($_SERVER['HTTP_X_REQUEST_ID'])) {
            $request_id = preg_replace(
                '/[^a-zA-Z0-9._-]/',
                '',
                (string) $_SERVER['HTTP_X_REQUEST_ID']
            );
        }

        if (empty($request_id) && !empty($_SERVER['UNIQUE_ID'])) {
            $request_id = preg_replace(
                '/[^a-zA-Z0-9._-]/',
                '',
                (string) $_SERVER['UNIQUE_ID']
            );
        }

        if (empty($request_id)) {
            try {
                $request_id = bin2hex(random_bytes(8));
            } catch (Throwable $e) {
                $request_id = substr(
                    hash(
                        'sha256',
                        microtime(true) . mt_rand()
                    ),
                    0,
                    16
                );
            }
        }

        return $request_id;
    }
}


if (!function_exists('Wo_SessionValueDiagnostics')) {
    function Wo_SessionValueDiagnostics($value)
    {
        if (!is_scalar($value)) {
            $value = '';
        }

        $value = (string) $value;

        return array(
            'present' => ($value !== ''),
            'length' => strlen($value),
            'fingerprint' => (
                $value !== ''
                    ? hash('sha256', $value)
                    : ''
            ),
            'first_4_chars' => (
                $value !== ''
                    ? substr($value, 0, 4)
                    : ''
            ),
            'last_4_chars' => (
                $value !== ''
                    ? substr($value, -4)
                    : ''
            ),
            'hex_format' => (
                $value !== ''
                    ? (bool) preg_match('/^[a-f0-9]+$/i', $value)
                    : false
            )
        );
    }
}


if (!function_exists('Wo_SessionDiagnosticLog')) {
    function Wo_SessionDiagnosticLog($event, $context = array())
    {
        $log_directory = dirname(__DIR__, 3) . '/data/logs';

        if (!is_dir($log_directory)) {
            @mkdir($log_directory, 0755, true);
        }

        if (!is_array($context)) {
            $context = array(
                'value' => (string) $context
            );
        }

        $session_status = function_exists('session_status')
            ? session_status()
            : -1;

        $php_session_id = '';

        if (
            $session_status === PHP_SESSION_ACTIVE &&
            function_exists('session_id')
        ) {
            $php_session_id = (string) session_id();
        }

        $context['request_id'] =
            Wo_SessionDiagnosticRequestId();

        $context['timestamp_utc'] =
            gmdate('c');

        $context['method'] =
            $_SERVER['REQUEST_METHOD'] ?? '';

        $context['request_uri'] =
            $_SERVER['REQUEST_URI'] ?? '';

        $context['remote_addr'] =
            $_SERVER['REMOTE_ADDR'] ?? '';

        $context['session_status'] =
            $session_status;

        $context['session_name'] =
            function_exists('session_name')
                ? session_name()
                : '';

        $context['php_session_id'] =
            Wo_SessionValueDiagnostics(
                $php_session_id
            );

        $filename =
            $log_directory .
            '/session-' .
            gmdate('Y-m-d') .
            '.log';

        $line = array(
            'event' => (string) $event,
            'timestamp_utc' => gmdate('c'),
            'request_id' =>
                Wo_SessionDiagnosticRequestId(),
            'context' => $context
        );

        @file_put_contents(
            $filename,
            json_encode(
                $line,
                JSON_UNESCAPED_SLASHES |
                JSON_UNESCAPED_UNICODE
            ) . PHP_EOL,
            FILE_APPEND | LOCK_EX
        );
    }
}


if (!function_exists('Wo_EnsurePhpSession')) {
    function Wo_EnsurePhpSession()
    {
        if (
            !function_exists('session_status') ||
            !function_exists('session_start')
        ) {
            Wo_SessionDiagnosticLog(
                'php_session_unavailable',
                array(
                    'session_status_function' =>
                        function_exists('session_status'),
                    'session_start_function' =>
                        function_exists('session_start')
                )
            );

            return false;
        }

        if (session_status() === PHP_SESSION_ACTIVE) {
            return true;
        }

        if (headers_sent($headers_file, $headers_line)) {
            Wo_SessionDiagnosticLog(
                'php_session_start_blocked_headers_sent',
                array(
                    'headers_file' => $headers_file,
                    'headers_line' => $headers_line,
                    'session_status' =>
                        session_status()
                )
            );

            return false;
        }

        try {
            $started = @session_start();
        } catch (Throwable $e) {
            Wo_SessionDiagnosticLog(
                'php_session_start_exception',
                array(
                    'error_class' =>
                        get_class($e),
                    'error_message' =>
                        $e->getMessage()
                )
            );

            return false;
        }

        Wo_SessionDiagnosticLog(
            $started &&
            session_status() === PHP_SESSION_ACTIVE
                ? 'php_session_started'
                : 'php_session_start_failed',
            array(
                'start_return_value' => $started,
                'session_status_after_start' =>
                    session_status(),
                'session_name' =>
                    function_exists('session_name')
                        ? session_name()
                        : '',
                'last_php_error' =>
                    error_get_last()
            )
        );

        return (
            $started &&
            session_status() === PHP_SESSION_ACTIVE
        );
    }
}


if (!function_exists('Wo_CreateSession')) {
    function Wo_CreateSession()
    {
        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'create_session_failed',
                array(
                    'session_key' => 'hash_id',
                    'reason' =>
                        'php_session_not_active'
                )
            );

            return '';
        }

        $existing =
            isset($_SESSION['hash_id'])
                ? (string) $_SESSION['hash_id']
                : '';

        /*
         * WoWonder request hash contract:
         * 40 hexadecimal characters.
         *
         * A malformed value such as a 64-character SHA-256
         * token is deliberately NOT reused.
         */
        if (
            $existing !== '' &&
            preg_match(
                '/^[a-f0-9]{40}$/i',
                $existing
            )
        ) {
            Wo_SessionDiagnosticLog(
                'create_session_reused',
                array(
                    'session_key' => 'hash_id',
                    'value' =>
                        Wo_SessionValueDiagnostics(
                            $existing
                        )
                )
            );

            return $existing;
        }

        $old_value = $existing;

        try {
            $hash = bin2hex(
                random_bytes(20)
            );
        } catch (Throwable $e) {
            Wo_SessionDiagnosticLog(
                'create_session_random_generation_failed',
                array(
                    'session_key' => 'hash_id',
                    'error_class' =>
                        get_class($e),
                    'error_message' =>
                        $e->getMessage()
                )
            );

            return '';
        }

        $_SESSION['hash_id'] = $hash;

        Wo_SessionDiagnosticLog(
            'create_session_created',
            array(
                'session_key' => 'hash_id',
                'old_value' =>
                    Wo_SessionValueDiagnostics(
                        $old_value
                    ),
                'new_value' =>
                    Wo_SessionValueDiagnostics(
                        $hash
                    ),
                'session_write_pending' => true
            )
        );

        return $hash;
    }
}


if (!function_exists('Wo_CheckSession')) {
    function Wo_CheckSession($hash = '')
    {
        $provided_hash =
            is_scalar($hash)
                ? (string) $hash
                : '';

        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'check_session_failed',
                array(
                    'session_key' => 'hash_id',
                    'reason' =>
                        'php_session_not_active',
                    'provided' =>
                        Wo_SessionValueDiagnostics(
                            $provided_hash
                        )
                )
            );

            return false;
        }

        $stored_hash =
            isset($_SESSION['hash_id'])
                ? (string) $_SESSION['hash_id']
                : '';

        $format_valid = (
            $provided_hash !== '' &&
            preg_match(
                '/^[a-f0-9]{40}$/i',
                $provided_hash
            )
        );

        $stored_format_valid = (
            $stored_hash !== '' &&
            preg_match(
                '/^[a-f0-9]{40}$/i',
                $stored_hash
            )
        );

        $matches = (
            $format_valid &&
            $stored_format_valid &&
            hash_equals(
                $stored_hash,
                $provided_hash
            )
        );

        Wo_SessionDiagnosticLog(
            $matches
                ? 'check_session_passed'
                : 'check_session_failed',
            array(
                'session_key' => 'hash_id',

                'provided' =>
                    Wo_SessionValueDiagnostics(
                        $provided_hash
                    ),

                'stored' =>
                    Wo_SessionValueDiagnostics(
                        $stored_hash
                    ),

                'format_valid' =>
                    (bool) $format_valid,

                'stored_format_valid' =>
                    (bool) $stored_format_valid,

                'match' => $matches,

                'reason' =>
                    $matches
                        ? 'match'
                        : (
                            $provided_hash === ''
                                ? 'empty_provided_hash'
                                : (
                                    $stored_hash === ''
                                        ? 'empty_stored_hash'
                                        : (
                                            !$format_valid
                                                ? 'invalid_provided_format'
                                                : (
                                                    !$stored_format_valid
                                                        ? 'invalid_stored_format'
                                                        : 'fingerprints_differ'
                                                )
                                        )
                                )
                        )
            )
        );

        return $matches;
    }
```

### Why this version is better

1. **64-character values cannot become `main_hash_id`.**
2. Existing valid session values survive normal page loads.
3. Corrupt/mismatched values are automatically regenerated.
4. `random_bytes()` replaces the weak `rand()` construction.
5. `hash_equals()` is used for comparisons.

8. Every important transition is logged.
9. Raw session credentials never enter the logs.

This directly implements the important GitHub recommendations. ([GitHub][3])

# Step 4 — Fix the SSO bridge fast path

There is another subtle issue in the bridge.

A user can already have a valid WoWonder login and enter the bridge again. The current fast path can redirect without guaranteeing that the two request-security hashes exist.

GitHub correctly identified this as another potential source of the intermittent behaviour. ([GitHub][3])

In the fast-path section of `ww-sso-bridge.php`, use:

```php
/*
 * -------------------------------------------------------------------------
 * FAST PATH
 * -------------------------------------------------------------------------
 *
 * The WoWonder login may already exist, but the request-security session
 * must also be valid before redirecting away from the bridge.
 */

if (
    !empty($wo['loggedin']) &&
    !empty($wo['user']['user_id']) &&
    !empty($_SESSION['wo_user_id']) &&
    (string) $_SESSION['wo_user_id'] ===
        (string) $wo['user']['user_id']
) {

    $fast_path_ready = false;

    $fast_request_hash = '';
    $fast_main_hash    = '';

    if (
        function_exists('Wo_EnsurePhpSession') &&
        Wo_EnsurePhpSession() &&
        function_exists('Wo_CreateSession') &&
        function_exists('Wo_CreateMainSession')
    ) {

        $fast_request_hash =
            Wo_CreateSession();

        $fast_main_hash =
            Wo_CreateMainSession();

        $fast_path_ready = (
            $fast_request_hash !== '' &&
            $fast_main_hash !== ''
        );
    }

    bz_bridge_log(
        'WoWonder SSO fast-path session verification',
        array(
            'wo_user_id' =>
                (int) $wo['user']['user_id'],

            'request_hash' =>
                function_exists(
                    'Wo_SessionValueDiagnostics'
                )
                    ? Wo_SessionValueDiagnostics(
                        $fast_request_hash
                    )
                    : array(
                        'present' =>
                            ($fast_request_hash !== ''),
                        'length' =>
                            strlen($fast_request_hash)
                    ),

            'main_hash' =>
                function_exists(
                    'Wo_SessionValueDiagnostics'
                )
                    ? Wo_SessionValueDiagnostics(
                        $fast_main_hash
                    )
                    : array(
                        'present' =>
                            ($fast_main_hash !== ''),
                        'length' =>
                            strlen($fast_main_hash)
                    ),

            'session_status' =>
                function_exists('session_status')
                    ? session_status()
                    : -1,

            'session_cookie_present' =>
                function_exists('session_name')
                    ? !empty(
                        $_COOKIE[session_name()]
                    )
                    : false,

            'ready' =>
                $fast_path_ready
        )
    );

    if (!$fast_path_ready) {

        http_response_code(500);

        echo 'Unable to initialize the Streams request session.';

        exit;
    }

    header(
        'Location: ' . $last_url
    );

    exit;
}
```

This prevents an already-authenticated user from bypassing request-security initialization.

# Step 5 — Make the rendered `.main_session` canonical

This is the other half of the problem.

Creating `$_SESSION['main_hash_id']` isn't enough.

The browser must receive **that exact value**.

The GitHub recommendation is therefore correct: the active Streams template should explicitly render the result of:

```php
Wo_CreateMainSession()
```

and not some unrelated hash.

In the active Sunshine container template, add the following where the other hidden session/security fields are rendered:

```php
<?php

$rendered_main_hash_id =
    Wo_CreateMainSession();

if (
    function_exists('Wo_SessionDiagnosticLog') &&
    function_exists('Wo_SessionValueDiagnostics')
) {

    Wo_SessionDiagnosticLog(
        'main_session_rendered_into_html',
        array(
            'page' =>
                $wo['page'] ?? '',

            'user_id' =>
                $wo['user']['user_id'] ?? 0,

            'rendered_main_hash' =>
                Wo_SessionValueDiagnostics(
                    $rendered_main_hash_id
                ),

            'stored_main_hash' =>
                Wo_SessionValueDiagnostics(
                    $_SESSION['main_hash_id'] ?? ''
                ),

            'same_value' =>
                (
                    (string) $rendered_main_hash_id ===
                    (string) (
                        $_SESSION['main_hash_id'] ?? ''
                    )
                )
        )
    );
}

?>

<input
    type="hidden"
    class="main_session"
    value="<?php echo htmlspecialchars(
        $rendered_main_hash_id,
        ENT_QUOTES,
        'UTF-8'
    ); ?>"
>
```

The GitHub investigation specifically recommends this canonical rendering and says the diagnostic result should be:

```text
rendered_main_hash.length = 20
stored_main_hash.length = 20
same_value = true
```

([GitHub][3])

### Why this matters

It creates a guaranteed chain:

```text
$_SESSION['main_hash_id']
          │
          │ Wo_CreateMainSession()
          ▼
.main_session
          │
          │ JavaScript
          ▼
requests.php?hash_id=...
          │
          ▼
Wo_CheckMainSession()
```

No second token generator is involved.

Your current JavaScript optimistically changes the button before the AJAX request completes:

```javascript
        if (data.status == 200) {
```

```php
if (!empty($_POST['hash_id'])) {
```

```text
hash_id = $_SESSION['main_hash_id']
```

```text
64-character mystery hash
```

I would avoid globally changing `requests.php` until we have observed the new logs.

# What I would NOT do

I would specifically avoid these shortcuts:

### ❌ Remove this

```php
Wo_CheckMainSession($hash_id)
```

That merely disables a security control.

### ❌ Make `Wo_CheckMainSession()` accept 64-character tokens

That would hide the underlying token-generation problem.

### ❌ Make `Wo_CheckMainSession()` accept either `hash_id` or `main_hash_id`

The two values have different purposes.

### ❌ Copy the WordPress SSO JWT into `$_SESSION['main_hash_id']`

The Buzzjuice SSO JWT and WoWonder's request-security token are different authentication layers.

### ❌ Regenerate the token on every request

That would cause exactly the kind of intermittent mismatch we are trying to eliminate.

### ❌ Close/reopen PHP sessions inside the token functions

As GitHub correctly pointed out, that creates unnecessary session race/staleness risks. ([GitHub][3])

## Bottom line

The GitHub diagnosis is substantially correct, but I would implement it as a **session lifecycle repair**, not merely a Follow fix.

The key changes are:

1. **Repair the four session functions in `functions_two.php`.**
2. **Initialize both hashes during `Wo_SSO_Login()`.**
3. **Repair the bridge fast path.**
4. **Render the canonical `main_hash_id` into `.main_session`.**
5. **Explicitly send `.main_session` from `Wo_RegisterFollow()`.**
6. **Keep `Wo_CheckMainSession()` enforced.**
7. **Make `follow_user.php` extensively diagnostic.**
8. **Return the actual final follow/requested state to JavaScript.**
9. **Do not modify `sso-session-sync.php` unless the new evidence shows it is involved.**
10. **Do not modify `requests.php` yet.**

The current repository and debug evidence support this approach: the existing WoWonder functions expect a 40-character `hash_id` and a 20-character `main_hash_id`, while your failing request was presenting a 64-character value to `Wo_CheckMainSession()`. 

**One important implementation note:** because `functions_two.php` and `ww-sso-bridge.php` are very large production files, I have given you the complete replacement blocks and exact insertion/replacement sections rather than reproducing hundreds of KB of unrelated WoWonder code. That is safer operationally and avoids accidentally overwriting unrelated Buzzjuice customizations.

After these changes, the **first thing to send me is the new `session-2026-09-22.log` and `follow-2026-09-22.log` from one clean login + one Follow attempt**. Those two logs should let us determine conclusively whether the remaining issue, if any, is PHP session persistence, HTML token rendering, AJAX token propagation, or the actual WoWonder relationship logic.
