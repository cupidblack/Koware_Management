The follow-state bug is caused by multiple independent problems:

1. `Wo_RegisterFollow()` still honors `confirm_followers`, so it can insert `active = 0`.
2. `follow_user.php` returns only a generic status and does not verify the final database state.
3. `content.phtml` changes the button optimistically before the server confirms the result.
4. The browser can display `Requested` or revert to `Follow` even when the database contains a different state.
5. The endpoint does not consistently initialize an error response when an insert/delete fails.
6. Cached `Wo_UserData()` results can preserve an old follow state after the database has changed.
7. The SSO registration code can produce incomplete or inconsistently mapped `Wo_Users` records, although SSO is not the direct cause of `active = 0`.

I cannot execute a database comparison against Buzzjuice from here, and I have not modified or pushed anything. The following is a proposed refactor to apply manually.

## 1. Add centralized follow logging

Add this helper once in `streams/assets/includes/functions_one.php`, preferably near the other general-purpose helpers.

````php name=streams/assets/includes/functions_one.php
<?php
if (!function_exists('Buzzjuice_FollowLog')) {
    /**
     * Follow diagnostics.
     *
     * Logs to:
     *   buzzjuice.net/data.logs/follow/
     *
     * Do not log passwords, SSO tokens, cookies, or email addresses.
     */
    function Buzzjuice_FollowLog($event, array $context = array())
    {
        $base_dir = dirname(__DIR__, 3) . '/data.logs/follow';

        if (!is_dir($base_dir)) {
            @mkdir($base_dir, 0750, true);
        }

        $context['timestamp_utc'] = gmdate('c');
        $context['request_id'] = $context['request_id']
            ?? ($_SERVER['HTTP_X_REQUEST_ID'] ?? bin2hex(random_bytes(8)));

        $line = json_encode(
            array(
                'event'   => (string) $event,
                'context' => $context,
            ),
            JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE
        );

        if ($line !== false) {
            @file_put_contents(
                $base_dir . '/follow-' . gmdate('Y-m-d') . '.log',
                $line . PHP_EOL,
                FILE_APPEND | LOCK_EX
            );
        }
    }
}
````

The requested base folder is `buzzjuice.net/data.logs`; the implementation uses the more specific subdirectory `buzzjuice.net/data.logs/follow/`.

## 2. Make follow registration always create an active relationship

The current logic shown elsewhere in the repository explicitly does this:

```php
if ($following_data['confirm_followers'] == "1") {
    $active = 0;
}
```

That is incompatible with the requested behavior. The following implementation always writes `active = 1`.

Replace the existing `Wo_RegisterFollow()` implementation used by Streams with the following logic. Preserve any existing notification or synchronization code from the current implementation after the database operation.

````php name=streams/assets/includes/functions_one.php
<?php
function Wo_RegisterFollow($following_id = 0, $followers_id = 0)
{
    global $wo, $sqlConnect, $db;

    $following_id = (int) $following_id;

    if ($following_id < 1) {
        Buzzjuice_FollowLog('register_rejected', array(
            'reason' => 'invalid_following_id',
            'following_id' => $following_id,
        ));
        return false;
    }

    if (!is_array($followers_id)) {
        $followers_id = array($followers_id);
    }

    foreach ($followers_id as $raw_follower_id) {
        $follower_id = (int) $raw_follower_id;

        if ($follower_id < 1 || $follower_id === $following_id) {
            Buzzjuice_FollowLog('register_rejected', array(
                'reason' => 'invalid_follower_id',
                'following_id' => $following_id,
                'follower_id' => $follower_id,
            ));
            continue;
        }

        // Resolve the actual table name through WoWonder constants.
        $followers_table = defined('T_FOLLOWERS') ? T_FOLLOWERS : 'Wo_Followers';
        $users_table     = defined('T_USERS') ? T_USERS : 'Wo_Users';

        $following_id_sql = (int) $following_id;
        $follower_id_sql  = (int) $follower_id;

        // Validate both accounts before touching the relationship.
        $user_query = mysqli_query(
            $sqlConnect,
            "SELECT user_id, active
             FROM {$users_table}
             WHERE user_id IN ({$following_id_sql}, {$follower_id_sql})"
        );

        $valid_users = array();

        if ($user_query) {
            while ($row = mysqli_fetch_assoc($user_query)) {
                $valid_users[(int) $row['user_id']] = $row;
            }
        }

        if (
            empty($valid_users[$following_id]) ||
            empty($valid_users[$follower_id]) ||
            (int) $valid_users[$following_id]['active'] !== 1 ||
            (int) $valid_users[$follower_id]['active'] !== 1
        ) {
            Buzzjuice_FollowLog('register_rejected', array(
                'reason' => 'user_missing_or_inactive',
                'following_id' => $following_id,
                'follower_id' => $follower_id,
                'users_found' => array_keys($valid_users),
            ));
            continue;
        }

        // Do not allow a blocked relationship.
        if (function_exists('Wo_IsBlocked') && Wo_IsBlocked($following_id)) {
            Buzzjuice_FollowLog('register_rejected', array(
                'reason' => 'blocked',
                'following_id' => $following_id,
                'follower_id' => $follower_id,
            ));
            continue;
        }

        /*
         * Important:
         * Existing pending rows are upgraded to active instead of creating
         * a second row. This removes the Requested state permanently.
         */
        $existing_query = mysqli_query(
            $sqlConnect,
            "SELECT id, active
             FROM {$followers_table}
             WHERE following_id = {$following_id_sql}
               AND follower_id = {$follower_id_sql}
             ORDER BY id DESC
             LIMIT 1"
        );

        if ($existing_query && ($existing = mysqli_fetch_assoc($existing_query))) {
            $relationship_id = (int) $existing['id'];

            $updated = mysqli_query(
                $sqlConnect,
                "UPDATE {$followers_table}
                 SET active = 1
                 WHERE id = {$relationship_id}"
            );

            Buzzjuice_FollowLog(
                $updated ? 'register_upgraded_to_active' : 'register_upgrade_failed',
                array(
                    'following_id' => $following_id,
                    'follower_id' => $follower_id,
                    'relationship_id' => $relationship_id,
                    'previous_active' => (int) $existing['active'],
                    'mysql_error' => $updated ? null : mysqli_error($sqlConnect),
                )
            );

            if (!$updated) {
                continue;
            }
        } else {
            $created_at = time();

            $inserted = mysqli_query(
                $sqlConnect,
                "INSERT INTO {$followers_table}
                    (following_id, follower_id, active, created_at)
                 VALUES
                    ({$following_id_sql}, {$follower_id_sql}, 1, {$created_at})"
            );

            Buzzjuice_FollowLog(
                $inserted ? 'register_inserted_active' : 'register_insert_failed',
                array(
                    'following_id' => $following_id,
                    'follower_id' => $follower_id,
                    'mysql_error' => $inserted ? null : mysqli_error($sqlConnect),
                )
            );

            if (!$inserted) {
                continue;
            }
        }

        // Invalidate any cached user data after the relationship changes.
        if (function_exists('cache')) {
            @cache($following_id, 'users', 'delete');
            @cache($follower_id, 'users', 'delete');
        }

        /*
         * Keep the existing notification / connection-sync code here.
         * It must run only after the active relationship has been confirmed.
         */
    }

    return true;
}
````

### Important

Do not leave the old `confirm_followers` block in the active implementation. If the old implementation is still loaded later from another file, it can override this function or continue inserting pending rows.

Search for every definition before applying the change:

```bash

```

There must be one authoritative implementation for the web request path.

The endpoint should determine the current state from the database, perform the requested operation, invalidate caches, then return the verified state.

````php name=streams/xhr/follow_user.php

$followers_table = defined('T_FOLLOWERS') ? T_FOLLOWERS : 'Wo_Followers';

$following_id_sql = (int) $following_id;
$follower_id_sql  = (int) $follower_id;

$relationship_query = mysqli_query(
    $sqlConnect,

     WHERE following_id = {$following_id_sql}
       AND follower_id = {$follower_id_sql}
     ORDER BY id DESC
     LIMIT 1"

    ? mysqli_fetch_assoc($relationship_query)

    $current_relationship &&
    (int) $current_relationship['active'] === 1

if (!$success) {

    Buzzjuice_FollowLog('endpoint_operation_failed', array(

        'follower_id' => $follower_id,
        'mysql_error' => mysqli_error($sqlConnect),

if (function_exists('cache')) {
    @cache($following_id, 'users', 'delete');
    @cache($follower_id, 'users', 'delete');
}

if (function_exists('Wo_CleanCache')) {
    Wo_CleanCache();
}

// Read the final state after the write. Never infer it from the click.
$verify_query = mysqli_query(
    $sqlConnect,
    "SELECT id, active
     FROM {$followers_table}
     WHERE following_id = {$following_id_sql}
       AND follower_id = {$follower_id_sql}
     ORDER BY id DESC
     LIMIT 1"

$verified_relationship = $verify_query
    ? mysqli_fetch_assoc($verify_query)
    : null;

$active = (
    $verified_relationship &&
    (int) $verified_relationship['active'] === 1
);

$data = array(
    'status' => 200,
    'state' => $active ? 'following' : 'follow',
    'following_id' => $following_id,
    'follower_id' => $follower_id,
    'active' => $active ? 1 : 0,
    'requested' => 0,
    'relationship_id' => $verified_relationship
        ? (int) $verified_relationship['id']
        : 0,
);

Buzzjuice_FollowLog('endpoint_operation_complete', array(
    'operation' => $operation,
    'following_id' => $following_id,
    'follower_id' => $follower_id,
    'state' => $data['state'],
    'active' => $data['active'],
    'relationship_id' => $data['relationship_id'],
````

## 4. Replace the follow portion of `content.phtml`

The current JavaScript changes the HTML before knowing whether the request succeeded. It also determines the next state from CSS classes, which is unreliable after an SSO redirect, cached response, or failed request.

Replace the current `Wo_RegisterFollow()` function with this server-authoritative version:

````html+php name=streams/themes/sunshine/layout/extra_js/content.phtml
<script>
(function () {
    'use strict';

    window.BuzzjuiceFollowState = window.BuzzjuiceFollowState || {};

    function followLog(eventName, details) {
        if (window.console && console.debug) {
            console.debug('[BuzzjuiceFollow]', eventName, details || {});
        }
    }

    function escapeHtml(value) {
        return $('<div>').text(value == null ? '' : String(value)).html();
    }

    function renderFollowButton(id, state) {
        var container = $('[id="Follow-' + id + '"]');

        if (!container.length) {
            followLog('container_missing', {id: id});
            return;
        }

        var followingText = <?php echo json_encode($wo['lang']['following_btn'] ?? 'Following'); ?>;
        var followText    = <?php echo json_encode($wo['lang']['follow'] ?? 'Follow'); ?>;

        var isFollowing = state === 'following';
        var label = isFollowing ? followingText : followText;

        var buttonClass = isFollowing
            ? 'btn-active btn btn-default btn-sm wo_following_btn'
            : 'btn btn-default btn-sm wo_follow_btn';

        var html =
            '<button type="button" ' +
                'class="' + buttonClass + '" ' +
                'id="wo_useract_btn" ' +
                'data-follow-state="' + state + '" ' +
                'aria-pressed="' + (isFollowing ? 'true' : 'false') + '" ' +
                'onclick="Wo_RegisterFollow(' + parseInt(id, 10) + ')">' +
                '<span class="button-text">' + escapeHtml(label) + '</span>' +
            '</button>';

        container.html(html);
    }

    window.Wo_RegisterFollow = function (id) {
        id = parseInt(id, 10);

        if (!id || id < 1) {
            followLog('invalid_id', {id: id});
            return false;
        }

        if (window.BuzzjuiceFollowState[id] === 'pending') {
            followLog('duplicate_click_ignored', {id: id});
            return false;
        }

        var container = $('[id="Follow-' + id + '"]');
        var button = container.find('button').first();

        if (!container.length || !button.length) {
            followLog('button_missing', {id: id});
            return false;
        }

        var previousState =
            button.attr('data-follow-state') ||
            (button.hasClass('btn-active') ? 'following' : 'follow');

        window.BuzzjuiceFollowState[id] = 'pending';

        button.prop('disabled', true);
        button.attr('aria-busy', 'true');

        followLog('request_start', {
            id: id,
            previousState: previousState
        });

        $.ajax({
            url: Wo_Ajax_Requests_File(),
            type: 'GET',
            dataType: 'json',
            cache: false,
            data: {
                f: 'follow_user',
                following_id: id,
                _: Date.now()
            }
        })
        .done(function (data) {
            followLog('request_complete', {
                id: id,
                response: data
            });

            if (!data || parseInt(data.status, 10) !== 200) {
                throw new Error(
                    data && data.error
                        ? data.error
                        : 'The follow operation failed'
                );
            }

            var finalState = data.state === 'following'
                ? 'following'
                : 'follow';

            window.BuzzjuiceFollowState[id] = finalState;
            renderFollowButton(id, finalState);

            if (
                finalState === 'following' &&
                typeof node_socket_flow !== 'undefined' &&
                String(node_socket_flow) === '1' &&
                typeof socket !== 'undefined'
            ) {
                socket.emit('user_notification', {
                    to_id: id,
                    user_id: _getCookie('user_id'),
                    type: 'added'
                });
            }

            if (
                finalState === 'follow' &&
                typeof node_socket_flow !== 'undefined' &&
                String(node_socket_flow) === '1' &&
                typeof socket !== 'undefined'
            ) {
                socket.emit('user_notification', {
                    to_id: id,
                    user_id: _getCookie('user_id'),
                    type: 'removed'
                });
            }

            if (data.can_send == 1 && typeof Wo_SendMessages === 'function') {
                Wo_SendMessages();
            }
        })
        .fail(function (xhr, status, error) {
            followLog('request_failed', {
                id: id,
                httpStatus: xhr.status,
                status: status,
                error: error,
                response: xhr.responseText
            });

            window.BuzzjuiceFollowState[id] = previousState;
            renderFollowButton(id, previousState);

            if (typeof $('#modal-alert').modal === 'function') {
                $('#modal-alert').modal('show');

                if (typeof Wo_Delay === 'function') {
                    Wo_Delay(function () {
                        $('#modal-alert').modal('hide');
                    }, 3000);
                }
            }
        });

        return false;
    };
}());
</script>
````

### Why this fixes the UI

The browser no longer decides whether the result is `Follow`, `Requested`, or `Following`.

The sequence is now:

1. User taps the button.
2. The button is disabled.
3. The server writes or deletes the relationship.
4. The server reads the relationship again.
5. The server returns `state`.
6. The browser renders that verified state.

`Requested` is deliberately never rendered because the required behavior is immediate following.

## 6. Update `follow_users.php`

The startup follow endpoint should use the same active-follow implementation and verify every ID.

````php name=streams/xhr/follow_users.php
<?php

if ($f !== 'follow_users') {
    exit();
}

header('Content-Type: application/json; charset=utf-8');

$data = array(
    'status' => 400,
    'followed' => array(),
    'failed' => array(),
);

if (empty($wo['loggedin']) || $wo['loggedin'] !== true) {
    $data['error'] = 'Unauthorized request';
    echo json_encode($data);
    exit();
}

$raw_users = $_POST['user'] ?? '';
$ids = array_filter(array_map('intval', explode(',', (string) $raw_users)));

$current_user_id = (int) (
    $wo['user']['user_id']
    ?? $wo['user']['id']
    ?? 0
);

foreach ($ids as $id) {
    if ($id < 1 || $id === $current_user_id) {
        $data['failed'][] = $id;
        continue;
    }

    if (Wo_RegisterFollow($id, $current_user_id)) {
        $data['followed'][] = $id;
    } else {
        $data['failed'][] = $id;
    }
}

if ($current_user_id > 0) {
    Wo_UpdateUserData($current_user_id, array(
        'startup_follow' => '1',
        'start_up' => '1',
    ));

    Wo_UpdateUserDetails($current_user_id, false, false, true);
}

if (function_exists('Wo_CleanCache')) {
    Wo_CleanCache();
}

$data['status'] = empty($data['failed']) ? 200 : 207;

Buzzjuice_FollowLog('bulk_follow_complete', array(
    'follower_id' => $current_user_id,
    'followed' => $data['followed'],
    'failed' => $data['failed'],
));

echo json_encode($data);
exit();
````

### Find users with missing or suspicious values

```sql
SELECT
    user_id,
    username,
    email,
    wp_user_id,
    active,
    start_up,
    startup_follow,
    confirm_followers,
    follow_privacy
FROM Wo_Users
WHERE user_id <> 66
  AND (
       active IS NULL
    OR active NOT IN (0, 1)
    OR start_up IS NULL
    OR startup_follow IS NULL
    OR confirm_followers IS NULL
    OR follow_privacy IS NULL
    OR username IS NULL
    OR username = ''
    OR email IS NULL
    OR email = ''
  )
ORDER BY user_id;
```

### Find duplicate relationships

```sql
SELECT
    following_id,
    follower_id,
    COUNT(*) AS relationship_count,
    GROUP_CONCAT(CONCAT(id, ':', active) ORDER BY id) AS rows_found
FROM Wo_Followers
GROUP BY following_id, follower_id
HAVING COUNT(*) > 1
ORDER BY relationship_count DESC;
```

### Find pending relationships that should be converted

```sql
SELECT
    id,
    following_id,
    follower_id,
```

## 9. SSO and auto-registration corrections

The SSO bridge is not directly responsible for the `Requested` state, but it can create accounts with inconsistent identity fields.

The current auto-registration call is:

```php
$registration = Wo_RegisterUser([
    'username' => $final_username,
    'email'    => $wp_email,
    'password' => bin2hex(random_bytes(16)),
    'active'   => 1
]);
```

Before calling `Wo_RegisterUser()`, validate the required fields that the actual WoWonder registration function expects. At minimum, the registration result should be checked by querying the database afterward, not only by checking the return value.

Add a diagnostic helper to `streams/ww-sso-bridge.php`:

````php name=streams/ww-sso-bridge.php
<?php
if (!function_exists('bz_log_wo_account_diagnostics')) {
    function bz_log_wo_account_diagnostics($wo_user_id, $wp_user_id = 0)
    {
        global $sqlConnect;

        $wo_user_id = (int) $wo_user_id;
        $wp_user_id = (int) $wp_user_id;

        if ($wo_user_id < 1 || empty($sqlConnect)) {
            return;
        }

        $users_table = defined('T_USERS') ? T_USERS : 'Wo_Users';

        $query = mysqli_query(
            $sqlConnect,
            "SELECT
                user_id,
                username,
                email,
                wp_user_id,
                active,
                start_up,
                startup_follow,
                confirm_followers,
                follow_privacy,
                type,
                admin,
                verified,
                is_pro
             FROM {$users_table}
             WHERE user_id = {$wo_user_id}
             LIMIT 1"
        );

        $row = $query ? mysqli_fetch_assoc($query) : null;

        if (function_exists('bz_bridge_log')) {
            bz_bridge_log('WoWonder account diagnostics', array(
                'wo_user_id' => $wo_user_id,
                'wp_user_id' => $wp_user_id,
                'account' => $row,
                'mysql_error' => $query ? null : mysqli_error($sqlConnect),
            ));
        }
    }
}
````

Call it after resolving or creating the account:

```php
bz_log_wo_account_diagnostics($wo_user_id, $wp_user_id);
```

Also fix this existing condition in `ww-sso-bridge.php`:

```php
if (!empty($exp_wp && $exp_login && $exp_email)) {
```

It should be:

```php
if (
    !empty($exp_wp) &&
    !empty($exp_login) &&
    !empty($exp_email)
) {
```

The current expression evaluates the combined boolean expression first and then passes that result to `empty()`, which is not the intended validation.
