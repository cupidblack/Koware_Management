The primary failure is **not** that `Wo_RegisterFollow()` creates a “Requested” state. The request is being rejected before the follow operation completes because:

1. `ww-sso-bridge.php` creates the normal login session with `Wo_CreateLoginSession()`, but does not explicitly initialize `hash_id` or `main_hash_id`.
2. `container.phtml` later creates `main_hash_id` only when the page is rendered.
3. The follow buttons call `Wo_RegisterFollow(id)` without sending `.main_session`.
4. `requests.php` therefore receives an empty `$hash_id`.
5. `follow_user.php` executes:

```php
Wo_CheckMainSession($hash_id) === true
```

with an empty value and rejects the request.

The existing endpoint also has an error-control problem: when the session check fails, `$data` may never be initialized, so the response can become `null`, which makes the frontend appear to have changed state even though the database operation failed.

 * Buzzjuice session diagnostics.

 * Security note:
 * Raw session hashes are never written to the log. The diagnostic log

if (!function_exists('Wo_SessionDiagnosticLog')) {
    function Wo_SessionDiagnosticLog($event, $context = array())
    {
        $base_dir = dirname(__DIR__, 3) . '/data/logs';

        if (!is_dir($base_dir)) {
            @mkdir($base_dir, 0755, true);
        }

        $log_file = $base_dir . '/session-' . gmdate('Y-m-d') . '.log';

        $safe_context = is_array($context) ? $context : array(
            'value' => (string) $context
        );

        $safe_context['timestamp_utc'] = gmdate('c');
        $safe_context['request_id'] = $_SERVER['HTTP_X_REQUEST_ID']
            ?? ($_SERVER['UNIQUE_ID'] ?? bin2hex(random_bytes(8)));

        if (session_status() === PHP_SESSION_ACTIVE) {
            $safe_context['php_session_status'] = 'active';
            $safe_context['php_session_id_fingerprint'] = hash(
                'sha256',
                session_id()
            );
            $safe_context['php_session_id_length'] = strlen(session_id());
        } else {
            $safe_context['php_session_status'] = session_status();
            $safe_context['php_session_id_fingerprint'] = '';
            $safe_context['php_session_id_length'] = 0;
        }

        $line = json_encode(
            array(
                'event'   => (string) $event,
                'context' => $safe_context
            ),
            JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE
        );

        if ($line !== false) {
            @file_put_contents(
                $log_file,
                $line . PHP_EOL,
                FILE_APPEND | LOCK_EX
            );
        }
    }
}

if (!function_exists('Wo_SessionValueDiagnostics')) {
    function Wo_SessionValueDiagnostics($value)
    {
        $value = is_scalar($value) ? (string) $value : '';

        return array(
            'present'       => ($value !== ''),
            'length'        => strlen($value),
            'fingerprint'   => ($value !== '' ? hash('sha256', $value) : ''),
            'first_4_chars' => ($value !== '' ? substr($value, 0, 4) : ''),
            'last_4_chars'  => ($value !== '' ? substr($value, -4) : '')

if (!function_exists('Wo_EnsurePhpSession')) {
    function Wo_EnsurePhpSession()
    {
        if (session_status() === PHP_SESSION_ACTIVE) {
            return true;
        }

        $started = @session_start();

        Wo_SessionDiagnosticLog(
            $started ? 'php_session_started' : 'php_session_start_failed',
            array(
                'session_status_after_start' => session_status(),
                'session_name'               => session_name(),
                'session_cookie_params'      => session_get_cookie_params(),
                'last_php_error'             => error_get_last()
            )
        );

        return $started && session_status() === PHP_SESSION_ACTIVE;
    }
}

if (!function_exists('Wo_CreateSession')) {
    function Wo_CreateSession()
    {
        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'create_session_failed',
                array(
                    'reason' => 'php_session_not_active'
                )
            );

            return '';
        }

        $existing = isset($_SESSION['hash_id'])
            ? (string) $_SESSION['hash_id']
            : '';

        if ($existing !== '') {
            Wo_SessionDiagnosticLog(
                'create_session_reused',
                array(
                    'session_key' => 'hash_id',
                    'value'       => Wo_SessionValueDiagnostics($existing)
                )
            );

            return $existing;
        }

        try {
            $hash = bin2hex(random_bytes(32));
        } catch (Throwable $e) {
            Wo_SessionDiagnosticLog(
                'create_session_random_bytes_failed',
                array(
                    'error' => $e->getMessage()
                )
            );

            return '';
        }

        $_SESSION['hash_id'] = $hash;

        Wo_SessionDiagnosticLog(
            'create_session_created',
            array(
                'session_key' => 'hash_id',
                'value'       => Wo_SessionValueDiagnostics($hash),
                'session_write_result' => @session_write_close()
            )
        );

        /*
         * Re-open the session because the current request may continue using
         * $_SESSION after this function returns.
         */
        @session_start();

        return $hash;
    }
}

if (!function_exists('Wo_CheckSession')) {
    function Wo_CheckSession($hash = '')
    {
        $provided_hash = is_scalar($hash) ? (string) $hash : '';

        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'check_session_failed',
                array(
                    'reason'   => 'php_session_not_active',
                    'provided' => Wo_SessionValueDiagnostics($provided_hash)
                )
            );

            return false;
        }

        $stored_hash = isset($_SESSION['hash_id'])
            ? (string) $_SESSION['hash_id']
            : '';

        $valid = (
            $provided_hash !== '' &&
            $stored_hash !== '' &&
            hash_equals($stored_hash, $provided_hash)
        );

        Wo_SessionDiagnosticLog(
            $valid ? 'check_session_passed' : 'check_session_failed',
            array(
                'session_key' => 'hash_id',
                'provided'    => Wo_SessionValueDiagnostics($provided_hash),
                'stored'      => Wo_SessionValueDiagnostics($stored_hash),
                'match'       => $valid
            )
        );

        return $valid;
    }
}

## Important caution about `session_write_close()`

The code above writes the session and then reopens it. This is useful for diagnostic testing, but it is not ideal as a permanent pattern because repeated close/reopen operations during one request can cause confusing behavior.

A simpler production version should not close and reopen the session inside each function. If you want the least invasive production implementation, remove these blocks from both creation functions:

```php
'session_write_result' => @session_write_close()
```

and remove:

```php
@session_start();
```

The important requirements are:

- `session_start()` must have succeeded.
- The session must be initialized before values are written.
- The same PHP session cookie must be sent on the subsequent AJAX request.
- The browser must send the same `main_hash_id` that was stored in `$_SESSION`.

For initial debugging, leave the explicit logging enabled.

```php name=streams/xhr/follow_user.php url=https://github.com/cupidblack/buzzjuice.net/blob/5a35fd9f80c6a97a4d5f2f91e96dfc722277f49d/streams/xhr/follow_user.php#L1-L39
            'reason' => 'invalid_following_id'
        );

        if (function_exists('Wo_SessionDiagnosticLog')) {
            Wo_SessionDiagnosticLog(
                'endpoint_rejected',
                array(
                    'request_id' => $request_id,
                    'reason' => 'invalid_following_id',
                    'following_id_raw' => $_GET['following_id'] ?? null
                )
            );
        }

        echo json_encode($data);
        exit();
    }

    $provided_hash = '';

    if (!empty($_POST['hash_id'])) {
        $provided_hash = (string) $_POST['hash_id'];
    } elseif (!empty($_GET['hash_id'])) {
        $provided_hash = (string) $_GET['hash_id'];
    } elseif (!empty($_GET['hash'])) {
        $provided_hash = (string) $_GET['hash'];
    } elseif (!empty($_POST['hash'])) {
        $provided_hash = (string) $_POST['hash'];
    }

    /*
     * Keep $hash_id synchronized with the value selected by requests.php.
     * This allows both the endpoint and diagnostic logging to refer to the
     * exact same incoming value.
     */
    $hash_id = $provided_hash;

    if (function_exists('Wo_SessionDiagnosticLog')) {
        Wo_SessionDiagnosticLog(
            'follow_main_session_validation_start',
            array(
                'request_id' => $request_id,
                'following_id' => (int) $following_id,
                'provided_hash' => Wo_SessionValueDiagnostics($provided_hash),
                'stored_hash' => Wo_SessionValueDiagnostics(
                    $_SESSION['main_hash_id'] ?? ''
                )
            )
        );
    }

    if (!function_exists('Wo_CheckMainSession')) {
        throw new RuntimeException(
            'Wo_CheckMainSession() is not available.'
        );
    }

    $main_session_valid = Wo_CheckMainSession($provided_hash);

    if ($main_session_valid !== true) {
        http_response_code(403);

        $data = array(
            'status' => 403,
            'can_send' => 0,
            'message' => 'Invalid or expired request session. Reload the page and try again.',
            'reason' => 'invalid_main_session',
            'request_id' => $request_id
        );

        if (function_exists('Wo_SessionDiagnosticLog')) {
            Wo_SessionDiagnosticLog(
                'endpoint_rejected',
                array(
                    'request_id' => $request_id,
                    'reason' => 'invalid_main_session',
                    'following_id' => (int) $following_id,
                    'provided_hash' => Wo_SessionValueDiagnostics($provided_hash),
                    'stored_hash' => Wo_SessionValueDiagnostics(
                        $_SESSION['main_hash_id'] ?? ''
                    ),
                    'session_cookie_present' => !empty($_COOKIE[session_name()]),
                    'user_id' => $wo['user']['user_id'] ?? null
                )
            );
        }

        echo json_encode($data);
        exit();
    }

    $current_user_id = 0;

    if (!empty($wo['user']['user_id'])) {
        $current_user_id = (int) $wo['user']['user_id'];
    } elseif (!empty($wo['user']['id'])) {
        $current_user_id = (int) $wo['user']['id'];
    }

    if ($current_user_id < 1) {
        throw new RuntimeException(
            'Authenticated user ID is missing.'
        );
    }

    if ($current_user_id === (int) $following_id) {
        http_response_code(400);

        $data = array(
            'status' => 400,
            'can_send' => 0,
            'message' => 'You cannot follow yourself.',
            'reason' => 'self_follow'
        );

        if (function_exists('Wo_SessionDiagnosticLog')) {
            Wo_SessionDiagnosticLog(
                'endpoint_rejected',
                array(
                    'request_id' => $request_id,
                    'reason' => 'self_follow',
                    'user_id' => $current_user_id,
                    'following_id' => (int) $following_id
                )
            );
        }

        echo json_encode($data);
        exit();
    }

    $user_followers = Wo_CountFollowing($current_user_id, true);
    $friends_limit = (int) ($wo['config']['connectivitySystemLimit'] ?? 0);

    $already_following = Wo_IsFollowing(
        $following_id,
        $current_user_id
    ) === true;

    $follow_requested = Wo_IsFollowRequested(
        $following_id,
        $current_user_id
    ) === true;

    if (function_exists('Wo_SessionDiagnosticLog')) {
        Wo_SessionDiagnosticLog(
            'follow_state_loaded',
            array(
                'request_id' => $request_id,
                'user_id' => $current_user_id,
                'following_id' => (int) $following_id,
                'user_followers' => (int) $user_followers,
                'friends_limit' => $friends_limit,
                'already_following' => $already_following,
                'follow_requested' => $follow_requested,
                'connectivity_system' => $wo['config']['connectivitySystem'] ?? null
            )
        );
    }

    if ($already_following || $follow_requested) {
        $deleted = Wo_DeleteFollow(
            $following_id,
            $current_user_id
        );

        if (!$deleted) {
            throw new RuntimeException(
                'The existing follow relationship could not be removed.'
            );
        }

        $data = array(
            'status' => 200,
            'can_send' => 0,
            'html' => '',
            'action' => 'removed',
            'following_id' => (int) $following_id,
            'request_id' => $request_id
        );

        if (function_exists('Wo_SessionDiagnosticLog')) {
            Wo_SessionDiagnosticLog(
                'follow_removed',
                array(
                    'request_id' => $request_id,
                    'user_id' => $current_user_id,
                    'following_id' => (int) $following_id
                )
            );
        }
    } elseif (
        ($wo['config']['connectivitySystem'] ?? 0) == 1 &&
        $friends_limit > 0 &&
        $user_followers >= $friends_limit
    ) {
        http_response_code(400);

        $data = array(
            'status' => 400,
            'can_send' => 0,
            'message' => 'You have reached the follow limit.',
            'reason' => 'follow_limit_reached',
            'request_id' => $request_id
        );

        if (function_exists('Wo_SessionDiagnosticLog')) {
            Wo_SessionDiagnosticLog(
                'endpoint_rejected',
                array(
                    'request_id' => $request_id,
                    'reason' => 'follow_limit_reached',
                    'user_id' => $current_user_id,
                    'following_id' => (int) $following_id,
                    'user_followers' => (int) $user_followers,
                    'friends_limit' => $friends_limit
                )
            );
        }
    } else {
        $registered = Wo_RegisterFollow(
            $following_id,
            $current_user_id
        );

        if (!$registered) {
            throw new RuntimeException(
                'Wo_RegisterFollow() did not create the follow relationship.'
            );
        }

        $data = array(
            'status' => 200,
            'can_send' => 0,
            'html' => '',
            'action' => 'added',
            'following_id' => (int) $following_id,
            'request_id' => $request_id
        );

        if (function_exists('Wo_CanSenEmails') && Wo_CanSenEmails()) {
            $data['can_send'] = 1;
        }

        if (function_exists('Wo_SessionDiagnosticLog')) {
            Wo_SessionDiagnosticLog(
                'follow_added',
                array(
                    'request_id' => $request_id,
                    'user_id' => $current_user_id,
                    'following_id' => (int) $following_id,
                    'can_send' => $data['can_send']
                )
            );
        }
    }

    if (function_exists('Wo_CleanCache')) {
        Wo_CleanCache();
    }

    echo json_encode($data);
    exit();
} catch (Throwable $e) {
    http_response_code(500);

    $data = array(
        'status' => 500,
        'can_send' => 0,
        'message' => 'A server error occurred while processing the follow request.',
        'reason' => 'server_exception',
        'request_id' => $request_id
    );

    if (function_exists('Wo_SessionDiagnosticLog')) {
        Wo_SessionDiagnosticLog(
            'follow_endpoint_exception',
            array(
                'request_id' => $request_id,
                'error_class' => get_class($e),
                'error_message' => $e->getMessage(),
                'error_file' => $e->getFile(),
                'error_line' => $e->getLine(),
                'user_id' => $wo['user']['user_id'] ?? null,
                'following_id' => $_GET['following_id'] ?? null,
                'provided_hash' => Wo_SessionValueDiagnostics($hash_id ?? ''),
                'stored_hash' => Wo_SessionValueDiagnostics(
                    $_SESSION['main_hash_id'] ?? ''
                )
            )
        );
    }

    echo json_encode($data);
    exit();
}
```

# Step 9: Validate that `Wo_RegisterFollow()` actually changes the database

The button state is only a client-side representation. Confirm the database state after clicking follow.

Immediately before clicking follow, run:

```sql
SELECT
    following_id,
    follower_id,
    active,
    time
FROM Wo_Followers
WHERE
    (following_id = 63 AND follower_id = 1)
    OR
    (following_id = 1 AND follower_id = 63);
```

After clicking follow, run the same query.

The expected outcomes depend on your WoWonder configuration:

- `connectivitySystem = 0`: normally an active follow should be inserted.
- `connectivitySystem = 1`: the relationship may initially be stored as a pending request.
- If you modified `Wo_RegisterFollow()` to auto-accept, the database must show the active relationship after that function returns.

The key distinction is:

- `action: added` from `follow_user.php` means the endpoint completed.
- A database row with the wrong `active` state means the problem is inside `Wo_RegisterFollow()`.
- No row means the request failed before or during follow registration.
- A row exists but the page displays “Follow” after reload means the profile-state lookup/cache is stale or uses a different user ID.

# Step 11: Interpret the likely results

## Case 1: `main_session` is empty in the browser

The container is not being used, or `Wo_CreateMainSession()` is failing because the PHP session is not active.

Check:

- `session_start()` is called in `assets/init.php`.
- PHP can write to its configured session directory.
- The browser receives the PHP session cookie.
- `session.cookie_domain`, `session.cookie_path`, `secure`, and `SameSite` settings are correct.

## Case 2: Browser hash exists, but stored session hash is empty

The AJAX request is reaching a different PHP session.

This usually means:

- The SSO bridge and Streams use different session cookie names.
- The cookie domain/path differs.
- The session cookie is marked secure but the request is HTTP.
- The bridge redirects between hosts and the cookie is not available on the final host.
- PHP session storage is not shared between servers.
- A load balancer sends subsequent requests to a server with a different session store.

## Case 3: Browser and server hashes differ

The page rendered an old hash, or a new PHP session was created between the page request and AJAX request.

Look for:

- `session_regenerate_id(true)` after rendering.
- SSO bridge redirects that overwrite the cookie.
- Multiple PHP session cookies with the same name but different paths.
- Multiple `main_hash_id` fields generated on the same page.
- An AJAX request going to a different hostname.

## Case 4: Session validation passes but the button still says “Requested”

Then the hash problem is fixed. The remaining issue is in follow-state behavior:

- `Wo_RegisterFollow()` may be creating a pending row.
- The automatic acceptance code may execute only for some users.
- `connectivitySystem` may differ by configuration.
- The response UI is optimistic and does not reflect the final server state.
- The follow relationship cache is stale.

At that point, inspect `Wo_RegisterFollow()`, `Wo_IsFollowing()`, `Wo_IsFollowRequested()`, and the profile follow-button rendering logic.

# Most likely final fix

The minimal functional fix is:

1. Call `Wo_CreateSession()` and `Wo_CreateMainSession()` during successful SSO login.
2. Ensure `container.phtml` renders the existing `main_hash_id`.
3. Send `.main_session` as `hash_id` from `Wo_RegisterFollow()`.
4. Keep `Wo_CheckMainSession()` enabled in `follow_user.php`.
5. Return explicit JSON errors instead of allowing an undefined `$data`.
6. Use the logging above to verify the PHP session cookie and hash fingerprints match.

The current `follow_user.php` check is doing the right security job. Removing it only hides the session propagation problem and leaves other protected endpoints vulnerable.
