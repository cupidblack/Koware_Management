## Diagnosis

The follow operation is failing **before the database follow logic completes**.

The evidence is consistent:

- `streams/requests.php` reads `hash_id` from the request and passes it to the endpoint.
- `streams/xhr/follow_user.php` requires `Wo_CheckMainSession($hash_id) === true`.
- The follow JavaScript currently does not explicitly send `.main_session`.
- `ww-sso-bridge.php` calls `Wo_CreateLoginSession()`, but does not initialize `hash_id` or `main_hash_id`.
- The diagnostic log shows inconsistent token formats:
  - browser/request hash: **64 characters**
  - `hash_id`: **40 characters**
  - `main_hash_id`: **20 characters**
- The browser is therefore sending a value generated by a different mechanism than the value stored in `$_SESSION['main_hash_id']`.

The SSO plugin is probably not directly generating the 64-character request hash. Its likely effect is indirect: it establishes or refreshes the WordPress/SSO state, then `ww-sso-bridge.php` creates or reuses a WoWonder session without initializing the two request-security values.

The search results used for tracing may be incomplete. Additional occurrences can be reviewed here:

https://github.com/cupidblack/buzzjuice.net/search?q=Wo_CheckMainSession&type=code

# Step 2: Important security correction

Do **not** use the previous implementation that does this inside `Wo_CreateSession()` or `Wo_CreateMainSession()`:

```php
session_write_close();
session_start();
```

Closing and reopening the PHP session in the middle of a request can create race conditions and can cause later code in the same request to observe stale or missing session data.

Also do not log the raw session hash. A hash is still a credential. The diagnostic code below logs:

- whether the value exists;
- its length;
- its SHA-256 fingerprint;
- its first and last four characters;
- whether the incoming and stored values match.

The raw value is never logged.

if (!function_exists('Wo_SessionDiagnosticRequestId')) {
    function Wo_SessionDiagnosticRequestId()
    {
        static $request_id = null;

        if ($request_id !== null) {
            return $request_id;
        }

        if (!empty($_SERVER['HTTP_X_REQUEST_ID'])) {
            $request_id = preg_replace(
                '/[^a-zA-Z0-9._-]/',
                '',
                (string) $_SERVER['HTTP_X_REQUEST_ID']
            );
        }

        if (empty($request_id) && !empty($_SERVER['UNIQUE_ID'])) {
            $request_id = preg_replace(
                '/[^a-zA-Z0-9._-]/',
                '',
                (string) $_SERVER['UNIQUE_ID']
            );
        }

        if (empty($request_id)) {
            try {
                $request_id = bin2hex(random_bytes(8));
            } catch (Throwable $e) {
                $request_id = substr(
                    hash('sha256', microtime(true) . mt_rand()),
                    0,
                    16
                );
            }
        }

        return $request_id;
    }
}

if (!function_exists('Wo_SessionValueDiagnostics')) {
    function Wo_SessionValueDiagnostics($value)
    {
        if (!is_scalar($value)) {
            $value = '';
        }

        $value = (string) $value;

        return array(
            'present'        => ($value !== ''),
            'length'         => strlen($value),
            'fingerprint'    => ($value !== '')
                ? hash('sha256', $value)
                : '',
            'first_4_chars'  => ($value !== '')
                ? substr($value, 0, 4)
                : '',
            'last_4_chars'   => ($value !== '')
                ? substr($value, -4)
                : '',
            'hex_format'     => ($value !== '')
                ? (bool) preg_match('/^[a-f0-9]+$/i', $value)
                : false
        );
    }
}

if (!function_exists('Wo_SessionDiagnosticLog')) {
    function Wo_SessionDiagnosticLog($event, $context = array())
    {
        $log_directory = dirname(__DIR__, 3) . '/data/logs';

        if (!is_dir($log_directory)) {
            @mkdir($log_directory, 0755, true);
        }

        if (!is_array($context)) {
            $context = array(
                'value' => (string) $context
            );
        }

        $session_status = function_exists('session_status')
            ? session_status()
            : -1;

        $php_session_id = '';

        if (
            $session_status === PHP_SESSION_ACTIVE &&
            function_exists('session_id')
        ) {
            $php_session_id = (string) session_id();
        }

        $context['request_id'] = Wo_SessionDiagnosticRequestId();
        $context['timestamp_utc'] = gmdate('c');
        $context['method'] = $_SERVER['REQUEST_METHOD'] ?? '';
        $context['request_uri'] = $_SERVER['REQUEST_URI'] ?? '';
        $context['remote_addr'] = $_SERVER['REMOTE_ADDR'] ?? '';
        $context['session_status'] = $session_status;
        $context['session_name'] = function_exists('session_name')
            ? session_name()
            : '';
        $context['php_session_id'] = Wo_SessionValueDiagnostics(
            $php_session_id
        );
        $context['session_cookie_present'] = (
            function_exists('session_name') &&
            !empty($_COOKIE[session_name()])
        );

        $line = json_encode(
            array(
                'event' => (string) $event,
                'context' => $context
            ),
            JSON_UNESCAPED_SLASHES |
            JSON_UNESCAPED_UNICODE |
            JSON_PARTIAL_OUTPUT_ON_ERROR
        );

        if ($line === false) {
            $line = json_encode(
                array(
                    'event' => 'session_diagnostic_json_encode_failed',
                    'context' => array(
                        'original_event' => (string) $event,
                        'request_id' => Wo_SessionDiagnosticRequestId(),
                        'timestamp_utc' => gmdate('c')
                    )
                )
            );
        }

        if ($line !== false) {
            @file_put_contents(
                $log_directory . '/session-' . gmdate('Y-m-d') . '.log',
                $line . PHP_EOL,
                FILE_APPEND | LOCK_EX
            );
        }
    }
}

if (!function_exists('Wo_EnsurePhpSession')) {
    function Wo_EnsurePhpSession()
    {
        if (!function_exists('session_status')) {
            Wo_SessionDiagnosticLog(
                'php_session_unavailable',
                array(
                    'reason' => 'session_status_function_missing'
                )
            );

            return false;
        }

        if (session_status() === PHP_SESSION_ACTIVE) {
            return true;
        }

        if (session_status() !== PHP_SESSION_NONE) {
            Wo_SessionDiagnosticLog(
                'php_session_not_startable',
                array(
                    'session_status' => session_status()
                )
            );

            return false;
        }

        if (headers_sent($headers_file, $headers_line)) {
            Wo_SessionDiagnosticLog(
                'php_session_start_blocked_headers_sent',
                array(
                    'headers_file' => $headers_file,
                    'headers_line' => $headers_line
                )
            );

            return false;
        }

        $started = @session_start();

        Wo_SessionDiagnosticLog(
            $started && session_status() === PHP_SESSION_ACTIVE
                ? 'php_session_started'
                : 'php_session_start_failed',
            array(
                'start_return_value' => $started,
                'session_status_after_start' => session_status(),
                'session_name' => session_name(),
                'last_php_error' => error_get_last()
            )
        );

        return (
            $started &&
            session_status() === PHP_SESSION_ACTIVE
        );
    }
}

if (!function_exists('Wo_CreateSession')) {
    function Wo_CreateSession()
    {
        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'create_session_failed',
                array(
                    'session_key' => 'hash_id',
                    'reason' => 'php_session_not_active'
                )
            );

            return '';
        }

        $existing = isset($_SESSION['hash_id'])
            ? (string) $_SESSION['hash_id']
            : '';

        /*
         * WoWonder's normal request hash is a 40-character SHA-1-shaped
         * hexadecimal value. Reuse valid existing values so existing forms
         * continue to work. Regenerate values from incompatible modifications,
         * such as a 64-character SHA-256 value.
         */
        if (
            $existing !== '' &&
            preg_match('/^[a-f0-9]{40}$/i', $existing)
        ) {
            Wo_SessionDiagnosticLog(
                'create_session_reused',
                array(
                    'session_key' => 'hash_id',
                    'value' => Wo_SessionValueDiagnostics($existing)
                )
            );

            return $existing;
        }

        $old_value = $existing;

        try {
            $hash = bin2hex(random_bytes(20));
        } catch (Throwable $e) {
            Wo_SessionDiagnosticLog(
                'create_session_random_generation_failed',
                array(
                    'error_class' => get_class($e),
                    'error_message' => $e->getMessage()
                )
            );

            return '';
        }

        $_SESSION['hash_id'] = $hash;

        Wo_SessionDiagnosticLog(
            'create_session_created',
            array(
                'session_key' => 'hash_id',
                'old_value' => Wo_SessionValueDiagnostics($old_value),
                'new_value' => Wo_SessionValueDiagnostics($hash),
                'session_write_pending' => true
            )
        );

        return $hash;
    }
}

if (!function_exists('Wo_CheckSession')) {
    function Wo_CheckSession($hash = '')
    {
        $provided_hash = is_scalar($hash)
            ? (string) $hash
            : '';

        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'check_session_failed',
                array(
                    'session_key' => 'hash_id',
                    'reason' => 'php_session_not_active',
                    'provided' => Wo_SessionValueDiagnostics($provided_hash)
                )
            );

            return false;
        }

        $stored_hash = isset($_SESSION['hash_id'])
            ? (string) $_SESSION['hash_id']
            : '';

        $format_valid = (
            $provided_hash !== '' &&
            preg_match('/^[a-f0-9]{40}$/i', $provided_hash)
        );

        $stored_format_valid = (
            $stored_hash !== '' &&
            preg_match('/^[a-f0-9]{40}$/i', $stored_hash)
        );

        $matches = (
            $format_valid &&
            $stored_format_valid &&
            hash_equals($stored_hash, $provided_hash)
        );

        Wo_SessionDiagnosticLog(
            $matches
                ? 'check_session_passed'
                : 'check_session_failed',
            array(
                'session_key' => 'hash_id',
                'provided' => Wo_SessionValueDiagnostics($provided_hash),
                'stored' => Wo_SessionValueDiagnostics($stored_hash),
                'format_valid' => (bool) $format_valid,
                'stored_format_valid' => (bool) $stored_format_valid,
                'match' => $matches,
                'reason' => $matches
                    ? 'match'
                    : (
                        $provided_hash === ''
                            ? 'empty_provided_hash'
                            : (
                                $stored_hash === ''
                                    ? 'empty_stored_hash'
                                    : (
                                        !$format_valid
                                            ? 'invalid_provided_format'
                                            : (
                                                !$stored_format_valid
                                                    ? 'invalid_stored_format'
                                                    : 'fingerprints_differ'
                                            )
                                    )
                            )
                    )
            )
        );

        return $matches;
    }
}

## Why these functions are deliberately strict

The current repository implementation uses:

```php
$hash = sha1(rand(1111, 9999));
```

and:

```php
$hash = substr(sha1(rand(1111, 9999)), 0, 20);
```

That is weak randomness and can also preserve values introduced by a previous incompatible patch.

The replacement:

- preserves valid existing values;
- regenerates malformed values;
- prevents a 64-character SHA-256 value from being accepted as a 20-character main session;
- uses `random_bytes()`;
- uses `hash_equals()` for comparison;
- creates `/data/logs/session-YYYY-MM-DD.log`.

# Step 10: Search for the code generating the 64-character token

Run these searches on the server:

```bash
grep -RIn --exclude-dir=cache --exclude-dir=upload \
  -E "hash\(['\"]sha256|hash_hmac\(['\"]sha256|main_hash_id|hash_id" \
  streams shared wp-content 2>/dev/null

Also search specifically for URL parameters:

```bash
grep -RIn --exclude-dir=cache --exclude-dir=upload \
  -E "[?&](hash|hash_id)=|hash[[:space:]]*:" \
  streams shared wp-content 2>/dev/null
```

The 64-character value in the log is almost certainly coming from one of these situations:

1. a previous diagnostic patch generated `hash('sha256', ...)`;
2. a JavaScript request appended a JWT or SHA-256 value as `hash`;
3. a stale page still contains an old `.main_session` value;
4. a PHP session cookie changed between the page request and AJAX request;
5. the SSO bridge regenerated the PHP session while the browser kept the old token.

Do not change `Wo_CheckMainSession()` to accept 64-character values. That would make the endpoint accept a token produced by an unrelated mechanism.

# Step 13: How to interpret the next log

## Case A: Request hash is empty

Example:

```text
hash_id.present = false
stored_main_hash_id.present = true
```

Cause: the browser did not send the token.

Check:

- whether `.main_session` exists in the HTML;
- whether `Wo_RegisterFollow()` includes `hash_id`;
- whether the active theme is Sunshine or another theme;
- whether AJAX code is being replaced by a cached JavaScript bundle.

## Case B: Request hash is 64 characters

Example:

```text
provided.length = 64
stored.length = 20
reason = invalid_provided_format
```

Cause: another component is generating or appending the 64-character value.

Search for SHA-256 generation and `hash=` URL construction. Do not loosen validation.

## Case C: Both values are 20 characters but fingerprints differ

Example:

```text
provided.length = 20
stored.length = 20
reason = fingerprints_differ
```

Cause: the page and AJAX request are using different PHP sessions or the page contains a stale token.

Check:

- PHP session cookie domain;
- cookie path;
- Secure and SameSite attributes;
- reverse proxy behavior;
- whether `www.buzzjuice.net` and `buzzjuice.net` are mixed;
- whether SSO redirects regenerate the session;
- whether the page was cached.

## Case D: Fingerprints match but the endpoint still rejects

Then the session check is no longer the problem. Investigate:

- `$wo['loggedin']`;
- `$wo['user']['user_id']`;
- `$wo['user']['id']`;
- whether the authenticated user ID is `1`;
- whether the target user ID is `63`;
- whether the user is banned;
- the result of `Wo_RegisterFollow()`.

## Case E: Follow succeeds, but reload returns to Follow

Then inspect the follow database row and the state functions:

```sql
SELECT
    following_id,
    follower_id,
    active,
    created_at
FROM Wo_Followers
WHERE
    (
        following_id = 63
        AND follower_id = 1
    )
    OR
    (
        following_id = 1
        AND follower_id = 63
    );
```

Use the actual table resolved by `T_FOLLOWERS`.

Interpretation:

- `active = 1`: immediate follow should display as Following.
- `active = 0`: WoWonder registered a pending request.
- no row: `Wo_RegisterFollow()` did not persist the relationship.

If the account should always follow immediately, then the relevant `Wo_RegisterFollow()` implementation must force:

```php
$active = 1;
```

However, that should only be changed after confirming that the endpoint request is succeeding and the database row is being created.

# Important issue with the current SSO bridge

The current bridge contains this sequence after the JWT is resolved:

```php
$_SESSION['wp_user_id'] = ...
$_SESSION['wo_user_id'] = ...
$_SESSION['wp_Wo_SSO_Login'] = true;
```

It does not create the WoWonder request hashes there.

The current login path later calls:

```php
$session_token = Wo_CreateLoginSession($accepted_user_id);
```

but originally did not call:

```php
Wo_CreateSession();
Wo_CreateMainSession();
```

That is the main architectural defect.

The WordPress MU plugin is primarily issuing and refreshing SSO cookies. It does not replace the WoWonder PHP request-session system. Therefore, the proper division is:

- `sso-session-sync.php`: WordPress identity and SSO token management;
- `ww-sso-bridge.php`: map the SSO identity to a WoWonder user and establish the WoWonder PHP session;
- `Wo_CreateSession()` / `Wo_CreateMainSession()`: create request-security values inside that same PHP session;
- `container.phtml`: render the stored `main_hash_id`;
- JavaScript: send that exact rendered value;
- `follow_user.php`: validate it and process the follow.

Do not make the WordPress MU plugin generate WoWonder’s `main_hash_id`. That would couple two separate session systems and is likely how the 64-character mismatch was introduced.

# Recommended implementation order

Apply and test in this order:

1. Replace the four session functions.
2. Add the SSO login initialization after `Wo_CreateLoginSession()`.
3. Fix the fast SSO path.
4. Confirm the main token rendered in the container has length 20.
5. Add `hash_id: $('.main_session').first().val()` to `Wo_RegisterFollow()`.
6. Replace `follow_user.php`.
7. Add router logging in `requests.php`.
8. Clear cookies and cached pages.
9. Log in again.
10. Inspect the log before attempting a follow.
11. Attempt user `1` following user `63`.
12. Compare the fingerprints from the page render, router, validator, and endpoint.
13. Only after session validation passes, investigate whether the database row is `active = 0` or `active = 1`.

The root cause is most likely a combination of:

- missing request-hash initialization during SSO login;
- missing explicit `main_session` transmission from `Wo_RegisterFollow()`;
- stale or incompatible 64-character hash state from the previous debugging package;
- potentially changing PHP session cookies during the SSO redirect cycle.

The correct fix is to restore one consistent session contract, not to remove `Wo_CheckMainSession()` from follow-related endpoints.
