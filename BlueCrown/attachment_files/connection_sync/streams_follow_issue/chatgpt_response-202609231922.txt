function Wo_CreateSession()
{
    /*
     * The PHP session must already be active.
     *
     * This function creates the application-level hash once and
     * then preserves it for the lifetime of the PHP session.
     */
    if (session_status() !== PHP_SESSION_ACTIVE) {
        if (function_exists('bz_streams_log')) {
            bz_streams_log(
                'create_session_without_active_php_session'
            );
        }

        return '';
    }

    /*
     * Preserve an existing valid application hash.
     */
    if (
        isset($_SESSION['hash_id']) &&
        is_string($_SESSION['hash_id']) &&
        preg_match(
            '/^[a-f0-9]{40}$/i',
            $_SESSION['hash_id']
        )
    ) {
        return $_SESSION['hash_id'];
    }

    /*
     * Generate a cryptographically secure 40-character
     * hexadecimal application hash.
     */
    try {
        $hash = bin2hex(
            random_bytes(20)
        );
    } catch (Throwable $exception) {

        /*
         * Compatibility fallback for environments where
         * random_bytes() is unavailable.
         */
        $hash = sha1(
            uniqid(
                (string) mt_rand(),
                true
            )
        );

        if (function_exists('bz_streams_log')) {
            bz_streams_log(
                'create_session_random_bytes_fallback',
                array(
                    'exception' => $exception->getMessage()
                )
            );
        }
    }

    $_SESSION['hash_id'] = $hash;

    return $hash;
}

# 8. Why the avatar appears to be causing it

This is the most important conceptual point.

`Wo_GetMedia()` itself returns a string. It does not execute an HTTP request.

So this:

```php
<img src="<?php echo Wo_GetMedia(...); ?>">
```

causes the **browser** to make another HTTP request after the HTML arrives.

If that generated URL is something like:

```text
https://buzzjuice.net/streams/upload/photos/...
```

and the web server serves it directly, no PHP bootstrap should run.

But if the generated URL is routed through something such as:

```text
/streams/index.php
/streams/requests.php
/streams/image.php
/streams/upload.php
```

then that second request can execute:

```text
assets/init.php
        ↓
bz_safe_session_start()
        ↓
session_start()
```

and, under the old code:

```text
session_start() fails
        ↓
session_destroy()
        ↓
session cookie removed
        ↓
new session
        ↓
new hash_id
        ↓
new main_hash_id
```

That would explain why removing the avatar appears to "fix" the problem. The GitHub analysis makes the same distinction.

# 10. Do not try to "fix" this by making `Wo_CheckMainSession()` permissive

I specifically recommend **not** doing:

```php
if (empty($_SESSION['main_hash_id'])) {
    return true;
}
```

and not doing:

```php
$_SESSION['main_hash_id'] = $hash;
return true;
```

inside `Wo_CheckMainSession()`.

That would convert:

```text
missing security token
```

into:

```text
valid request
```

which is architecturally backwards.

The correct model is:

```text
Page rendering
     │
     ├── PHP session exists
     │
     └── Wo_CreateMainSession()
             │
             └── create once if absent
                    │
                    ▼
              main_session
                    │
                    ▼
              Browser request
                    │
                    ▼
          Wo_CheckMainSession()
                    │
          ┌─────────┴─────────┐
          │                   │
        valid               invalid
          │                   │
       proceed             reject
```

That preserves the security boundary while eliminating unnecessary regeneration.
