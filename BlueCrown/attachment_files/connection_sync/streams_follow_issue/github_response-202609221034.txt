## Diagnosis

The follow operation is failing because the browser, server session, and rendered `main_hash_id` are becoming disconnected.

The important distinction is:

- `$_SESSION['hash_id']` and `$_SESSION['main_hash_id']` are **server-side PHP-session values**.
- They will never appear directly in browser cookies or DevTools.
- The browser only receives the PHP session cookie, normally `PHPSESSID`.
- The browser must also receive the rendered `.main_session` value and send that value back with protected AJAX requests.

The current follow request does not send a hash:

```javascript
$.get(Wo_Ajax_Requests_File(), {
    f: 'follow_user',
    following_id: id
}, ...)
```

However, `follow_user.php` validates the router-selected `$hash_id` with:

```php
Wo_CheckMainSession($hash_id)
```

Therefore the request normally reaches the endpoint with an empty or stale hash.

The diagnostic log confirms an additional problem. It repeatedly shows:

- a rendered `main_hash_id` being created;
- later requests sending a previous `main_hash_id`;
- the server creating a new PHP session with another `main_hash_id`;
- `check_main_session_failed`;
- the same stale client fingerprint being sent repeatedly.

That means this is not primarily an automatic-follow problem. It is a session continuity and token-transport problem.

Do **not** permanently change `Wo_CheckMainSession()` to `return true`. That disables a request-security boundary for follow, chat, payments, admin functions, and other endpoints.

The relevant current code is:

- [`streams/assets/init.php`](https://github.com/cupidblack/buzzjuice.net/blob/5a35fd9f80c6a97a4d5f2f91e96dfc722277f49d/streams/assets/init.php)
- [`streams/assets/includes/functions_two.php`](https://github.com/cupidblack/buzzjuice.net/blob/5a35fd9f80c6a97a4d5f2f91e96dfc722277f49d/streams/assets/includes/functions_two.php#L5590-L5638)

# 2. Fix PHP session initialization first

Your current `init.php` starts a session, but it does not explicitly guarantee that Streams and QuickDate use separate, consistent session cookies.

If QuickDate and Streams both use `PHPSESSID`, one application can overwrite, destroy, or reinterpret the other application's session.

The safest architecture is:

- WordPress owns WordPress cookies;
- QuickDate uses its own session cookie;
- Streams uses its own session cookie;
- every Streams request uses the same Streams cookie name, domain, path, and storage backend.

Add the following configuration **before** `bz_safe_session_start()` in `streams/assets/init.php`.

```php name=streams/assets/init.php url=https://github.com/cupidblack/buzzjuice.net/blob/5a35fd9f80c6a97a4d5f2f91e96dfc722277f49d/streams/assets/init.php

        JSON_UNESCAPED_UNICODE |
        JSON_PARTIAL_OUTPUT_ON_ERROR
    );

            $json . PHP_EOL,
            FILE_APPEND | LOCK_EX
        );
    }

function bz_safe_session_start()
{
    if (!function_exists('session_status')) {
        return false;
    }

    if (session_status() === PHP_SESSION_ACTIVE) {
        return true;
    }

    if (session_status() !== PHP_SESSION_NONE) {
        bz_session_log(
            'session_not_startable',
            array(
                'session_status' => session_status()
            )
        );

        return false;
    }

    if (headers_sent($headers_file, $headers_line)) {
        bz_session_log(
            'session_start_blocked_headers_sent',
            array(
                'headers_file' => $headers_file,
                'headers_line' => $headers_line
            )
        );

        return false;
    }

    try {
        $started = session_start();
    } catch (Throwable $exception) {
        bz_session_log(
            'session_start_exception',
            array(
                'exception_class' => get_class($exception),
                'exception_message' => $exception->getMessage()
            )
        );

        return false;
    }

    $active = (
        $started &&
        session_status() === PHP_SESSION_ACTIVE
    );

    bz_session_log(
        $active
            ? 'session_started'
            : 'session_start_failed',
        array(
            'start_return_value' => $started,
            'session_name' => session_name(),
            'last_error' => error_get_last()
        )
    );

    return $active;
}

### Important

If you cannot immediately separate the QuickDate session cookie, do not deploy the new cookie name partially. The name must be changed consistently for all Streams entry points.

After deployment, inspect the response headers. You should see something similar to:

```text
Set-Cookie: BUZZSTREAMSESSID=...; Path=/; Domain=.buzzjuice.net; Secure; HttpOnly; SameSite=Lax
```

Then inspect the follow request and confirm that the request contains:

```text
Cookie: BUZZSTREAMSESSID=...
```

If the cookie is absent from the AJAX request, the problem is cookie scope, browser policy, domain mismatch, or the request being sent to another hostname.

# 3. Replace the four session functions

The functions belong in `streams/assets/includes/functions_two.php`.

The following implementation:

- preserves valid existing values;
- generates cryptographically secure values;
- keeps `hash_id` at 40 hexadecimal characters;
- keeps `main_hash_id` at 20 hexadecimal characters;
- uses `hash_equals()`;
- logs fingerprints rather than full credentials;
- does not close and reopen the session;
- logs the stored and supplied values during every check.

Replace the existing four functions with this block.

```php name=streams/assets/includes/functions_two.php url=https://github.com/cupidblack/buzzjuice.net/blob/5a35fd9f80c6a97a4d5f2f91e96dfc722277f49d/streams/assets/includes/functions_two.php#L5590-L5638
if (!function_exists('Wo_SessionValueDiagnostics')) {
    function Wo_SessionValueDiagnostics($value)
    {
        if (!is_scalar($value)) {
            $value = '';
        }

        $value = (string) $value;

        return array(
            'present' => ($value !== ''),
            'length' => strlen($value),
            'sha256' => ($value !== '')
                ? hash('sha256', $value)
                : '',
            'format' => ($value !== '')
                ? (
                    preg_match('/^[a-f0-9]+$/i', $value)
                        ? 'hexadecimal'
                        : 'invalid'
                )
                : 'empty'
        );
    }
}

                    'headers_file' => $headers_file,

if (!function_exists('Wo_CreateSession')) {
    function Wo_CreateSession()
    {
        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'create_session_failed',
                array(
                    'session_key' => 'hash_id',
                    'reason' => 'php_session_not_active'
                )
            );

            return '';
        }

        $existing = isset($_SESSION['hash_id'])
            ? (string) $_SESSION['hash_id']
            : '';

        if (preg_match('/^[a-f0-9]{40}$/i', $existing)) {
            Wo_SessionDiagnosticLog(
                'create_session_reused',
                array(
                    'session_key' => 'hash_id',
                    'value' => Wo_SessionValueDiagnostics(
                        $existing
                    )
                )
            );

            return $existing;
        }

        try {
            $hash = bin2hex(random_bytes(20));
        } catch (Throwable $exception) {
            Wo_SessionDiagnosticLog(
                'create_session_random_bytes_failed',
                array(
                    'session_key' => 'hash_id',
                    'exception_class' => get_class($exception),
                    'exception_message' => $exception->getMessage()
                )
            );

            return '';
        }

        $_SESSION['hash_id'] = $hash;

        Wo_SessionDiagnosticLog(
            'create_session_created',
            array(
                'session_key' => 'hash_id',
                'old_value' => Wo_SessionValueDiagnostics(
                    $existing
                ),
                'new_value' => Wo_SessionValueDiagnostics(
                    $hash
                )
            )
        );

        return $hash;
    }
}

if (!function_exists('Wo_CheckSession')) {
    function Wo_CheckSession($hash = '')
    {
        $provided = is_scalar($hash)
            ? (string) $hash
            : '';

        if (!Wo_EnsurePhpSession()) {
            Wo_SessionDiagnosticLog(
                'check_session_failed',
                array(
                    'session_key' => 'hash_id',
                    'reason' => 'php_session_not_active',
                    'provided' => Wo_SessionValueDiagnostics(
                        $provided
                    )
                )
            );

            return false;
        }

        $stored = isset($_SESSION['hash_id'])
            ? (string) $_SESSION['hash_id']
            : '';

        $provided_valid = (bool) preg_match(
            '/^[a-f0-9]{40}$/i',
            $provided
        );

        $stored_valid = (bool) preg_match(
            '/^[a-f0-9]{40}$/i',
            $stored
        );

        $matched = (
            $provided_valid &&
            $stored_valid &&
            hash_equals($stored, $provided)
        );

        Wo_SessionDiagnosticLog(
            $matched
                ? 'check_session_passed'
                : 'check_session_failed',
            array(
                'session_key' => 'hash_id',
                'provided' => Wo_SessionValueDiagnostics(
                    $provided
                ),
                'stored' => Wo_SessionValueDiagnostics(
                    $stored
                ),
                'provided_valid' => $provided_valid,
                'stored_valid' => $stored_valid,
                'matched' => $matched
            )
        );

        return $matched;
    }
}

# 9. Harden `follow_user.php`

The endpoint currently does not guarantee that `$data` has a defined value for every failure path.

Use the following implementation:

```php name=streams/xhr/follow_user.php url=https://github.com/cupidblack/buzzjuice.net/blob/5a35fd9f80c6a97a4d5f2f91e96dfc722277f49d/streams/xhr/follow_user.php
<?php

    $data = array(
        'status' => 400,
        'can_send' => 0,
        'message' => 'Unable to process the follow request.'
    );

    $following_id = isset($_GET['following_id'])
        ? (int) $_GET['following_id']
        : 0;

    $session_valid = Wo_CheckMainSession($hash_id);

    if (function_exists('Wo_SessionDiagnosticLog')) {
        Wo_SessionDiagnosticLog(
            'follow_user_request',
            array(
                'following_id' => $following_id,
                'follower_id' => isset($wo['user']['user_id'])
                    ? (int) $wo['user']['user_id']
                    : 0,
                'hash_id' => Wo_SessionValueDiagnostics(
                    $hash_id
                ),
                'main_hash_id' => Wo_SessionValueDiagnostics(
                    isset($_SESSION['main_hash_id'])
                        ? $_SESSION['main_hash_id']
                        : ''
                ),
                'session_valid' => $session_valid
            )
        );
    }

    if ($following_id <= 0) {
        $data['message'] = 'Invalid user ID.';
    } else if (!$session_valid) {
        $data['message'] = 'Your session expired. Please refresh the page.';
    } else {
        $user_followers = Wo_CountFollowing(
            $wo['user']['id'],
            true
        );

        $friends_limit = $wo['config']['connectivitySystemLimit'];

        $is_following = Wo_IsFollowing(
            $following_id,
            $wo['user']['user_id']
        );

        $is_requested = Wo_IsFollowRequested(
            $following_id,
            $wo['user']['user_id']
        );

        if ($is_following === true || $is_requested === true) {
            if (
                Wo_DeleteFollow(
                    $following_id,
                    $wo['user']['user_id']
                )
            ) {
                $data = array(
                    'status' => 200,
                    'can_send' => 0,
                    'html' => '',
                    'state' => 'removed'
                );
            } else {
                $data['message'] = 'Unable to remove the follow relationship.';
            }
        } else if (
            $wo['config']['connectivitySystem'] == 1 &&
            $user_followers >= $friends_limit
        ) {
            $data = array(
                'status' => 400,
                'can_send' => 0,
                'message' => 'Your follow limit has been reached.'
            );
        } else {
            $registered = Wo_RegisterFollow(
                $following_id,
                $wo['user']['user_id']
            );

            if ($registered) {
                $data = array(
                    'status' => 200,
                    'can_send' => 0,
                    'html' => '',
                    'state' => 'added'
                );

                if (Wo_CanSenEmails()) {
                    $data['can_send'] = 1;
                }
            } else {
                $data['message'] = 'Unable to create the follow relationship.';
            }
        }
    }

    if ($wo['loggedin'] == true) {
        Wo_CleanCache();
    }

    header('Content-Type: application/json; charset=utf-8');
    echo json_encode($data);
    exit();
}
```

This does not force automatic acceptance. It first ensures that the request is valid and then calls the existing relationship logic.

If you want all new relationships to be accepted immediately, that policy must be implemented in the relationship-registration logic and verified in the database. Changing only the button label or making the session check always return true does not guarantee automatic acceptance.

# Expected final result

For a successful follow request, the complete chain should be:

```text
SSO bridge starts Streams session
        ↓
Wo_CreateSession() creates/reuses hash_id
        ↓
Wo_CreateMainSession() creates/reuses main_hash_id
        ↓
page renders .main_session
        ↓
Wo_RegisterFollow() reads .main_session
        ↓
AJAX sends hash_id=<main_hash_id>
        ↓
requests.php selects $_GET['hash_id']
        ↓
follow_user.php calls Wo_CheckMainSession()
        ↓
provided fingerprint equals stored fingerprint
        ↓
Wo_RegisterFollow() updates the database
        ↓
page reload reads the persisted relationship
```

The most important changes are:

1. Do not return `true` unconditionally from either session-check function.
2. Ensure Streams has a stable, separate session cookie.
3. Initialize both hashes in the SSO bridge.
4. Render `.main_session` in the active Sunshine layout.
5. Send `.main_session` as `hash_id` from `Wo_RegisterFollow()`.
6. Log fingerprints and session IDs at the router and endpoint.
7. Do not let the SSO bridge destroy the Streams session during an ordinary missing-cookie condition.
8. Verify the actual relationship row after the request instead of relying on the optimistic button state.
