### Important architectural corrections

1. **BuddyBoss remains the only relationship authority.**
2. **External platforms never write BuddyBoss tables directly.**
3. Streams/Socials first complete their own local action, then call the signed WordPress endpoint.
4. BuddyBoss-originated changes use BuddyBoss hooks and project outward.
5. QuickDate **Add Friend is not treated as an ordinary follow**.
6. QuickDate's shared `followers` table is interpreted according to the canonical BuddyBoss state:

   * pending connection → one `active=0` row;
   * connection → reciprocal `active=1` rows;
   * ordinary follow → one directional `active=1` row.
7. A block is destructive:

   * removes BuddyBoss connection;
   * removes both BuddyBoss follow directions;
   * removes corresponding Streams follows;
   * removes corresponding Socials relationship rows;
   * creates the external blocks.
8. Unblocking **never restores previous relationships**.
9. The signed REST command endpoint is:
   `/wp-json/bzj/v6/connection-management`
10. `/shared/wwqd_bridge.php` remains an identity/profile bridge rather than becoming another relationship control plane. This agrees with the GitHub recommendation. ([GitHub][1])
11. Synchronization state is retained in two small WordPress tables because durable idempotency/retry state cannot safely be replaced by a plain log file. The human-readable operational logs remain under `/data/logs`.
12. The current `db_helpers.php` already provides the required WoWonder and QuickDate `mysqli` connections and the shared SSO secret mechanism. 

The current Streams implementation confirms that `Wo_RegisterFollow()` can create pending rows through `confirm_followers`/`connectivitySystem`, while `Wo_IsFollowRequested()` currently only detects the pending row. That is why the integration explicitly forces ordinary synchronized follows to `active=1` and implements the requested automatic acceptance. 

The current QuickDate implementation also confirms the important distinction: `add_friend()` ultimately uses the followers mechanism, while `approve_friend_request()` changes the pending row to active and `disapprove_friend_request()` deletes it.
