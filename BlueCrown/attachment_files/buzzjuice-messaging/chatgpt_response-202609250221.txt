# 10. Security correction: never trust `wp_user_id` supplied by Streams/Socials

This deserves special emphasis.

The previous response proposed a signed request containing:

```text
wp_user_id
operation
payload
signature
```

That's directionally correct, but I would strengthen it.

The gateway must **not simply believe**:

```json
{
    "wp_user_id": 168
}
```

even when the request is HMAC-signed.

The signature proves:

> "This request came from an authorized platform."

It does **not automatically prove**:

> "The browser user really is WP user 168."

Therefore we need two identities:

```text
PLATFORM IDENTITY
        +
USER SESSION IDENTITY
```

The platform server authenticates to WordPress using:

```text
BUZZ_SSO_SECRET
```

Then the platform resolves its currently authenticated user:

```text
Streams user
        ↓
wo_user_id
        ↓
WP user ID
```

or:

```text
Socials user
        ↓
qd_user_id
        ↓
WP user ID
```

That mapping should happen server-side using the existing Buzzjuice identity architecture.

The browser must never be able to change:

```text
wp_user_id=42
```

to impersonate another member.

This is one place where the existing Buzzjuice SSO architecture gives us a major advantage. The previous architecture also correctly recommended reusing the signed-request mechanism and `BUZZ_SSO_SECRET`. ([GitHub][1])

# 31. Relationship integration

The existing Buzzjuice connection system should be reused rather than duplicated.

The messaging policy can query the authoritative relationship state:

```text
connected?
blocked?
pending?
```

It should **not create its own independent friendship system**.

Therefore:

```text
BuddyBoss
   ↓
relationship state
   ↓
Messaging Policy
```

This also means a block immediately affects messaging.

For example:

```text
A blocks B
     ↓
connection removed
     ↓
chat policy = denied
     ↓
existing conversation becomes read-only/blocked
```

Unblocking should not automatically restore the previous connection or chat entitlement.

That matches the non-restorative relationship model already established for Buzzjuice.
