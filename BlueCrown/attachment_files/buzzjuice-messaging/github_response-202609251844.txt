Short summary / recommendation
- Make WordPress (BP Better Messages) the authoritative message store & routing hub, and implement a small, secure “Buzz Messaging” MU-plugin (wp-content/mu-plugins/bzj-messaging.php) that exposes a signed REST API and event dispatcher.
- Implement lightweight signed clients for Streams (WoWonder) and Socials (QuickDate) that call the MU-plugin when a local chat action occurs, and listen for inbound events (push via sockets or fallback polling).
- Reuse patterns already used in the repo (signed HMAC+timestamp pattern from shared/bzj-connection-client.php and the WP-side queuing/retry patterns from wp-content/mu-plugins/bzj-connections-sync.php).
- Provide a NodeJS bridge (optionally reuse streams/nodejs) for real-time delivery (socket.io) and/or Redis pub/sub for scale. Real-time mode is a configuration toggle.
- Start incrementally: (A) server-side notifications only, (B) one-way message posting into WP (streams/socials → WP), (C) two-way messages with server pushes (WP → streams/socials) and socket delivery, (D) gating/credits/features layered on top.

1) Architecture & dataflow (high level)
- Authoritative store: BP Better Messages (WP).
- Event router (MU-plugin): receives signed webhooks/REST calls from Streams/Socials and from internal WP hooks; stores events in a lightweight queue and writes messages using BP Better Messages plugin API (or safe DB fallback).
- Outbound dispatcher: MU-plugin notifies other platforms about new messages (via nodejs socket, or via signed webhooks to Streams/Socials endpoints). Also publishes to NodeJS/Redis for real-time delivery.
- Clients on Streams/Socials:
  - On send: call MU-plugin REST endpoint (signed). MU-plugin will create the message in WP store and publish event.
  - On receive: subscribe to NodeJS sockets, or long-poll / poll / Server-Sent Events as fallback to get new inbound messages/receipt updates.
- Mapping: user mapping table associates user IDs between platforms (the bzj-connections-sync plugin already uses similar mapping for connections). Use or extend that ledger.

Dataflow for a message:
1. Streams user sends message -> Streams local UI calls Streams backend -> Streams backend triggers shared client which calls WP MU-plugin /message/create (signed).
2. MU-plugin validates signature, creates message in BP Better Messages store, returns success.
3a. If real-time enabled, MU-plugin pushes event to NodeJS (or Redis) which broadcasts to recipients (Streams/Socials socket clients). Recipients get live update.
3b. If no real-time, recipient client polls MU-plugin for new events (periodic AJAX).
4. Read receipts and reactions go back via the same signed flow.

2) Security, identity & mapping
- Use HMAC (sha256) signature over timestamp + JSON payload (like shared/bzj-connection-client.php). Include X-BZJ-Timestamp, X-BZJ-Signature headers. Reject if timestamp skew > configurable threshold (e.g., 120s).
- Shared secrets stored in environment or constants:
  - BZJ_MESSAGING_STREAMS_SECRET
  - BZJ_MESSAGING_SOCIALS_SECRET
  - or BUZZ_MESSAGING_SECRET (fallback).
- Map user ids across platforms:
  - Use existing mapping or create new meta-key usermeta like 'bzj_streams_id' and 'bzj_socials_id' for WP users.
  - The Streams/Socials client will include the local platform id and the WP user id (if known). If the only reliable identifier is platform-local, the MU-plugin can map WP user via an admin-provisioned mapping or a background reconciliation (similar to BZJ_Connections_Sync ledger).
- Rate-limit and validate inputs server side; sanitize content for stored HTML.

A) MU-plugin skeleton — wp-content/mu-plugins/bzj-messaging.php
```php
<?php
/**
 * name: BZJ Messaging - MU plugin
 * path: wp-content/mu-plugins/bzj-messaging.php
 *
 * Exposes signed REST endpoints for Streams/Socials to push/pull messages.
 */

if ( ! defined( 'ABSPATH' ) ) {
    // Running as must-use plugin; assume WP environment available.
}

class BZJ_Messaging {

    const NONCE_HEADER = 'X-BZJ-Signature';
    const TS_HEADER = 'X-BZJ-Timestamp';
    const HEADER_ORIGIN = 'X-BZJ-Platform';
    const SIGNATURE_ALGO = 'sha256';
    const MAX_SKEW = 120; // seconds

    private static $instance;

    public static function instance() {
        if (!self::$instance) self::$instance = new self();
        return self::$instance;
    }

    private function __construct() {
        add_action('rest_api_init', [$this, 'register_routes']);
    }

    public function register_routes() {
        register_rest_route('bzj-messaging/v1', '/message', [
            'methods'  => 'POST',
            'callback' => [$this, 'route_message_create'],
            'permission_callback' => '__return_true',
        ]);
        register_rest_route('bzj-messaging/v1', '/event', [
            'methods'  => 'POST',
            'callback' => [$this, 'route_event'],
            'permission_callback' => '__return_true',
        ]);
        register_rest_route('bzj-messaging/v1', '/status', [
            'methods'  => 'GET',
            'callback' => [$this, 'route_status'],
            'permission_callback' => '__return_true',
        ]);
        // More routes: poll, history, reconciliation endpoints
    }

    private function get_secret_for_origin($origin) {
        // Map platform name to secret constant or env var
        $origin = strtolower((string)$origin);
        if ($origin === 'streams') {
            return defined('BZJ_MESSAGING_STREAMS_SECRET') ? BZJ_MESSAGING_STREAMS_SECRET : getenv('BZJ_MESSAGING_STREAMS_SECRET');
        } elseif ($origin === 'socials') {
            return defined('BZJ_MESSAGING_SOCIALS_SECRET') ? BZJ_MESSAGING_SOCIALS_SECRET : getenv('BZJ_MESSAGING_SOCIALS_SECRET');
        }
        // fallback
        return defined('BUZZ_MESSAGING_SECRET') ? BUZZ_MESSAGING_SECRET : getenv('BUZZ_MESSAGING_SECRET');
    }

    private function verify_request($request) {
        $origin = $request->get_header(self::HEADER_ORIGIN) ?: '';
        $sig = $request->get_header(self::NONCE_HEADER) ?: '';
        $ts = $request->get_header(self::TS_HEADER) ?: '';

        if ($sig === '' || $ts === '' || $origin === '') {
            return new WP_Error('bzj_auth', 'Missing authentication headers', ['status' => 401]);
        }

        if (abs(time() - (int)$ts) > self::MAX_SKEW) {
            return new WP_Error('bzj_auth', 'Request timestamp skewed', ['status' => 401]);
        }

        $secret = $this->get_secret_for_origin($origin);
        if (empty($secret)) {
            return new WP_Error('bzj_auth', 'No secret configured for origin', ['status' => 401]);
        }

        $body = $request->get_body();
        $expected = hash_hmac(self::SIGNATURE_ALGO, $ts . '.' . $body, $secret);

        if (!hash_equals($expected, $sig)) {
            return new WP_Error('bzj_auth', 'Invalid signature', ['status' => 401]);
        }
        return true;
    }

    public function route_status( $request ) {
        return rest_ensure_response(['status' => 'ok', 'version'=> 'bzj-messaging-0.1']);
    }

    public function route_message_create( $request ) {
        $v = $this->verify_request($request);
        if ( is_wp_error($v) ) return $v;

        $payload = json_decode($request->get_body(), true);
        if (!is_array($payload)) {
            return new WP_Error('bad_payload', 'Invalid JSON', ['status' => 400]);
        }

        // Required fields: from_external_id, to_external_id (or to_wp_id), text, platform
        // Validate & sanitize
        $from = isset($payload['from_external_id']) ? intval($payload['from_external_id']) : 0;
        $to = isset($payload['to_external_id']) ? intval($payload['to_external_id']) : 0;
        $text = isset($payload['text']) ? wp_kses_post($payload['text']) : '';

        if ($from < 1 || $to < 1 || $text === '') {
            return new WP_Error('missing', 'Missing fields', ['status' => 400]);
        }

        // Map external ids to WP user ids if necessary (implement mapping function)
        $from_wp_id = $this->map_external_to_wp('streams', $from) ?: $from;
        $to_wp_id = $this->map_external_to_wp('streams', $to) ?: $to;

        // Insert message using BP Better Messages plugin API if available
        if (function_exists('bp_better_messages_insert_message')) {
            $res = bp_better_messages_insert_message([
                'sender_id' => $from_wp_id,
                'recipient_id' => $to_wp_id,
                'message' => $text,
                'type' => 'text',
            ]);
        } else {
            // fallback: trigger hook that plugin listens to, or DB insert
            do_action('bzj_messaging_create_message_fallback', [
                'from' => $from_wp_id,
                'to' => $to_wp_id,
                'text' => $text,
                'raw_payload' => $payload
            ]);
            $res = true; // actual write must be implemented by hooking into above, or direct DB
        }

        if (!$res) {
            // enqueue to local queue (to implement)
            return new WP_Error('insert_failed','Could not create message', ['status'=>500]);
        }

        // dispatch to other platforms (e.g., nodejs/redis/webhook)
        $this->dispatch_event('message_created', $payload);

        return rest_ensure_response(['status' => 200, 'ok' => true]);
    }

    private function dispatch_event($event, $payload) {
        // push to nodejs or webhook; keep as abstraction.
        // Implement HTTP call to NodeJS or publish to Redis here.
    }

    private function map_external_to_wp($platform, $external_id) {
        // Implement mapping via usermeta lookup or a dedicated table; placeholder:
        global $wpdb;
        $meta_key = ($platform === 'streams') ? 'bzj_streams_id' : 'bzj_socials_id';
        return (int) $wpdb->get_var($wpdb->prepare("SELECT user_id FROM {$wpdb->usermeta} WHERE meta_key=%s AND meta_value=%s LIMIT 1", $meta_key, (string)$external_id));
    }
}

BZJ_Messaging::instance();
```

B) Shared client library for Streams & Socials (shared/bzj-messaging/bzj-msg-client.php)
```php
<?php
/**
 * Minimal signed client to post events to WP MU-plugin
 * Place in shared/bzj-messaging/bzj-msg-client.php
 */

function bzj_msg_secret($origin) {
    $name = strtoupper('bzj_messaging_' . $origin . '_secret');
    if (defined($name) && constant($name)) return constant($name);
    if (getenv('BZJ_MESSAGING_SECRET')) return getenv('BZJ_MESSAGING_SECRET');
    return '';
}

function bzj_msg_post($origin, $endpoint, $payload) {
    $secret = bzj_msg_secret($origin);
    if (!$secret) throw new RuntimeException('Messaging secret not configured');

    $raw = json_encode($payload);
    $ts = (string) time();
    $sig = hash_hmac('sha256', $ts . '.' . $raw, $secret);

    $base = defined('BUZZWORDPRESS_API_BASE') ? BUZZWORDPRESS_API_BASE : 'https://buzzjuice.net/wp-json';
    $url = rtrim($base, '/') . '/bzj-messaging/v1/' . ltrim($endpoint, '/');

    $ch = curl_init($url);
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_POST => true,
        CURLOPT_POSTFIELDS => $raw,
        CURLOPT_HTTPHEADER => [
            'Content-Type: application/json',
            'X-BZJ-Timestamp: ' . $ts,
            'X-BZJ-Signature: ' . $sig,
            'X-BZJ-Platform: ' . $origin
        ],
        CURLOPT_TIMEOUT => 10,
    ]);
    $resp = curl_exec($ch);
    $http = curl_getinfo($ch, CURLINFO_HTTP_CODE);
    $err = curl_error($ch);
    curl_close($ch);
    if ($err !== '') return ['success' => false, 'error' => $err, 'http' => $http, 'raw' => $resp];
    $decoded = json_decode($resp, true);
    return is_array($decoded) ? $decoded : ['success' => true, 'http' => $http, 'raw' => $resp];
}
```

D) NodeJS bridge (concept example)
- Add a small HTTP endpoint to your nodejs process that can receive POST events from MU-plugin and broadcast to socket.io channels. Or use Redis pub/sub.

Example (brief):
```js
// nodejs/bridge.js (sketch)
const express = require('express');
const bodyParser = require('body-parser');
const socketio = require('socket.io');
const http = require('http');
const app = express();
app.use(bodyParser.json({limit: '1mb'}));
const server = http.createServer(app);
const io = socketio(server, { cors: { origin: '*' } });

app.post('/_bzj/events', (req,res) => {
  // Optional: validate a secret in header X-BZJ-Secret
  const event = req.body;
  // event.payload should include recipient external id and platform
  if (event && event.recipient_external_id) {
    const channel = `user-${event.recipient_external_id}`;
    io.to(channel).emit('bzj_message', event);
  }
  res.json({ok:true});
});

io.on('connection', (socket) => {
  // client should emit 'identify' with their external id
  socket.on('identify', (data) => {
    if (data && data.external_id) {
      socket.join(`user-${data.external_id}`);
    }
  });
});
server.listen(3000);
```
- MU-plugin dispatch_event should POST to this /_bzj/events endpoint.

E) Client JS (fallback poll + socket connect) (shared/bzj-messaging/js/bzj-messaging.js)
```javascript
// quick client library
(function(window) {
  function BZJMessaging(opts) {
    this.origin = opts.origin || 'streams';
    this.external_id = opts.external_id || 0; // user's external id for platform
    this.socketUrl = opts.socketUrl || null;
    this.pollUrl = opts.pollUrl || '/wp-json/bzj-messaging/v1/poll';
    this.socket = null;
    this.pollInterval = opts.pollInterval || 5000;
    this._pollTimer = null;
  }
  BZJMessaging.prototype.connect = function() {
    if (this.socketUrl && window.io) {
      this.socket = io(this.socketUrl);
      this.socket.on('connect', () => {
        this.socket.emit('identify', { external_id: this.external_id });
      });
      this.socket.on('bzj_message', (e) => {
        document.dispatchEvent(new CustomEvent('bzj_message', { detail: e }));
      });
      return;
    }
    this._startPolling();
  };
  BZJMessaging.prototype._startPolling = function() {
    var self = this;
    this._pollTimer = setInterval(function(){
      fetch(self.pollUrl + '?to_external_id=' + encodeURIComponent(self.external_id))
        .then(r => r.json())
        .then(d => {
          if (Array.isArray(d.messages)) {
            d.messages.forEach(m => document.dispatchEvent(new CustomEvent('bzj_message', { detail: m })));
          }
        })
        .catch(()=>{});
    }, this.pollInterval);
  };
  BZJMessaging.prototype.disconnect = function() {
    if (this.socket) this.socket.disconnect();
    if (this._pollTimer) clearInterval(this._pollTimer);
  };
  window.BZJMessaging = BZJMessaging;
})(window);
```

7) Additional technical & operational considerations
- Identity & mapping:
  - You must define one consistent mapping strategy for users across platforms. The simplest path: provision WP user accounts for Streams/Socials external users (with mapping meta), or maintain mapping table and reconcile periodically as in bzj-connections-sync.

- Store minimal event logs for reconciliation and add CLI/cron reconcile jobs.
- For group chats, rely on BP plugin's group constructs; ensure MU-plugin respects group message semantics when dispatching.

10) Performance & scaling recommendations
- Real-time: use NodeJS + socket.io + Redis for horizontal scaling. MU-plugin posts events to redis pub/sub or HTTP to NodeJS, NodeJS publishes to connected socket clusters.
- Consider sharding events by user id mod N if very large.
- Protect endpoints with rate limiting (WP REST plugin or custom throttling).
- Messages should be small JSON, attachments uploaded to a central store (S3/Backblaze) and only references sent in events.
