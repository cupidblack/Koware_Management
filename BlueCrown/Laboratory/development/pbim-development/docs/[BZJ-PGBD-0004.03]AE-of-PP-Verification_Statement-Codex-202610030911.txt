# 11. SINGLE AUTHORITATIVE ARTIFACT RULE

At every stage, exactly one artifact is authoritative.

A subsequent stage may:

* reference it;
* challenge it;
* supersede it through controlled process.

A subsequent stage may not silently rewrite it.

Re-entry requires:

```text
Change Request
 ↓
Impact Assessment
 ↓
Authority Decision
 ↓
New Task Packet
 ↓
Superseding Artifact
 ↓
Re-verification
```

This prevents recursive proposal/template loops.

# 14. IMPLEMENTATION VERIFICATION GATE

A new mandatory distinction is introduced:

## Design verification

Demonstrates that the architecture has been logically specified and independently examined.

## Implementation verification

Demonstrates that the actual repositories, branches, files, workflows or automation enforce the architecture.

A design control may therefore be:

```text
DESIGN-VERIFIED
```

while remaining:

```text
IMPLEMENTATION-PENDING
```

This is not a contradiction.

It is the intended two-stage verification model.

Copilot specifically identified the failure of the previous document to make this distinction sufficiently explicit.

# 20. EVIDENCE RULE

Agent agreement is not evidence.

Evidence must be one or more of:

```text
E1 — Direct Artifact Evidence
E2 — Structural Verification
E3 — Agent Finding
E4 — Architectural Decision
E5 — Implementation Verification
```

The critical distinction is:

```text
E3 ≠ E5
```

An agent saying that a control exists does not prove that the repository enforces it.
