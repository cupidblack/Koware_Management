> **Execution contract.** On a `DAILY_CHRONICLE` instruction, run the ordered operations below. The master sets policy, franchise substance, command scope, date algorithm, creative transformations and A/B/C boundaries. This runbook sets the actual sequence, per-step evidence, stop/continue decision, verification and portable handover. A newer draft file's presence on GitHub is not proof of adoption.

## 1. Purpose, scope and entry conditions

This runbook is appropriate only after an express daily commission or a deliberately authorized dry-run. Other master modes are **routed** rather than silently executed: `REVIEW_ONLY` produces documentation only; `DAILY_REVISION` updates a named draft through a new revision and proposed deltas; `EPISODE_COMPILATION`, chapter/season rollups, `COMIC_*`, `MEDIA_*` and `ARCHIVE_WRITE` follow their distinct commissions. A weekend requires its own special-issue authorization and never occupies a normal Monday–Friday Chronicle #1–#10 slot by implication. A reviewer should not execute the daily run because they were merely asked to refactor it.

Before starting, distinguish the following independent state axes from CC-UPMP §4: process (`REQUEST_CLASSIFIED`, `PREFLIGHT`, `GO`, `GO_WITH_OMISSIONS`, `BLOCKED`, `EVIDENCE_LOCKED_FOR_DRAFT`, `DRAFTED`, `AWAITING_EDITORIAL_REVIEW`); editorial (`UNREVIEWED`, `CHANGES_REQUESTED`, `ACCEPTED`, `LOCKED`, `REJECTED`); persistence (`UNSAVED`, `DRAFTED_NOT_COMMITTED`, `WRITE_AUTHORIZED`, `COMMIT_ATTEMPTED`, `COMMITTED_VERIFIED`, `WRITE_FAILED`, `CONFLICT_REQUIRES_RECONCILIATION`); release (`NOT_ELIGIBLE`, `RELEASE_ELIGIBLE`, `PUBLICATION_AUTHORIZED`, `PUBLISHED_VERIFIED`); derivative (`NOT_COMMISSIONED`, `PLANNED`, `STORYBOARDED`, `PROMPTS_CREATED`, `ASSETS_RENDERED_VERIFIED`, `ASSEMBLED_VERIFIED`, `QA_PASSED`, `APPROVED`, `STALE_SOURCE`). These are not interchangeable. In B1/B8 represent their actual values and the observation or authorization supporting each one.

### 1.1 Minimal input contract

Resolve from the *actual* instruction and authorized records: the requested operation; production-local target date or explicit date-selection authority; approved production timezone; usable master/protocol/ledger versions and effective status; authorized commissioning actor and recipients; approved calendar and episode identity; accessible accepted continuity; applicable canon/rights; permitted A and B destinations; and source endpoints/resources. Extra stylistic requirements apply only where they do not override privacy, historical truth, canon or the master. If a required value is absent, represent it by a missing-state and reason; do not manufacture an ID, date, source response, human approval or calendar fixture.

### 1.2 Output contract

A successful *draft* run produces **A** (one standalone, public-eligible **draft** chronicle, ending literally with one challenge question and any approved public choices) and **B** (a separately saved or separately transmitted **internal-only** B1–B8 packet). Produce **C** only by an independent explicit restricted-key instruction and verified secure custody, never in chat, A, B, package downloads or public repositories. If a central prerequisite is unresolved, return a nonpublishable `BLOCKED` report rather than a fictionally completed Output A. Every completed run also reports actual QA and the exact next permissible action.

## 2. Phase 0 — classify the request and resolve authority

1. Parse explicit mode, date, operation count, expected length/language, allowed sources, recipients and any special commission. `REVIEW_ONLY` exits to document review; do not write story prose.
2. Identify approved *scope-specific* authority: law/rights; owner decisions; Studio storage and disclosure controls; approved character/world/era canon and organization records; approved season/chapter/episode and continuity; approved production specification; and any expressly tested v0.08.00 candidate. Use CC-UPMP §3 when reconciling hierarchy.
3. Pin which document editions are actually being used as **working baseline**, separately from their **ratification state** and persisted schema version. Preserve historical `S00_T05` / `S00_T05_E01` IDs unless a genuine authorized crosswalk exists.
4. Check that publication-eligible A can be physically separated from internal B. A model reply with private B after a public challenge is not a compliant public artifact; use separate files or properly access-controlled channels.
5. Identify whether the requested output is **definitive**, **expressly provisional**, or **blocked**. Provisional authorization can address an editorial uncertainty but cannot waive consent, copyright, platform safety or independent factual claims.

**Exit gate:** operation, date-resolution method, authority status and output recipients are known. Otherwise mark `BLOCKED`, identify decision owner and report rather than invent.

## 3. Phase 1 — inventory and retrieve actual sources

A URL, search result, directory name, previously remembered excerpt or draft claim is **not** proof of reading the underlying material. Make a read attempt where access permits and record URI, source owner, version/commit/edition when observable, acquisition time with timezone, request-date relevance, access state, digest if actually calculated, intended use, rights, conflicts and exact missing fields. Separate **not fetched**, **fetched but unverified**, **verified and authorized**, and **access-restricted** states.

| Evidence group | Actual checks | If absent or conflicting |
|---|---|---|
| Approved calendar, timezone, phase boundaries, full episode slots, Foundation crosswalk | Effective-dated owner record; inclusive/exclusive end rule; assigned chapter/episode/day; existing identity | **Block definitive episode/day identity**; do not make live Probe the calendar authority. |
| Studio governance, approved character/world/technology canon | Actual specific version, era limits, permissions and affected character | Omit optional character; block if essential premise would contradict binding canon. |
| Accepted last chronicle, event/state projection, current mission/roles and prior B6 | Read accepted source and base revision; carry forward open mission, locations, obligations | Report gap; block only when essential causal continuity cannot be established safely. |
| Organizational role chart and actual Koware projects | Current chart revision, aliased check day 1–40, real action evidence and publication rights | Never claim fictional work happened in the organization; omit unsupported assignments. |
| Reading-plan list and effective-dated week anchor | Real 250-entry catalog, selection rule and actual dated entry | No invented week/daily text; noncentral material may be omitted with B2 disclosure. |
| Verse and H&S learning | Actual requested-date YouVersion attribution *or named genuine alternative*; real Buzzjuice Health & Safety course/module/lesson | No false provider or invented accredited lesson; source omissions documented. |
| Millennium clocks and distinct locations | Historical endpoint and Probe endpoint; current or authorized pinned response; independent HQ/home/history/probe/team locations | Capture failed attempts, unknown fields and evidence age; no false retrospective telemetry. |
| History, current reporting, optional weather/geography | Source publication date, event date, geographic fit, actual story period; distinguish fact from future imagination | Remove unsupported claims; never invent newspaper coverage in the future. |
| Diaries, source licenses, real-person portrayal, images, private communications | Actual permission for *this* actor, operation, audience and revocation state | Deny use by default; do not infer public consent from read access or previous draft. |
| Public challenge and derivative states | Prior obligation, exact current story revision; opaque custody metadata; valid commissioned derivative links | No solution retrieval by ordinary run; derivatives marked not commissioned or stale as appropriate. |

**Minimum B2 source classifications:** `VERIFIED_REAL_WORLD_FACT`, `HISTORICAL_INTERPRETATION`, `FICTION_PROBE_SCENARIO`, `CANON_ACCEPTED`, `FICTIONAL_DRAFT`, `PROPOSAL`, `UNVERIFIED`, `RESTRICTED`. Where a previous evidence item is reused, identify the stored capture date and whether it is adequate for the requested historical/present claim; don't rebrand it as today's live retrieval.

**Exit gate:** provenance for each central factual statement is supportable, or a scoped `GO_WITH_OMISSIONS` disposition is possible. A core unlicensed/unsafe source, unresolvable date or binding canon conflict is `BLOCKED`.

## 4. Phase 2 — resolve the production date, episode, IDs and role index

Follow **CC-UPMP §§5–7 and the actual approved calendar**, not an approximate season window:

1. Convert approved effective phase start/end and target to the **approved production timezone**, preserving original offsets. For a date-only user request, use that local civil date as instructed; do not assign an invented time of day. Determine whether the approved end is inclusive or exclusive.
2. Let `anchor` equal the first Monday on/after the approved phase-start *local date*. Dates earlier than this are unallocated partial-week days unless the approved calendar explicitly says otherwise.
3. Let `elapsed_days = target_local_date - anchor` in whole local civil days. Reject negative offsets, approved phase gaps, dates beyond authorized episode blocks and full episode spans that exceed phase-end bounds.
4. Let `episode_ordinal = floor(elapsed_days/14)+1` (allow **1–4 only** for a full ordinary chapter); let `block_day = elapsed_days mod 14`.
5. If `block_day` is 0–4, then `chronicle_ordinal = block_day+1`; if 7–11, then `chronicle_ordinal = block_day-1`; if 5, 6, 12 or 13, return `WEEKEND_NOT_SCHEDULED` without assigning a standard chronicle ordinal.
6. Let `chapter_working_day = 10*(episode_ordinal-1)+chronicle_ordinal` (**1–40**). The episode window is first Monday through the **second Friday**, i.e. 11 calendar days later; check the *whole* window. An editor-approved shortened episode follows its own explicit exception policy; no unapproved invented slot.
7. Resolve season, chapter, episode and chronicle **against actual accepted IDs and legacy archive paths**. Never assume `S00_T05 = CH05` or that a new folder template is real. For duplicate target days, inspect previous status and either propose a named `DAILY_REVISION`, decline redundant creation or follow a verified owner decision; do not silently overwrite.
8. Use **chapter working day 1–40** for role checks. Never index roles by the daily episode ordinal 1–10. Where role chart uses 20-day recurring semantics, require the actual chart or owner decision before applying modulo arithmetic.

**Calendar examples for deterministic unit tests only, not current episode assertions:** `elapsed_days` 0→episode1/day1/chapterday1; 4→1/5/5; 7→1/6/6; 11→1/10/10; 14→2/1/11; 28→3/1/21; 42→4/1/31; 53→4/10/40. Days 5,6,12,13 and corresponding block offsets are weekends. A current Probe's `phase_index` is telemetry rather than approval or an identifier crosswalk.

**Exit gate:** verified slot and day/role indices, or explicit `CALENDAR_EXCEPTION`/`BLOCKED` with the exact missing authority. Do not label an unverified episode #N in A.

## 5. Phase 3 — obtain and lock the three-clock run snapshot

Track each time as a *separate* datum from its retrieval instant and physical location:

| Clock | Meaning and authority | Acquisition rule | Explicit prohibition |
|---|---|---|---|
| `P` — production present | Requested story date in approved local timezone (actual local today only for a today's-story request) | Approved calendar; current local datetime if requested; execution/retrieval time stored separately | Do not use today's news as if it existed on a retrospective requested date. |
| `H` — historical reference | Independently obtained historical `.iso` value and **separate** authorized Enka historical-reference location | `https://buzzjuice.net/shared/millennium-timezone/millennium-timezone.php?endpoint=historical` or authenticated pinned fallback | Historical clock does **not** prove present Enka was physically there. |
| `F` — Edubeam Probe | `probe_iso` with `now_iso` when actually supplied, other returned telemetry and separately accepted probe destination | `https://buzzjuice.net/shared/millennium-timezone/millennium-probe.php?probe=now`, cross-check optional probe endpoint | Future probe dates are fictional research settings, never verified future reporting. |

Capture HTTP/retrieval status, actual exact payload, parsed fields and parse errors; source UTC timestamp vs offset; any `phase_start_iso`/`phase_end_iso`/`phase_index`, oscillation and amplitude *only if returned*; timezone conversions; payload source/capture timestamp/digest if available; expected-vs-observed field set; whether the snapshot is **live, historical pinned, user-supplied fallback, stale, unavailable or unverified**. Do not insert dummy telemetry. A valid old fallback may be used only as expressly permitted and must retain its true age and provenance.

Resolve **distinct locations**, without unsafe coalescence: Koware HQ, current Enka, possible home, Enka at historical reference, Adenta laboratory, Probe destination, and every deployed member's latest accepted physical/temporal position. A place may be `UNKNOWN` or `RESTRICTED`; never default a missing member to HQ. Scene timestamps must reconcile with transit/retrieval events and each character's knowledge. Freeze the source set as an **as-of-draft logical snapshot**: new live results later require a new snapshot or revision rather than silent mutation.

**Exit gate:** sufficient timestamp/space provenance to write safely, or explicitly identified omissions. If the three-clock anomaly drives the central plot and all necessary data are absent, block the definitive draft.

## 6. Phase 4 — reconstruct accepted continuity without accepting today's ideas

Load current approved episode context and the last **accepted** A revision; inspect actual accepted, nonrevoked continuity events, storyline, character, role, mission and challenge projections, current source/rights status, and any later editorial corrections since the last handover. Distinguish accepted history from drafts, speculative B6 notes, proposed canon and external real-life events. Derive a story-state **read view** from accepted events only; preserve its base revision so later proposed events can cite what state they would change.

Reconstruct, per character: knowledge boundaries, relevant relationships, obligations, last verified whereabouts, current location time, appearance/era limitations and source link. For any active mission reconstruct: goal, team membership, device state, time and physical location of each deployed person, messages, charge/communications assumptions, hazard/retrieval window, open causality and last accepted event. If not known, use an explicit unknown; do not state `NO ACTIVE MISSION` without adequate current evidence.

Preserve open arcs and previous public challenge release obligations across second Friday, episode, chapter and season boundaries. Day #10 is only a **readiness checkpoint**; it does not teleport teams home, award prizes, reveal the current answer, finalize a title, compile ten days or publish the episode. Compare current storyline context with approved canon and current human correction log; file material conflict when they disagree.

**Exit gate:** an evidence-linked baseline, explicit unknowns, causal restrictions for today and a list of safe proposed deltas. No draft event becomes accepted by this step.

## 8. Phase 6 — draft standalone Output A

Create **one** cohesive titled and appropriately labeled chronicle for the **one** supported day. The display identifier is provisional until authoritative calendar/identity is established; an approved existing title/path cannot be silently replaced. Use accurate place/time transitions, original prose, believable action/dialogue, episode beat and clear causal movement. Use the six stages as ingredients naturally integrated with Enka, Koware Group, recurring characters, real historical context and evolving Edubeam technology. Preserve actual mission limits and enforce exact knowledge/whereabouts, including delayed communication and return-trip causality. Never imply an actual organizational task was completed because a character accomplished its fictional analogue.

The public challenge must be **one** fair, relevant and feasible question, normally A–E multiple choice when suitable, answerable from the public story and/or an authentically public source. Its **full question and choices are the very last public-facing content of A**. Place permitted source attributions before the question if required. No bibliography, timestamp, internal annotation, endnote, credit, signature, footer, B heading, correct letter, answer, reveal, explanatory near-hint or answer-bearing filename/alt text follows or accompanies the challenge. Do not include unlicensed private details. Produce A as a separate artifact or exclusively public-eligible message.

If a source-safe narrative can be drafted but its intended competition cannot be launched because secure answer custody is absent, mark **draft** A as permitted and **competitive release** as blocked until owner policy is satisfied. Do not create restricted C in an ordinary workflow.

**Exit gate:** Output A passes narrative, rights, time/place and terminal-challenge checks, or returns to drafting without release claims.

## 11. Phase 9 — editorial handover, persistence and revision control

1. Produce a source-specific B8 QA table and accurate five-axis state report. An unreviewed draft ends in `DRAFTED`, `AWAITING_EDITORIAL_REVIEW`, `DRAFTED_NOT_COMMITTED` and no publication claim unless real external evidence establishes more.
2. Preserve the old accepted story revision and ledger `base_revision`; produce **proposed** event deltas and successor draft revision. A draft event is not eligible for the accepted-state projection before authorized human acceptance.
3. If—and only if—`ARCHIVE_WRITE` is separately authorized, write capability exists and a Studio-approved location/ACL is verified: read current head; validate expected `base_revision`; separate A/B/C destinations; stage an append/supersede operation; commit atomically if supported; verify by readback, returned immutable revision and access check. An intervening edit yields `CONFLICT_REQUIRES_RECONCILIATION`; do not force overwrite. Log actual failure and retry decision. Local generated files are **not GitHub commits**.
4. Refresh B6 *after* QA so it reflects actual latest draft and all discovered gaps. B6 must not absorb private key, diary contents without permission or provider-hidden memory. Before the **next** daily run, re-read latest approved ledger and corrections rather than trusting yesterday's stale handover.
5. For Chronicle #10, report ten-slot **compilation readiness** with each day's actual acceptance/revision. Do not auto-compile, approve episode title, recall deployed cast, reveal challenge answers or publish. For unresolved chapter-final release, seek the human decision specified in master §20.
6. If an editor accepts a revision, preserve the actual acceptance evidence and apply its accepted event delta under the ledger's conflict-safe projection contract; do not backdate the acceptance.

### 11.1 Exact blocked-run return contract

A `BLOCKED` result reports: actual requested mode/date/timezone and source; working governing versions/ratification; verified vs unresolved calendar and identifiers; source retrieval attempts; material blocker with severity, canon/privacy impact and conflicting evidence; any permissible scoped fallback; which exact source/decision/action owner could unblock; applicable Q results; and actual process/editorial/persistence/release statuses. It must **not** present a fabricated complete Output A. Internal-only facts remain in an authorized internal channel.

### 11.2 Daily revision and duplicate handling

For `DAILY_REVISION`, require existing source A revision and its editorial status. Record proposed textual delta, changed factual claims/permissions, new source snapshot, updated challenge if affected, event supersession proposals, downstream derivative staleness and required editor reacceptance. A previous published version remains an accurately recorded historical fact; remediation/public correction requires separate release authorization. If a date already has an accepted A, default to revision review rather than creating a duplicate new daily identity.
