3. ARCHITECTURAL PRINCIPLES
======================================================================

3.1 LEAN FIRST
Build the smallest reliable system capable of producing the episode.

3.2 SEPARATION OF CONCERNS
Keep production, communications, AI, archive, publishing and business
functions distinct.

3.3 ONE PERSISTENT AI DESK
There is one CC_AI_DESK for the entire Classies Chronicles franchise.
Episodes do not receive separate AI Desks.

3.4 EPISODE DATA REMAINS EPISODE-OWNED
The episode archive is authoritative for episode-specific information.
The AI Desk stores intelligence infrastructure and references, not the
episode's raw media or permanent episode-specific knowledge.

3.5 PROVIDER NEUTRALITY
Calling platforms and storage providers are replaceable endpoints.

3.6 HUMAN EDITORIAL AUTHORITY
AI may assist, converse and eventually operate autonomously within defined
boundaries, but editorial, consent, licensing and emergency controls remain
human-governed.

3.7 REBUILDABLE DERIVED DATA
Catalogs, indexes, hashes and retrieval caches are derived and rebuildable.

3.8 FAIL SAFE
Missing sources, invalid permissions, provider failures and stale indexes
must produce controlled failure rather than invented or unauthorized output.

10. MICROPHONE POLICY
======================================================================

ENVY:

    Primary:
    Conexant SmartAudio HD Microphone Array

Pavilion:

    Primary:
    Blue Yeti

    Backup:
    Intel Smart Sound Digital Microphone Array

V8S condenser:

    Supplemental close-range microphone.

The V8S condenser performs well at close range but requires excessive gain
when the speaker moves farther away, which can introduce noise and distortion.

The system should prioritize:

1. microphone placement
2. microphone distance
3. clean source gain
4. room control
5. routing
6. processing

Do not attempt to solve poor microphone placement with excessive gain.

19. PODCAST COMMUNICATIONS MODULE
======================================================================

The Pavilion is the Guest Communications Desk and uses Voicemeeter Potato
as the communications bus for Host ↔ Guest ↔ AI interaction.

The system is designed to prevent each participant from hearing their own
returned audio while allowing:

    HOST <-> GUEST
    HOST <-> AI
    GUEST <-> AI

The semantic communications buses are:

    A1 = Host Monitor
    B1 = Call Transmit
    B2 = AI Input
    B3 = Production Reserve

Conceptually:

    B1 = HOST + AI
    B2 = HOST + GUEST
    AI RETURN is excluded from B2
    GUEST RETURN is excluded from B1

AI return is separately controlled and may be routed to host and guest
without returning to AI input.

Calling applications remain replaceable endpoints, including WhatsApp,
Google Meet, Zoom, Riverside, Microsoft Teams and future providers.

The detailed Voicemeeter Potato installation, device configuration,
application I/O, mix-minus matrix, troubleshooting, testing and operating
procedures are intentionally NOT reproduced in this skeletal blueprint.

Full detailed blueprint:

https://github.com/cupidblack/Koware-Management/blob/main/Psymedia/Podcast%20Communications%20Module.txt

20. AI DESK ARCHITECTURE
======================================================================

CC_AI_DESK is one persistent franchise-level AI control plane for all
Classies Chronicles episodes.

It owns reusable intelligence infrastructure such as:

- persistent persona
- intellectual style
- voice and behaviour rules
- boundaries
- prompt methodology
- provider/runtime configuration
- retrieval configuration
- source catalog
- rebuildable indexes
- source hashes/status
- permission-aware retrieval state
- automation
- producer controls
- operational logs

It does NOT become the permanent home of:

- raw video
- raw audio
- full episode media
- arbitrary member exports
- private/unapproved material
- episode-specific research as permanent global knowledge

Episode data remains in the episode archive.

The AI Desk references and retrieves episode content through a controlled
catalog/retrieval layer.

Core retrieval scopes are:

    CURRENT_EPISODE
    CURRENT_SEASON
    ALL_APPROVED_EPISODES
    GLOBAL_CHRONICLES

The active scope must always be visible to the producer.

Initial retrieval:

    SQLite + FTS5

Later:

    Hybrid FTS5 + semantic/vector retrieval

Semantic infrastructure is deferred until real archive/search gaps justify it.

Persona evolution is governed:

    EPISODE
       ↓
    TRANSCRIPT
       ↓
    POST-EPISODE ANALYSIS
       ↓
    PERSONA PROPOSAL
       ↓
    PRODUCER REVIEW
       ↓
    APPROVE / REJECT
       ↓
    VERSIONED PERSONA CHANGELOG

AI MUTE must remain independently controllable.

The detailed filesystem contract, schemas, catalog, retrieval architecture,
episode context contract, automation, persona governance, UI and validation
procedures are intentionally NOT reproduced here.

Full detailed blueprint:

https://github.com/cupidblack/Koware-Management/blob/main/Psymedia/Classies_Chronicles_AI_Desk_Architecture_v22.0.txt

23. ARCHIVE SCANNING AND INDEXING
======================================================================

The persistent AI Desk must be able to scan the entire Chronicles archive.

Scanner responsibilities:

- discover seasons
- discover episodes
- discover context packages
- read metadata
- read status
- read permission states
- detect changed files
- calculate hashes
- update the catalog
- mark stale index entries

Preferred content hash:

    SHA-256

Derived system components should track:

    source version
    parser version
    index version

The catalog and FTS5 index must be rebuildable from authoritative sources.

Incremental indexing is preferred over blindly rebuilding the entire archive
after every minor change.

        ↓

        ↓
    HUMAN REVIEW
        ↓

Future Buzzjuice integration should use a controlled API/MU-plugin boundary.

The AI Desk must not directly query arbitrary WordPress database tables.

The boundary should expose only what the Chronicles workflow requires:

- controlled participant identity reference
- consent state
- content eligibility
- licensing state
- publication permission
- revocation state

If consent is withdrawn, the source must become restricted for retrieval and
publication.

A stale index must never override a current permission state.

Participant data should be minimized.

Participant records are not a general CRM.

25. AI OPERATING MODES
======================================================================

AI is controlled through four operating modes:

LISTEN
    AI receives permitted conversation but does not speak.

ASSIST
    AI provides producer-facing assistance without automatically entering
    the live programme.

CO-HOST
    AI participates as a controlled spoken participant.

AUTONOMOUS
    AI may reasonably initiate, respond, challenge, question and contribute
    within defined production boundaries.

AUTONOMOUS is not the default commissioning mode.

Independent control:

    AI MUTE

AI MUTE must be capable of silencing AI audio even if:

- the model hangs
- the UI fails
- retrieval fails
- network latency increases
- an AI provider fails

The exact physical mute/routing implementation is governed by the Podcast
Communications Module.

6. verify that the copied files are readable
7. maintain an additional off-machine copy when practical

The IO Crest enclosure normally remains powered off and is activated for
archive/restore operations.

Backup priority:

    1. Episode Context
    2. Project files
    3. Master recordings
    4. Stems
    5. Final exports
    6. Generated assets
    7. Supporting metadata

Git should primarily hold text, configuration, schemas, prompts, scripts and
other version-friendly assets rather than large raw media.

36. RETRIEVAL AND GOVERNANCE
======================================================================

Every retrieval result should be traceable to:

- episode
- source file
- source unit
- permission state
- licensing state where relevant
- source hash/version

The search layer must filter according to consent and commercial-use
eligibility.

Conceptually:

    QUERY
      ↓
    SCOPE
      ↓
    PERMISSION FILTER
      ↓
    FTS5 / FUTURE SEMANTIC SEARCH
      ↓
    RANK
      ↓
    SOURCE TRACEABILITY
      ↓
    AI / PRODUCER

If a source is unavailable:

    return unavailable

If permissions are invalid:

    do not retrieve for restricted operation

If the index is stale:

    warn / rebuild

If retrieval is ambiguous:

    qualify uncertainty or request clarification

The system must not invent missing archive information.

40. REMOTE GUEST ACCEPTANCE TEST
======================================================================

The guest communications system passes only when:

    Host hears Guest                  PASS
    Host hears AI                    PASS
    Guest hears Host                 PASS
    Guest hears AI                   PASS
    AI hears Host                    PASS
    AI hears Guest                   PASS

And:

    Host does not hear self-return   PASS
    Guest does not hear self-return  PASS
    AI does not hear self-return     PASS
    Acoustic feedback absent         PASS
    AI MUTE immediate                PASS
    OBS captures programme           PASS
    REAPER captures Pavilion stems   PASS

These are architectural acceptance criteria, not optional enhancements.

42. ERROR HANDLING AND SAFE FAILURE
======================================================================

MISSING EPISODE CONTEXT

    Do not index.

INVALID CONSENT

    Do not retrieve for restricted operation.

INVALID LICENSING STATE

    Do not generate/publish using the restricted source for a commercial
    operation.

STALE INDEX

    Warn and rebuild.

MISSING SOURCE

    Return unavailable rather than inventing content.

AMBIGUOUS RETRIEVAL

    Ask or qualify uncertainty.

AI PROVIDER FAILURE

    AI MUTE / LISTEN state remains safe.

NETWORK FAILURE

    Preserve local archive and recording capability where possible.

UI FAILURE

    Physical production and emergency AI muting must remain possible.
