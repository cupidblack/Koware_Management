BUZZJUICE NETWORK CONNECTION MANAGEMENT SYNCHRONIZATION
VERSION 8.3.0 — IMPLEMENTATION GUIDE

ARCHITECTURE
============
BuddyBoss/WordPress is the only canonical authority. Streams and Socials are local projections and signed synchronization clients. External platforms never write BuddyBoss tables directly.

REST COMMAND ENDPOINT
POST /wp-json/bzj/v6/connection-management

Authentication:
HMAC-SHA256(timestamp + '.' + raw_json_body, platform_secret)
Headers:
X-BZJ-Timestamp
X-BZJ-Signature

Secrets:
BZJ_STREAMS_SYNC_SECRET and BZJ_SOCIALS_SYNC_SECRET are preferred. BUZZ_SSO_SECRET is the fallback.
Do NOT use WORDPRESS_API_USERNAME / WORDPRESS_API_PASSWORD for synchronization.

IMPORTANT SEMANTIC CORRECTION
=============================
QuickDate Add Friend and QuickDate Follow are NOT the same relationship.

Add Friend -> BuddyBoss connection request.
Follow -> BuddyBoss ordinary follow -> Streams ordinary follow.

This correction is deliberate. QuickDate's followers table is overloaded and cannot safely infer semantic intent from a row alone.

BUDDYBOSS MATRIX
================
Connection request -> QuickDate pending row active=0; no Streams follow.
Connection accept -> reciprocal QuickDate active=1 rows; no Streams friendship.
Connection reject/withdraw -> remove the connection-owned QuickDate pending row.
Connection remove -> remove connection-owned QuickDate friendship projection only; preserve independent follows.
Follow -> Streams active=1; QuickDate unchanged.
Unfollow -> Streams directional follow removed; QuickDate unchanged.
Block -> remove connection, pending requests and both follows; create directional block in Streams and Socials.
Unblock -> remove directional blocks only; never restore previous relationship automatically.

A. Replace Wo_IsFollowRequested() with:

function Wo_IsFollowRequested($following_id = 0, $follower_id = 0)
{
    global $sqlConnect, $wo;
    if ($wo['loggedin'] == false) return false;
    if (!isset($following_id) || empty($following_id) || !is_numeric($following_id) || $following_id < 1) return false;
    if (!isset($follower_id) || empty($follower_id) || !is_numeric($follower_id) || $follower_id < 1) {
        $follower_id = $wo['user']['user_id'];
    }
    if (!is_numeric($follower_id) || $follower_id < 1 || (int)$following_id === (int)$follower_id) return false;
    $following_id = (int)Wo_Secure($following_id);
    $follower_id  = (int)Wo_Secure($follower_id);

    $query = mysqli_query($sqlConnect, "SELECT `id` FROM " . T_FOLLOWERS . " WHERE `follower_id` = {$follower_id} AND `following_id` = {$following_id} AND `active` = '0' LIMIT 1");
    if (!$query) {
        error_log('[BZJ Streams] Wo_IsFollowRequested SELECT failed: ' . mysqli_error($sqlConnect));
        return false;
    }
    if (mysqli_num_rows($query) < 1) return false;

    $update = mysqli_query($sqlConnect, "UPDATE " . T_FOLLOWERS . " SET `active` = '1' WHERE `follower_id` = {$follower_id} AND `following_id` = {$following_id} AND `active` = '0'");
    if (!$update) {
        error_log('[BZJ Streams] Automatic follow acceptance failed: ' . mysqli_error($sqlConnect));
        return false;
    }

    $verify = mysqli_query($sqlConnect, "SELECT `id` FROM " . T_FOLLOWERS . " WHERE `follower_id` = {$follower_id} AND `following_id` = {$following_id} AND `active` = '1' LIMIT 1");
    if (!$verify || mysqli_num_rows($verify) < 1) {
        error_log('[BZJ Streams] Automatic follow acceptance verification failed: follower=' . $follower_id . ' following=' . $following_id);
        return false;
    }

    if (function_exists('cache')) {
        cache($following_id, 'users', 'delete');
        cache($follower_id, 'users', 'delete');
    }

    return false;
}

C. Replace Wo_RegisterBlock() with:

function Wo_RegisterBlock($user_id)
{
    global $wo, $sqlConnect;
    if ($wo['loggedin'] == false) return false;
    if (empty($user_id) || !is_numeric($user_id) || $user_id < 1) return false;
    $logged_user_id = (int)Wo_Secure($wo['user']['user_id']);
    $user_id = (int)Wo_Secure($user_id);
    if ($logged_user_id === $user_id) return false;

    $exists = mysqli_query($sqlConnect, "SELECT `id` FROM " . T_BLOCKS . " WHERE `blocker` = {$logged_user_id} AND `blocked` = {$user_id} LIMIT 1");
    if (!$exists) {
        error_log('[BZJ Streams] Block lookup failed: ' . mysqli_error($sqlConnect));
        return false;
    }
    if (mysqli_num_rows($exists) > 0) return true;

    $query = mysqli_query($sqlConnect, "INSERT INTO " . T_BLOCKS . " (`blocker`, `blocked`) VALUES ('{$logged_user_id}', '{$user_id}')");
    if (!$query) {
        error_log('[BZJ Streams] Block insert failed: ' . mysqli_error($sqlConnect));
        return false;
    }

    $verify = mysqli_query($sqlConnect, "SELECT `id` FROM " . T_BLOCKS . " WHERE `blocker` = {$logged_user_id} AND `blocked` = {$user_id} LIMIT 1");
    if (!$verify || mysqli_num_rows($verify) < 1) {
        error_log('[BZJ Streams] Block verification failed: blocker=' . $logged_user_id . ' blocked=' . $user_id);
        return false;
    }

    if (!defined('BZJ_CONNECTION_CLIENT_LOADED')) {
        $bzj_client = dirname(__DIR__, 3) . '/shared/bzj-connection-client.php';
        if (is_file($bzj_client)) require_once $bzj_client;
    }
    if (function_exists('bzj_connection_sync_command') && !bzj_connection_sync_command('streams', 'block', $logged_user_id, $user_id)) {
        error_log('[BZJ Streams] Block synchronization was queued/failed: blocker=' . $logged_user_id . ' blocked=' . $user_id);
    }
    return true;
}

STREAMS — content.phtml Wo_DeleteFollow()
==========================================
Replace the existing PHP Wo_DeleteFollow() in content.phtml with:

function Wo_DeleteFollow($following_id = 0, $follower_id = 0)
{
    global $wo, $sqlConnect;
    if ($wo['loggedin'] == false) return false;
    if (!isset($following_id) || empty($following_id) || !is_numeric($following_id) || $following_id < 1) return false;
    if (!isset($follower_id) || empty($follower_id) || !is_numeric($follower_id) || $follower_id < 1) return false;
    $following_id = (int)Wo_Secure($following_id);
    $follower_id = (int)Wo_Secure($follower_id);
    if ($following_id === $follower_id) return false;

    $query = mysqli_query($sqlConnect, "DELETE FROM " . T_FOLLOWERS . " WHERE `following_id` = {$following_id} AND `follower_id` = {$follower_id}");
    if (!$query) {
        error_log('[BZJ Streams] Follow delete failed: ' . mysqli_error($sqlConnect));
        return false;
    }
    $verify = mysqli_query($sqlConnect, "SELECT `id` FROM " . T_FOLLOWERS . " WHERE `following_id` = {$following_id} AND `follower_id` = {$follower_id} LIMIT 1");
    if ($verify && mysqli_num_rows($verify) > 0) {
        error_log('[BZJ Streams] Follow delete verification failed: follower=' . $follower_id . ' following=' . $following_id);
        return false;
    }
    if ($wo['config']['connectivitySystem'] == 1) {
        $query_two = mysqli_query($sqlConnect, "DELETE FROM " . T_FOLLOWERS . " WHERE `follower_id` = {$following_id} AND `following_id` = {$follower_id}");
        if (!$query_two) error_log('[BZJ Streams] Reciprocal follow delete failed: ' . mysqli_error($sqlConnect));
    }
    if (function_exists('Wo_DeleteSelectedActivity')) {
        Wo_DeleteSelectedActivity($follower_id, 'following', $following_id);
    }
    if (function_exists('cache')) {
        cache($following_id, 'users', 'delete');
        cache($follower_id, 'users', 'delete');
    }
    $bzj_client = dirname(__DIR__, 5) . '/shared/bzj-connection-client.php';
    if (is_file($bzj_client)) require_once $bzj_client;
    if (function_exists('bzj_connection_sync_command') && !bzj_connection_sync_command('streams', 'unfollow', $follower_id, $following_id)) {
        error_log('[BZJ Streams] Unfollow synchronization was queued/failed: follower=' . $follower_id . ' following=' . $following_id);
    }
    return true;
}

SOCIALS ORDINARY FOLLOW
=======================
The current QuickDate architecture must expose Follow as a separate semantic action from Add Friend. The resulting synchronization command is:

bzj_connection_sync_command('socials', 'follow', (int)self::ActiveUser()->id, $userid)

and ordinary unfollow is:

bzj_connection_sync_command('socials', 'unfollow', (int)self::ActiveUser()->id, $userid)

Do NOT route ordinary Follow through add_friend(). Do NOT convert ordinary Follow into a BuddyBoss connection request.

===========

B. BuddyBoss -> accept -> QuickDate reciprocal active=1; Streams none.
C. BuddyBoss -> reject/withdraw -> QuickDate pending row gone.
D. BuddyBoss -> follow -> Streams active=1; QuickDate unchanged.
E. BuddyBoss -> unfollow -> Streams row gone; QuickDate unchanged.

G. BuddyBoss -> unblock -> blocks removed; no follow/connection restored.
H. Streams follow -> BuddyBoss follow -> Streams remains active=1; QuickDate unchanged.
I. Streams unfollow -> BuddyBoss follow removed -> Streams row remains absent.

K. Socials Add Friend -> BuddyBoss connection request.
L. Socials Add Friend accept -> BuddyBoss connection accepted.
M. Socials Add Friend reject/withdraw -> BuddyBoss request removed.
N. Socials ordinary Follow -> BuddyBoss follow -> Streams follow; no connection request.
O. Socials ordinary Unfollow -> BuddyBoss and Streams follow removed; connection unaffected.
P. Socials block/unblock -> BuddyBoss moderation state and Streams projection.

CRITICAL OPERATIONAL RULE
=========================
A successful local external database action must not be rolled back merely because WordPress is temporarily unavailable. The signed command is the synchronization request; the WordPress event queue is the durable retry mechanism. The user-facing local action therefore succeeds while synchronization is retried and logged.

Do not deploy v8.2.0 unchanged. The v8.3.0 control-plane file corrects the major defects identified in the GitHub review: QuickDate Follow semantics, event retry execution, explicit semantic operations, per-platform HMAC secrets, canonical BuddyBoss mutation, directional blocking, and no automatic relationship restoration after unblock.
