CLASSIES CHRONICLES — STUDIO STRUCTURE SKELETAL BLUEPRINT
Version 21.0 — Persistent AI Desk / Episode-Archive Architecture
Status: Refactored, commissioning-ready
Date: 2026-08-14

======================================================================
0. PURPOSE
======================================================================

This blueprint defines the Classies Chronicles studio as a reusable
production system rather than a collection of one-off episode setups.

The architecture preserves the proven physical studio topology while
introducing one persistent AI Desk for the entire Classies Chronicles
franchise.

The AI Desk is NOT duplicated per episode.

The governing relationship is:

    ONE FRANCHISE
        |
        +-- ONE CC_AI_DESK
        |      |
        |      +-- persistent persona
        |      +-- relationship knowledge
        |      +-- intellectual style
        |      +-- prompts
        |      +-- operating modes
        |      +-- retrieval controls
        |      +-- rebuildable indexes
        |      +-- automation/control
        |
        +-- EPISODE ARCHIVE
               |
               +-- seasons
               +-- episodes
               +-- episode context
               +-- media
               +-- research
               +-- news
               +-- transcripts
               +-- consent/licensing
               +-- production/publishing assets

The AI Desk references the Episode Archive. It does not absorb the
episode archive into its persistent personality.

======================================================================
1. CORE ARCHITECTURAL PRINCIPLES
======================================================================

1. One persistent AI Desk
   CC_AI_DESK represents the continuing AI identity and control plane
   of Classies Chronicles.

2. Episodes are the source of truth
   Episode-specific facts, transcripts, news, research, participants,
   media and production records remain inside the episode archive.

3. Retrieval is temporary context
   When the AI is asked about an episode, the Desk retrieves relevant
   episode material and supplies it to the AI as working context.

4. Persona is persistent
   The AI's personality, intellectual style, voice, behaviours,
   boundaries and approved relationships live in CC_AI_DESK.

5. Persona evolution is governed
   Episode observations may propose changes, but an episode never
   silently rewrites the production persona.

6. News methodology is persistent; news results are episodic
   News prompts belong to CC_AI_DESK.
   Curated headlines belong to the episode's Episode Context.

7. Indexes are rebuildable
   Search indexes and embeddings are derived infrastructure.
   They must never be treated as the authoritative source.

8. Storage-provider independence
   The archive may reside on local storage, Google Drive, another cloud
   folder, Git, or a hybrid arrangement. The Desk uses a source/path
   contract rather than assuming one provider.

9. Consent/licensing is a retrieval gate
   Material that is not authorized for the intended use must not become
   silently available through retrieval.

10. Physical routing before virtual routing
    The existing proven studio audio path remains the baseline.

11. Producer authority
    AI MUTE is independent of AI operating mode. The producer must always
    be able to remove AI audio immediately.

12. Lean first
    Do not make vector databases, network audio, virtual mixers,
    autonomous agents or cloud infrastructure mandatory before they
    solve a demonstrated problem.

13. Prefer native/low-complexity Windows tooling
    Where automation can be performed reliably with PowerShell,
    Windows Task Scheduler, Git, SQLite/FTS5, existing applications or
    provider CLIs, prefer those over bespoke Python scripts.

======================================================================

CC_AI_DESK is the single persistent AI control plane for Classies
Chronicles.

It contains:

    PERSONA
    RELATIONSHIPS
    INTELLECTUAL STYLE
    VOICE
    BEHAVIOURS
    BOUNDARIES
    PROMPTS
    RETRIEVAL POLICY
    SOURCE POLICY
    NEWS-CURATION METHOD
    OPERATING-MODE RULES
    UI/CONTROL STATE
    REBUILDABLE CATALOGS/INDEXES

    raw episode video
    raw episode audio
    canonical episode transcripts
    episode-specific headlines
    episode-specific research
    episode-specific show notes
    episode-specific participant records

8. EPISODE CONTEXT — PURPOSE OF EACH FILE
======================================================================

01_METADATA.json
    Canonical machine-readable identity of the episode.

02_TRANSCRIPT.txt
    Canonical post-production transcript used for retrieval.

03_SHOW_NOTES.md
    Human-readable summary, segments, timestamps and key points.

04_HEADLINES.json
    Episode-specific current/local news selected for the episode.

05_RESEARCH\
    Episode-specific research and source references.

06_PARTICIPANTS.json
    Episode participants and production identifiers.
    Sensitive personal information should be minimized.

07_STORY_NOTES.md
    Narrative and editorial context.

08_CONSENT_MANIFEST.json
    Machine-readable permission state for relevant uses.

09_LICENSING_MANIFEST.json
    Rights/licensing state for content used in the episode.

10_AI_PROMPTS_USED.json
    Prompt identifiers and versions used during production.

11_AI_CONTEXT_SNAPSHOT.md
    Snapshot of the AI Desk state relevant to the episode:
      - persona version
      - prompt versions
      - retrieval policy version
      - selected source scope
      - active AI mode
    It is a record, not a replacement for the persistent Desk.

12_RETRIEVAL_REFERENCES.json
    Exact sources/chunks returned during important AI-assisted work.

13_POST_EPISODE_ANALYSIS.md
    Observations, errors, successes and improvement opportunities.

14_PERSONA_PROPOSAL.md
    Proposed persona/relationship changes derived from the episode.
    Approval is required before anything becomes persistent.

======================================================================
9. NEWS ARCHITECTURE
======================================================================

The news system has two layers.

PERSISTENT METHOD
    CC_AI_DESK\prompts\NEWS\

EPISODE RESULTS
    <episode>\01_EPISODE_CONTEXT\04_HEADLINES.json

The Desk's news curation prompt should accept:

    location
    time window
    episode topic
    relevance criteria
    category priorities
    desired number of headlines

The output should contain, at minimum:

    title
    summary
    category
    source
    source_url
    publish_date
    relevance
    suggested_reference
    fact_check_status

A headline can then be expanded using the persistent headline
expansion prompt when the producer wants greater emphasis.

News is time-sensitive. Therefore:

    headline discovery
        ->
    source verification
        ->
    producer selection
        ->
    episode storage
        ->
    retrieval during production

The AI Desk must not treat old headlines as current simply because
they remain indexed.

======================================================================
10. RETRIEVAL ARCHITECTURE
======================================================================

The retrieval system has four scopes:

    CURRENT_EPISODE
    CURRENT_SEASON
    ALL_APPROVED_EPISODES
    GLOBAL_CHRONICLES

Example:

    "What did we say about flooding in this episode?"
        -> CURRENT_EPISODE

    "Have we discussed flooding before?"
        -> ALL_APPROVED_EPISODES

    "What have we established about this character this season?"
        -> CURRENT_SEASON

    "What does the Chronicles archive say about this topic?"
        -> GLOBAL_CHRONICLES

Retrieval flow:

    USER / PRODUCER QUERY
          |
          v
    SCOPE SELECTION
          |
          v
    SOURCE AUTHORIZATION CHECK
          |
          v
    KEYWORD / FULL-TEXT SEARCH
          |
          v
    OPTIONAL SEMANTIC SEARCH
          |
          v
    RANK + DEDUPLICATE
          |
          v
    CONTEXT WINDOW
          |
          v
    AI REASONING
          |
          v
    RESPONSE + SOURCE REFERENCES

The first MVP should use full-text retrieval and metadata filtering.
Semantic embeddings are an enhancement, not a prerequisite.

For a transcript, indexing the entire transcript as one vector is
NOT sufficient. The transcript should be chunked into meaningful
segments, retaining:

    episode_id
    source_file
    segment_id
    start_time
    end_time
    text
    speaker
    authorization state

This permits precise retrieval and timestamp references.

11. CATALOG ARCHITECTURE
======================================================================

The AI Desk needs a catalog, not copies of episode data.

Recommended catalog entities:

EPISODE
    episode_id
    season_id
    title
    date
    archive_uri
    context_uri
    status

SOURCE
    source_id
    episode_id
    source_type
    relative_uri
    authorization_state
    license_state
    checksum
    modified_at

CHUNK
    chunk_id
    source_id
    episode_id
    speaker
    start_time
    end_time
    text
    retrieval_state

RELATIONSHIP
    relationship_id
    participant_id
    relationship_file
    status

The catalog points to the archive.

It does not become a second archive.

SQLite with FTS5 is the preferred first local catalog/retrieval layer
because it is lightweight, local, auditable and avoids making a vector
database mandatory on day one.

Semantic search can later be added beside FTS5.

======================================================================
13. PERSONA ARCHITECTURE
======================================================================

The persistent AI personality is divided into independent layers:

BASE
    Who the AI is.

INTELLECTUAL STYLE
    How it thinks, reasons, explains and challenges.

VOICE
    How it speaks.

BEHAVIOURS
    How it participates in a discussion.

BOUNDARIES
    What it must not do and what requires producer authority.

RELATIONSHIPS
    How it interacts differently with specific recurring hosts,
    guests or collaborators.

These files are independently versioned.

Example:

    CC_AI_PERSONA_BASE_v0.1.txt
    CC_AI_PERSONA_INTELLECTUAL_STYLE_v0.1.txt
    CC_AI_PERSONA_VOICE_v0.1.txt
    CC_AI_PERSONA_BEHAVIOURS_v0.1.txt
    CC_AI_PERSONA_BOUNDARIES_v0.1.txt

Relationship:

    relationships\
        CC_AI_PERSONA_RELATIONSHIP_<buzzjuice_username>.txt

The username is used only where a stable Buzzjuice identifier exists.
Do not place unnecessary private profile information in the relationship
file.

14. PERSONA EVOLUTION
======================================================================

Episode:

    transcript
       +
    observations
       +
    post-episode analysis
       |
       v
    PERSONA PROPOSAL
       |
       v
    PRODUCER REVIEW
       |
       +---- REJECT
       |
       +---- APPROVE
                 |
                 v
             VERSIONED CHANGE
                 |
                 v
             CHANGELOG

Rules:

    - no silent persona mutation
    - small incremental changes
    - every approved change has an episode/source reference
    - rejected proposals remain auditable but inactive
    - relationship changes are separate from base personality changes
    - the episode snapshot records the Desk version used

A single episode may propose several changes, but the producer decides
whether they represent a durable characteristic or merely an
episode-specific behaviour.

======================================================================
15. AI OPERATING MODES
======================================================================

LISTEN
    AI receives the permitted conversation/context but does not speak.

ASSIST
    AI prepares suggestions, facts, headlines or responses for the
    producer.

CO-HOST
    AI may speak when the production rules permit it.

AUTONOMOUS
    AI may participate with substantially greater conversational
    freedom, subject to the permanent safety, privacy, licensing and
    producer-mute controls.

AI MUTE
    Independent hard control that prevents AI audio from reaching the
    programme.

The architecture must never allow AUTONOMOUS to bypass AI MUTE.

======================================================================
16. AI PERSONALITY CONTROL
======================================================================

There are two separate concepts:

    PERSONALITY GOVERNANCE
        Long-term identity and behaviour.

    CONVERSATIONAL FREEDOM
        How much freedom the AI has during a specific recording.

A producer control may therefore be represented as:

    RESTRICTED
    GUIDED
    OPEN

while the operating mode remains:

    LISTEN / ASSIST / CO-HOST / AUTONOMOUS

This prevents "autonomous" from meaning "uncontrolled".

Permanent controls remain:

    privacy
    consent
    licensing
    safety
    factual uncertainty
    AI MUTE
    producer override

======================================================================
17. CONSENT AND LICENSING
======================================================================

Classies Chronicles may use member contributions only when the
appropriate consent is active.

The member contribution architecture may include:

    profile consent state
    contribution eligibility
    processing timestamp
    source reference
    deletion/revocation state

When consent is revoked:

    - new retrieval must exclude the material
    - active indexes must be rebuilt or invalidated as required
    - derived episode-generation material must be reviewed
    - the canonical source remains governed by the source system
    - the AI Desk must not continue presenting revoked material as
      authorized merely because it was previously indexed

Commercial licensing must be evaluated separately from participation
consent.

Consent to participate does not automatically mean commercial rights.

18. AI DESK DOES NOT BECOME AN EPISODE MEMORY
======================================================================

This distinction is mandatory.

BAD:

    Episode 01 -> copied into AI Desk
    Episode 02 -> copied into AI Desk
    Episode 03 -> copied into AI Desk

GOOD:

    Episode Archive
          |
          v
       Catalog
          |
          v
       Retrieval
          |
          v
      AI context
          |
          v
       Response

The AI Desk remembers durable persona/relationship knowledge.

The archive remembers episode facts.

======================================================================
19. PROVIDER-AGNOSTIC AI MODEL LAYER
======================================================================

The Desk should not be architecturally tied to one model vendor.

The model layer should support:

    conversation model
    embedding model (optional)
    transcription model
    text-to-speech model
    news/search provider

Each provider should be configured behind a simple provider contract.

The first commissioning target should be one reliable conversation
model and one reliable transcription method.

Multiple models can be tested later without changing the archive model.

======================================================================
20. PREFERRED AUTOMATION APPROACH
======================================================================

The previous concept of several Python scripts is replaced in the MVP
by a lower-complexity Windows automation approach.

Preferred order:

    1. Native application functions
    2. PowerShell
    3. Windows Task Scheduler
    4. Git hooks / GitHub Actions where appropriate
    5. SQLite/FTS5
    6. Provider CLI/API
    7. Python only when a required capability genuinely has no better
       practical alternative

Typical PowerShell automation:

    Initialize-CCStudio.ps1
    Validate-Episode.ps1
    Register-Episode.ps1
    Build-Catalog.ps1
    Refresh-Index.ps1
    Backup-AIDesk.ps1
    Prepare-Episode.ps1

These should be idempotent and log what they changed.

Python is not forbidden; it is simply not the default automation layer.

24. RECORDING SAFETY
======================================================================

The AI audio path must be independently controllable.

Recommended logical topology:

    AI MODEL
       |
       v
    AI TTS / AUDIO
       |
       v
    AI AUDIO SOURCE
       |
       +--> AI MUTE
       |
       v
    REAPER / OBS
       |
       v
    PROGRAMME

AI audio should have its own track/source wherever technically
possible.

Never rely on the AI model itself to mute its own audio.

======================================================================
29. FAILURE RECOVERY
======================================================================

If the AI Desk fails:

    podcast must still be recordable.

If retrieval fails:

    AI should state that it cannot retrieve the requested information.

If a model provider fails:

    producer should be able to continue recording without AI.

If AI audio fails:

    ENVY/REAPER/OBS must continue independently.

If an index becomes corrupt:

    delete/rebuild it from the archive.

If persona becomes undesirable:

    restore the last approved persona version.

If consent changes:

    invalidate affected retrieval material and rebuild.
