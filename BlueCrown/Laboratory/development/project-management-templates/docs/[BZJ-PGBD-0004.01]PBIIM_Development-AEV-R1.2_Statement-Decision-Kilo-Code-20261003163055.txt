## 4. WHERE R1.2 IS STILL NOT SUFFICIENT (my preserved dissent + one NEW regression)

I do not suppress dissent. The following remain genuine concerns:

### 4.1 NEW FINDING — R1.2 regressed the risk-scaling / small-project fast path (material, Question A)

**FINDING R-NEW-1 (material):** R1.1 contained explicit **§26 Risk-Scaled Governance (Light / Standard / High-Assurance profiles), §27 Small-Project Rule, §28 Large-Project Delegation**. **R1.2 dropped all three.** R1.2's §26–§28 are now *Stop/Resume* sections, not risk-scaling. Meanwhile R1.2 §35 imposes an **E2 (Automated Enforcement) floor on *every* control** ("No control may be described as ENFORCED … unless its evidence reaches at least E2"), with E4 for high-risk.

The consequence: R1.2 *improved evidence-scaling* (E2 vs E4 depth scales with risk) but **removed the ceremony-scaling** that R1.1 had. A one-day, low-risk feature now still runs the full AEA→AEV→AEC→AECC cycle with full task-packets, full gates, and must still produce E2 automated-enforcement evidence for *every* control — because there is no longer a Light Profile that reduces documentation/review depth/challenge scope for low-risk work. This **re-introduces the small-project over-governance** I specifically challenged in my AEC (Attack O / S8) and that R1.1 had begun to fix (Light Profile / MAT-5).

R1.2 is *honest* about this: LA-09 "Risk-scaled governance remains practical" is marked **AMENDED — VERIFY**, not RESOLVED (F6). So R1.2 does not overclaim LA-09 — but it has *regressed* from R1.1's explicit risk-scaling design without replacing it. This is a **material architectural (Question A) defect**, not an implementation one, because the *design* no longer provides the fast path. It must be re-introduced (or the E2 floor explicitly waived for a defined low-risk class) before the architecture can satisfy LA-09.

**This is why I am not giving a clean `AEV APPROVE`.** It is a bounded, fixable design gap (re-add the Light Profile / small-project fast path, or scope the E2 floor to "mandatory controls only"), which is why my verdict is `APPROVE WITH CONDITIONS` rather than `RETURN`.

## 10. NOTE ON CONVERGENCE (for the Lead Agent's synthesis)

Across R1.0 → R1.1 → R1.2 the control has *tightened consistently in one direction*: each revision has removed another way for a document to claim more maturity than it has. The architecture is now *honest about* both; it has not yet *fixed* both.
