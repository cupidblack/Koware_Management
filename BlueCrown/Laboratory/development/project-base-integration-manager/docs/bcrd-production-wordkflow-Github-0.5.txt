CHALLENGE AREAS (attack these specifically):

1. Idempotency
   - Can a duplicate payment intent be created?
   - Can the same order be created twice?
   - Can the same webhook trigger twice?
   - Can a retry create duplicate AffiliateWP commissions?
   - Can a retry activate subscriptions twice?

2. State Machine
   - Can the system reach an unrecoverable state?
   - Can two payments race and create inconsistency?
   - Can a webhook arrive out of order?
   - Can a webhook arrive before the initial request completes?

3. Currency Conversion
   - Can a ZAR amount be silently treated as GHS?
   - What happens if the exchange rate changes mid-conversion?
   - What happens if WOOCS is unavailable?
   - What happens if rounding causes amount discrepancy?

4. Authorization & Security
   - Can a browser manipulate the payment amount?
   - Can a webhook be replayed?
   - Can a webhook from another domain be accepted?
   - Can session/authentication be bypassed?

5. Integration Failure
   - What if AffiliateWP is down?
   - What if Jewel Affiliate rejects the request?
   - What if subscription activation fails?
   - What if WooCommerce order creation fails?
   - What if the thank-you page redirect fails?

6. Deployment & Rollback
   - Can the new bridge coexist with the old one?
   - What if we need to rollback mid-deployment?
   - What about in-flight transactions during rollback?
   - How do we verify the cutover worked?

7. Production Scenarios
   - Browser closes mid-payment?
   - Database connection drops?
   - Webhook timeout?
   - Multiple concurrent orders from same user?
   - Payment for same product twice (subscription + one-time)?

OUTPUT FORMAT:
For each finding:
- What could go wrong
- How it could happen
- What the impact is
- Is it currently mitigated?
- If not, what would mitigate it?

Severity levels:
- CRITICAL: Can lose money or duplicate charges
- HIGH: Can corrupt state or break business logic
- MEDIUM: Can degrade service or confuse users
- LOW: Can improve robustness but not breaking

## Summary of Key Improvements in This Template:

1. **Numeric Alignment to PM Phases**: 
   - `0xxx` = Initiating
   - `1xxx` = Planning  
   - `2xxx` = Architecture
   - `3xxx` = Specification
   - `4xxx` = Execution
   - `7xxx` = Monitoring
   - `8xxx` = Validation
   - `9xxx` = Closing

2. **Integrated Agent Prompts**: Each section contains the exact prompt to share with the relevant agent (ChatGPT, Codex, Jules, Claude), eliminating context loss from copy-pasting.

3. **Clear Phase Gates**: Each phase ends with a structured gate requiring approval before proceeding to the next phase. This prevents accumulating issues.

4. **FACT/ASSUMPTION/UNKNOWN Distinction**: Built into the Architecture Discovery phase to prevent AI from filling gaps with guesses.

5. **Embedded Section Notes & Placeholders**: Notes appear where they'll be encountered, not appended to the end.

6. **Specification → Implementation Binding**: The Implementation Specification (BZJ-PGB-3000.0) becomes the authoritative contract that implementation agents follow, reducing drift.

7. **Scaled Phase Implementation**: Instead of one giant task, implementation is broken into 5 numbered phases (Database, Currency, WooCommerce, Subscriptions/Affiliates, Testing), each with its own prompt, review, and gate.

8. **Independent Review Separation**: Jules performs technical correctness review; Claude performs adversarial/security review—different lenses on the same code.

9. **Deployment Procedure**: Explicit step-by-step deployment and rollback procedures prevent surprises in production.

This template can now be used as the binding governance structure for your Buzzjuice Payment Gateway Bridge project, ensuring multi-agent work stays aligned, phases don't blur, and decisions are documented at each gate.
