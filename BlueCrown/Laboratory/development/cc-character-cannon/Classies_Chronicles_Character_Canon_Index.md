This import-ready package contains **62 individually authored Markdown canon proposals**, one per aliased role in the supplied organizational chart. 
**No images were generated**. Proposed future collage names are *descriptive placeholders inside Markdown only*.

## Canon governance and non-biography requirement

The organizational chart identifies role aliases and check days; it does **not** verify birthdays, family details, ethnicity, credentials, former employers or permissions to portray real people. 
Every newly invented biographical attribute is labeled fictional. These drafts must be reviewed and cleared before they become approved or publicly usable canon.
The existing `CUPID_BLACK/CUPID_BLACK_CHARACTER_CANON.md` is **not overwritten**. `ENKA_YAMOAH` is a proposed organizational profile whose identity/ability boundaries defer to that existing Cupid Black file.

### Filenames

The folder and filename strictly follow the requested structure: `{{CHARACTER_SLUG}}/{{CHARACTER_SLUG}}_character_cannon.md`. The `cannon` filename spelling is retained **exactly as requested**, although the story-governance term inside documents is `canon`.
Honorifics are omitted from slugs, but original chart aliases appear verbatim inside files. Parenthetical chart notes are not treated as real education/work history. 
The five `NSS Personnel-*` aliases retain distinct files; their tentative stage names are purely fictional and not used as folder IDs.

## Recommended editorial acceptance checklist

1. Confirm each alias/role and its chapter working-day checks against the latest chart; note that check days are not episode-day numbers.
2. Review real-person consent and select whether each role remains a pseudonymous, composite or fully original fictional character.
3. Resolve identity-dependent private attributes by replacing, withholding or approving the invented candidate values.
4. Review visual design prose; only then commission and file original reference collages. No reference art is supplied in this version.
5. Insert only verified and eligible Daily Diaries links; do not publish or process restricted diary content without clearance.
6. Verify episode/debut/mission-state fields against approved locked narrative; do not convert prompts into already-occurred events.
7. Review Enka identity and capability gates against the existing Cupid Black canon before changing anything.
8. Commit files to `CC_AI_DESK/04_CANON/CHARACTERS/` only after approval. The archive does not write to GitHub.
