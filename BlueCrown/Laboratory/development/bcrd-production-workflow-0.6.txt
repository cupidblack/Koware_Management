OVERVIEW & OPERATING PRINCIPLES
--------------------------------------------------------------------------------
This workflow template establishes an evidence-based, highly durable AI engineering pipeline structured strictly around the 49 Project Management processes. Each PM stage uses an immutable sequential numeric prefix ranging from 0004.1 ("Develop Project Charter") through 9004.7 ("Close Project or Phase"). Pre-charter Project Base Integration Initialization activities use the explicit Knowledge Area 00 namespace (0000.01 through 0000.09) to preserve the canonical PM process anchors.

IDENTIFIER NAMESPACE ARCHITECTURE:
- Canonical PM Process Anchors: SSSS.S (e.g., 0004.1, 1004.2, 9004.7) — Immutable coordinates.
- Workflow Subsections: BZJ-[PROJECT]-WF-SSSS.SS (e.g., BZJ-[PROJECT]-WF-0000.01, BZJ-[PROJECT]-WF-0005.00)
- Analysis Artifacts: BZJ-[PROJECT]-AEA-SSSS.SS
- Verification Artifacts: BZJ-[PROJECT]-AEV-SSSS.SS
- Challenge Artifacts: BZJ-[PROJECT]-AEC-SSSS.SS
- Baseline Artifacts: BZJ-[PROJECT]-BL-SSSS.SS

AI AGENT ROLE ROSTER:
1. ChatGPT / Codex (Architecture & Strategy Lead):
   - Responsible for project initiation, chartering, architectural design, specifications, ADRs, task packet generation, and overall technical strategy synthesis.
2. Kilo Code (Engineering Feasibility Analyst):
   - Responsible for codebase feasibility analysis, developer workflow efficiency, repository structural checks, and failure recovery analysis.
3. Google Jules (Independent Workflow & Reliability Review Agent):
   - Responsible for independent workflow verification, test suite creation, CI/CD pipeline checks, edge-case analysis, and non-regression auditing.
4. GitHub Copilot (Primary Implementation Agent):
   - Responsible for primary code implementation, feature development on task branches, PR creation, and applying code fixes.

<<START ANALYSIS AND DEVELOPMENT OF THE 'Project Base Integration Initialization'>>

1. Architectural Analysis Generation (AEA):
   - Initial 'Project Base Integration Initialization' is submitted to ChatGPT / Codex (Lead Architecture Agent) to generate an 'Architectural Engineering Analysis' document.

2. Multi-Agent Review Distribution:
   - The generated AEA is distributed across dedicated agent evidence branches (`evidence/bzj-pgbd-0000.01-kilo`, `evidence/bzj-pgbd-0000.01-jules`, `evidence/bzj-pgbd-0000.01-copilot`).

3. Multi-Agent Analysis Synthesis (AEV):
   - Review findings from all collaborating agents are aggregated by ChatGPT / Codex into a controlled 'Architectural Engineering Verification' baseline candidate document (`BZJ-PGBD-AEV-0000.01`).

4. Adversarial Architectural Challenge (AEC):
   - Independent agents (Jules / Kilo) execute an adversarial challenge attacking transaction boundaries, cPanel cURL loopback restrictions, and database isolation.

5. Challenge Closure Protocol (AECC):
   - Every challenge objection is explicitly dispositioned as FIXED, ACCEPTED AS KNOWN LIMITATION, REJECTED WITH REASON, or ESCALATED TO HUMAN.

6. Bounded Convergence & Human Gate:
   - Review iterations are capped at 3 cycles. Unresolved CRITICAL findings trigger mandatory escalation to Human Authority. Upon approval, baseline candidate is tagged in Git (`pbi-baseline/v1.0.0`).
