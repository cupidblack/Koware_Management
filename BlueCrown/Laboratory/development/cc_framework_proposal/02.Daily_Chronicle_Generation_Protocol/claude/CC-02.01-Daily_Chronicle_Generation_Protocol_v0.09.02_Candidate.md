## 1. Necessity, authority and run order

### 1.1 Why this document still exists

The master (`CC-01.01` §5) deliberately delegates the **ordered daily operator runbook** to this file and states that a daily run loads: the effective master, this protocol, the ledger/record contract (`CC-02.02`) and the Context Merge Engine (`CC-05.01`). Without this file each provider would invent its own sequence, evidence log, stop rules and handover. It is retained, updated to the v0.09.01 section numbering, and stripped of any policy that the master already owns.

### 1.2 Invocation rule

*MUST* and *NEVER* here bind only when this edition has been expressly selected for a controlled run. This file is a functional specification, not proof that a repository, calendar connector, endpoint, renderer or vault is reachable. Field names below are **schema and instructions**, never blank fictional values to fill with guesses.

### 1.3 Run order at a glance

1. Classify the mode and pin authority (§4).
2. Discover, read and snapshot the actual sources (§5).
3. Resolve date, episode, identifiers and role-check day (§6).
4. Lock the three clocks and every independent location (§7).
5. Rebuild the accepted pre-state without absorbing today's ideas (§8).
6. Select and verify study, verse, safety and headline material (§9).
7. Plan the story and run the six cumulative transformations (§10).
8. Draft Output A (§11).
9. Draft separate Output B1–B8, including the self-contained B6 (§12).
10. Run exact Q01–Q16 with evidence (§13).
11. Report disposition and the five independent status axes; perform no unauthorized write (§14).
12. Stop and wait. Comic and media require separate prompts (`CC-01.01` §40).

### 1.4 What this runbook never does

It never decides that a candidate master is effective; never treats retrieval as permission to publish, portray, quote, rewrite accepted canon or write to storage; never generates a restricted answer key; never produces six public chronicles from the six internal passes; never compiles an episode on Chronicle #10; and never infers a calendar, identifier, source response, human approval or repository commit.

## 6. Phase 2 — resolve date, episode, identifiers and role-check day

Follow `CC-01.01` §§6–10 and the actual approved calendar, never an approximate season window. Nominal chapter windows (mid-January to mid-March; mid-March to mid-May; June–July; mid-August to mid-October; mid-October to mid-December) are planning windows, not adopted calendar rows.

### 6.1 Deterministic date-to-episode algorithm

1. Resolve the target **production civil date** in the approved IANA timezone. Record separately the retrieval timestamp (UTC) and any historical target-date basis. Convert offset-aware timestamps to the production timezone **before** date arithmetic.
2. Resolve the effective chapter ID, local start, local end and whether the supplied end is inclusive or exclusive. If no convention is approved, flag the ambiguity before assigning a definitive identity.
3. `anchor_date` = the first **Monday on or after** the local chapter start date, unless an approved exception supplies another anchor.
4. `offset` = target local date − `anchor_date` in whole civil days (never elapsed hours; DST and midnight errors matter). Reject negative offsets and dates outside the chapter.
5. `block = floor(offset / 14)`; `block_day = offset mod 14`. An ordinary episode index is `block + 1` only for `block` in 0–3 **and** an approved fully fitting block. Check the **whole** window: first Monday through the second Friday (`anchor + 14×block + 11`) must lie inside the chapter end.
6. Accept only `block_day` in `{0,1,2,3,4,7,8,9,10,11}`. Days 5, 6, 12 and 13 return `WEEKEND_NOT_SCHEDULED` with no ordinary chronicle ordinal.
7. `chronicle_slot` = `block_day + 1` for 0–4 and `block_day − 1` for 7–11. `chapter_workday = 10 × block + chronicle_slot` (1–40).
8. Cross-check weekday, approved episode schedule, role-day records, any accepted prior installment and any known archive/legacy ID before writing. A mismatch yields `BLOCKED` or a clearly documented provisional schedule — never an invented accepted identity.

### 6.2 Arithmetic fixtures (tests only, never claims about a live chapter)

| `offset` | `block` / `block_day` | Result |
| ---: | --- | --- |
| 0 | 0 / 0 | Episode 1 · Chronicle #1 · chapter workday 1 |
| 4 | 0 / 4 | Episode 1 · #5 · workday 5 |
| 5, 6 | 0 / 5, 6 | Weekend — no ordinary chronicle |
| 7 | 0 / 7 | Episode 1 · #6 · workday 6 |
| 11 | 0 / 11 | Episode 1 · #10 · workday 10 |
| 12, 13 | 0 / 12, 13 | Weekend |
| 14 | 1 / 0 | Episode 2 · #1 · workday 11 |
| 18 | 1 / 4 | Episode 2 · #5 · workday 15 |
| 25 | 1 / 11 | Episode 2 · #10 · workday 20 |
| 28 | 2 / 0 | Episode 3 · #1 · workday 21 |
| 39 | 2 / 11 | Episode 3 · #10 · workday 30 |
| 42 | 3 / 0 | Episode 4 · #1 · workday 31 |
| 53 | 3 / 11 | Episode 4 · #10 · workday 40 |
| 56 or more | block ≥ 4 | Rejected as an ordinary slot; needs an approved exception |

A phase that starts on a Wednesday does not make Wednesday Chronicle #1; the earlier days are unallocated partial-week days unless the approved calendar says otherwise. A leftover partial block never becomes a complete episode without an approved exception. A holiday schedule, weekend special, day reassignment or archival compression needs an actual exception record. A Phase/Probe endpoint may help validate proposed chapter boundaries but is not authority to change an approved schedule, and its `phase_index` is telemetry, not an identifier.

### 6.3 Identifiers and archive naming

Resolve season, chapter, episode and chronicle against the **actual accepted IDs and legacy paths**. Never assume `S00_T05` = `CH05`. Known patterns include `CC_ARCHIVES/`, `CC_EPISODE_ARCHIVES/`, `S00_T05`, `S00_T05_E01`, `S00_CH05_E02`, `S00CH01E01DAY01` and numbered Part records; keep original IDs and verified paths and use the bidirectional crosswalk rules in `CC-02.02` §4. For a target day that already has an accepted A, default to a `DAILY_REVISION` review or decline a redundant creation; never silently overwrite.

### 6.4 Internal identity versus public title

Internally the day is `Chronicle #N` (1–10) within its episode. The public audience title is **`Part N: Creative Title`**, where N is the accepted episode installment number; no date or code prefix sits beside it (the date may appear naturally inside the story). A documented historical compression (for example three final dated entries merged into one audience-facing Part 8) is an explicit exception that preserves the underlying dated coverage and source-to-part mapping; it is not a universal licence to merge days.

### 6.5 Role-check day (1–40)

Retrieve the actual latest `Organizational_Chart_Structure-Aliased_Checks.txt` and parse **chapter-wide 1–40** `Day`/`Days` values. Expand compound ranges such as `Days 4–5, 24–25` into `{4,5,24,25}`, preserve raw role/alias text and flag ambiguity. The check index is the chapter workday — never the story slot 1–10 and never the calendar day of the month. If the chart uses 20-day recurrence semantics, require the actual chart or an owner decision before applying any modulo. Select normally one or two **spotlight roles** (the highest eligible organizational level leads), up to four for a richer ensemble, a fifth only if justified and authorized. Each spotlight role needs a real responsibility, a professional skill or dilemma, a cross-functional relationship and a consequence. Enka and the field team stay subordinate to the day's legitimate focus. A role title is not proof of a person's identity.

**Exit gate:** a verified slot, chapter workday and role index, or an explicit `CALENDAR_EXCEPTION` / `BLOCKED` naming the missing authority. Never label an unverified episode number in A.

## 9. Phase 5 — study, verse, safety, headline and organization evidence

### 9.1 Eternal Dreamfall study (proposed cycle; owner-approved allocation outranks it)

The proposed cycle began in 2023 and lasts seven calendar years: two preparation/research years, then five reading years. The reading list has **250 named week entries**; five years contain roughly 260 Sunday–Saturday weeks. Never invent ten missing readings or equate a week label with a daily passage.

For production year `Y`: `cycle_start = 2023 + 7 × floor((Y − 2023) / 7)`. `first_full_reading_sunday` = the first Sunday on or after 1 January of `cycle_start + 2` (for the 2023 cycle this is **Sunday 5 January 2025**). A target date before that Sunday in a preparation year gets `STUDY_PREPARATION_YEAR` (research and review only). Otherwise `reading_week = floor((target_local_date − first_full_reading_sunday) / 7) + 1`, computed in the study calendar's authorized timezone. First verify whether the owner has an approved week-to-entry and day-to-passage allocation; use that. Without one, and only if a provisional run is expressly authorized, apply the labeled proposal `PROVISIONAL_ENTRY_EQUALS_WEEK` for weeks 1–250 and reserve weeks 251–260 for review, research and consolidation.

A weekly entry does not define seven daily assignments: derive a transparent internal `GENERATED_DAILY_STUDY_PLAN` across Sunday–Saturday, mindful of literary units and passage lengths, and record the original source line, editorial status, allocation provenance, selected daily focus and the whole week's assigned corpus.

**Dated regression fixture (not an always-current answer):** 19 November 2026 yields reading **Week 98** (the week of 15–21 November 2026), and the cited source entry is the Septuagint continuation **Judges; Ruth**; the Greek `1 Kingdoms`/1 Samuel entry is Week 99. For any real run, re-inspect the source line and the effective allocation. Classify texts by tradition and scholarly status (canonical in a tradition, deuterocanonical, pseudepigraphal, ancient literature, inscription, fragment, manuscript attestation, known-lost work, historical reconstruction, modern interpretation); never pretend lost verses were recovered; summarize long works rather than reproducing licensed translations.

### 9.4 Three-era research and the headline engine

Build separate historical, current and probe strands (`CC-01.01` §18):

1. **Historical (H):** verified reference date, independently established historical location, contemporaneous events and attributed interpretations; default window the seven days ending on the H civil date; note whether a claim comes from a contemporary paper or a later retrospective.
2. **Current (P):** the authorized Koware present city and region and the wider Ghanaian, West African and global context **as of the requested story day**; default window the seven days through P. A retrospective run must not mention news published afterward as if staff knew it.
3. **Probe (F):** the mission's accepted location and time. A verified past era may use historically dated sources; a future or alternate era is speculative fiction even when grounded in research trends. Never retrieve or imply future newspapers, politics, official weather, exchange rates or footage.

Internal notes per strand: Location → Collective Situation Summary → Local/Regional Headlines → Broader/Global Headlines → Story Consequences. Optional search coverage (up to ten headlines per location, twenty merged, five to ten awareness items) is guidance, **not** a compulsory spoken quota. A selected item earns its place by pressuring a role, causing a choice, launching an investigation, changing a route, raising a safety concern or setting up a payoff. Weather is typed `HISTORICAL_OBSERVATION`, `CURRENT_OBSERVATION`, `FORECAST`, `CLIMATOLOGICAL_CONTEXT`, `STORYWORLD_SIMULATION` or `UNVERIFIED` with issue time and place where known.

### 10.3 The eight-operation loop (apply at every stage boundary)

1. **READ** — inspect the actual new source, its date, permission and factual/fictional class.
2. **DECOMPOSE** — extract characters, facts, events, conflicts, motifs, tension, choices, chronology and risks.
3. **LOCK** — classify narrative anchors as `HARD`, `SOFT` or `OPTIONAL`; source facts stay locked to their evidence.
4. **CONNECT** — choose a causal, thematic, relational, environmental, historical or visual bridge into existing events.
5. **TRANSFORM** — rewrite the affected scenes (and transitions) so the new meaning lives inside the plot.
6. **PRESERVE** — test that the hard anchors, relationships, relative event order, source intentions and earlier payoffs survive.
7. **VALIDATE** — check provenance, canon, clocks, physical position, realism, rights, scope and coherence; reject unsupported material.
8. **REGISTER** — document source IDs, pre/post scene, retained anchors, new motif, bridge type, changed choice or consequence, QA, exclusions and editorial status.

The opening hard anchors normally number three to seven. A source that cannot materially influence the story is `REJECTED_FOR_STORY` and stays in the B2 register; never force every source into public prose. Do not delete a central workplace decision or an earned emotional change merely because a new theme is more convenient. Where the effective Context Merge Engine uses different verb names, the master's names govern the daily suite and the difference is logged. Transformation record fields per stage: `version`, `source_ids`, `premerge_scene`, `hard_anchors_retained`, `new_motif`, `bridge_type`, `resulting_scene`, `choice_or_consequence_change`, `rights_check`, `fact_check`, `continuity_check`, `excluded_material_reason`.

## 11. Phase 7 — draft Output A

Produce **one** finished, original audience manuscript for the one supported day (`CC-01.01` §34).

1. **Identification:** accepted or clearly provisional chapter/episode metadata with the public title `Part N: [earned narrative title]`.
2. **Opening:** a concrete action, decision, discovery, tension or stake.
3. **Progression:** causally connected scenes that put the role spotlight, field mission, characters and the selected study, verse, safety and news signals inside one lived story, with interiority, credible dialogue, humor, local sensory detail and consequences — not a report formatted as a story.
4. **Earned turn:** at least one consequential choice or revelation, respecting the slot's dramatic role without a mechanical cliffhanger every day.
5. **Ending:** resolve an appropriate local thread, carry forward what is genuinely unresolved.
6. **Final audience challenge:** after all scenes (and any approved credit, disclosure or preview), place **only Challenge A** as the very last audience-facing item. The challenge must be a solvable, story-anchored riddle, observation, deduction, sequence, character decision or verified-history link, answerable from the public text and any genuinely public source, never needing hidden files. Multiple choice A–E is one acceptable format, not a requirement. Do not imply a prize or guaranteed score.

A must **not** contain: internal source registers, B1–B8, a manifest, answer keys, answer rationale, near-answer hints, raw telemetry, repository revisions, V1–V6 labels, a notice that B exists, or an answer-bearing filename or alt text. Separate authorial fact (what happened in the narrated world) from in-character claims. Never depict an actual person, organization, health service or government as admitting or doing something without evidence; never publish an invented historical article as fact. Religion informs particular characters' perspectives without asserting that every employee shares it. Keep fictional narration immersive and free of reality labels. A reasonable default length is about three to five minutes of reading, advisory only and overridden by the effective instruction; do not pad to fill a fixed montage or illustration count. Reply in the language the owner writes in unless asked otherwise.

If a source-safe draft can be written but competitive release lacks secure answer custody, mark the **draft** as permitted and the **competitive release** as blocked until owner policy is satisfied. Do not create restricted C in an ordinary run.
