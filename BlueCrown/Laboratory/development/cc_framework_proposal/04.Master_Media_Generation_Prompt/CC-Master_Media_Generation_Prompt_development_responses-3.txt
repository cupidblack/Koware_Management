# PART I — COMMISSION AND AUTHORITY

## 1. Primary media modes

Select exactly one primary mode:

| Mode | Permitted output |
|---|---|
| `MEDIA_REVIEW_ONLY` | Refactor review, decision register and QA |
| `MEDIA_PLAN` | Story, format, shot, rights and feasibility plan |
| `MEDIA_SCRIPT` | Narration, dialogue and exact shot timing |

| `MEDIA_PLATFORM_PROMPTS` | Paste-ready provider-specific prompt pack |
| `MEDIA_GENERATE_ASSETS` | Only explicitly authorized actual renders |
| `MEDIA_EDIT_ASSEMBLE` | Only authorized assembly of actual files |
| `MEDIA_REVISE` | Correct named assets and dependencies |
| `MEDIA_QA_RELEASE_REVIEW` | Inspect real assets, metadata and approval evidence |

A combination request is represented as separately auditable commissioned stages.

## 2. Authority hierarchy

Apply in descending effective authority:

1. Applicable law, safety, consent and license.
2. Human owner/editor authorization.
3. Approved canon and accepted continuity.
4. Approved Studio and communications architecture.
5. Effective approved production master.
6. Effective daily, ledger, comic and media specialist editions.
7. Provider documentation and account state as observed at run time.

A higher physical filename or later document number does not itself establish authority.

## 3. Independent lifecycle axes

Track every result independently:

- **Commission:** `REQUESTED`, `CLASSIFIED`, `AUTHORIZED`, `NOT_AUTHORIZED`
- **Process:** `NOT_STARTED`, `PLANNED`, `IN_PROGRESS`, `BLOCKED`, `COMPLETE`
- **Editorial:** `UNREVIEWED`, `CHANGES_REQUESTED`, `ACCEPTED`, `LOCKED`, `REJECTED`
- **Persistence:** `UNSAVED`, `DRAFTED_NOT_COMMITTED`, `COMMIT_ATTEMPTED`, `COMMITTED_VERIFIED`, `WRITE_FAILED`
- **Release:** `NOT_ELIGIBLE`, `RELEASE_ELIGIBLE`, `PUBLICATION_AUTHORIZED`, `PUBLISHED_VERIFIED`
- **Derivative:** `NOT_COMMISSIONED`, `PLANNED`, `STORYBOARDED`, `PROMPTS_CREATED`, `ASSETS_RENDERED_VERIFIED`, `ASSEMBLED_VERIFIED`, `QA_PASSED`, `APPROVED`, `STALE_SOURCE`

Never replace these states with a single word such as `DONE`.

## 4. Fixed output contract

Unless the owner explicitly commissions another delivery:

| Property | Contract |
|---|---|
| Master format | 16:9 |
| Raster | 1920×1080 |
| Pixel shape | Square |
| Frame rate | 24 or 30 fps, explicitly selected |
| Scan | Progressive |
| Colour | SDR Rec.709 or a specifically approved alternative |
| Primary container | MP4/H.264 unless another delivery contract exists |
| Audio | 48 kHz stereo target, subject to actual equipment and final mix |
| Portrait derivative | Separate 9:16 asset only with explicit authorization |

Do not stretch, squeeze or convert a 9:16 comic page directly into a 16:9 frame.

# PART II — SOURCE AND CONTINUITY LOCK

## 5. Input lock

Before source-specific media work, capture:

- `episode_id`
- `day_id`
- `chronicle_slot`
- `chapter_workday`
- `production_date`
- `approved Output A revision`
- measured A digest when available
- Public Challenge A revision
- exact CC-03 comic count and export revision
- character and mission canon editions
- source permission and consent scope
- effective master, ledger, comic and daily editions
- exact runtime and frame-rate commission

Represent unavailable values as `UNKNOWN`, `UNAVAILABLE`, `NOT_RETRIEVED`, `NOT_AUTHORIZED`, `CONFLICTING` or `EDITORIAL_DECISION_REQUIRED`.

## 6. Provenance firewall

Separate four audiences:

| Audience | Permitted content |
|---|---|
| PUBLIC | Approved manuscript A, rights-cleared derivatives and exact Challenge A |
| INTERNAL | B1–B8, prompts, tests, production logs and permitted continuity |
| RESTRICTED | Challenge answer/key, private diary, real-person sensitive evidence and credentials |
| PUBLIC_DELIVERY | Independently authorized export only |

Never place restricted material in a provider prompt, filename, caption, metadata, alt text or public render.

## 7. Three clocks and physical position

Maintain three independent clocks:

- **P — Production/present:** authorized Koware-world or production date.
- **H — Historical/reference:** dated historical evidence or represented memory.
- **F — Field/probe:** accepted Edubeam destination and mission state.

For every character and major object record:

- Fictional time
- Clock modality
- Physical location
- Knowledge state
- Last accepted movement event
- Source for location claim
- Whether the scene is represented research, dream, memory or diegetic action

A probe destination or archive article must never be depicted as physical present-world displacement without an accepted event.

## 8. Story beat inventory

From the eligible Output A derive:

- Causal sequence
- Character/role action
- Knowledge change
- Emotional change
- Consequence
- Source beat ID
- Page/panel dependency
- Exact public challenge dependency
- Historical/current/speculative classification
- Rights status

A scene must change knowledge, action, emotion or consequence to justify its own duration.

## 9. Units and identifiers

Do not conflate:

- **Beat:** change in knowledge, action, emotion or consequence
- **Scene:** coherent dramatic unit
- **Act:** editorial time allocation
- **Shot:** one production composition and operation
- **Clip:** one actual provider/editor output
- **Comic page:** a complete 9:16 sequential-art page
- **Comic panel:** a rectangular visual unit inside a page
- **Sheet:** a four-page 2×2 grouping or a genuinely approved alternate assembly

Every output must preserve its upstream beat IDs and generated asset IDs.

# PART III — COMIC, CANON AND REFERENCE IMAGING

## 10. Character appearance lock

For each required character obtain:

- Actual approved canon folder/file
- Character appearance card
- Verified identity/aliases
- Era
- Age range
- Face, hair, eye, skin and posture anchors
- Clothing and insignia
- Injuries or physical aids
- Props
- Likeness/portrayal permissions
- Canon revision and measured hash when available
- Appearance state ID

If approved character media cannot be found or rights cannot be verified, block identity-critical generation. Do not claim that a directory URL proves rights.

## 11. Reference hierarchy

Use, in descending authority:

1. Approved character appearance card.
2. Approved canon artwork.
3. Approved comic page/panel crop.
4. Approved production still or frame.
5. Approved location/technology reference.
6. Non-authoritative style examples.
7. No reference for identity-critical shots.

Never infer facial identity solely from the name of a canon folder.

## 12. Comic acquisition and crop protocol

For actual comic assets:

1. Verify commissioning and allowed count.
2. Confirm exact comic source revision.
3. Record URI, retrieval time and measured SHA-256.
4. Verify 9:16 geometry or declared sheet geometry.
5. Locate exact individual page or panel.
6. Identify all story-critical visual content.
7. Crop without stretching or flipping.
8. Retain source and crop coordinates.
9. Name the crop with episode/page/panel/scene IDs.
10. Validate minimum native resolution and focal subject size.

Recommended source image roles:

- **Reference A:** exact source composition.
- **Reference B:** character identity.
- **Reference C:** environment/technology continuity.
- **Reference D:** pose/action continuity.

Reference D must only be used where the provider can preserve the pose without inventing action.

## 13. Native collage restriction

A 4×4 collage does not prove page quality.

- 4×4 collage minimum for sixteen native 1080×1920 page crops: 4320×7680.
- A 2048×2048 collage contains approximately 512×512 cells and cannot preserve native 1080×1920 geometry.
- A smaller source may support thumbnails or a low-resolution preview only.
- Reject silent upscaling or claims of native resolution.

Verify the measured dimensions before any crop claim.

## 14. Widescreen adaptation modes

Use only a documented mode:

| Mode | Contract |
|---|---|
| `F1_FIT_STAGE` | Show the complete portrait crop on a designed 16:9 stage; no stretch |
| `F2_REFRAME_SAFE` | Extract an authored horizontal region with no story-critical omission |
| `F3_SPLIT_VIEW` | Deliberately compose two readable source regions, with approval |
| `F4_EDITED_STILL` | Crop-to-framing plus only approved pan, push or parallax |
| `F5_GRAPHIC_MONTAGE` | Join source crops as a deliberate editorial graphic sequence |

F1 may use an approved plain, blurred, textured or animated stage. The side stage must not imply invented location or action.

## 15. Crop safety record

Each crop record must contain:

- Source path/URL and revision
- Source dimensions
- Source hash
- Page and panel ID
- Pixel rectangle
- Intended aspect conversion
- Selected mode
- Story-critical items retained
- Rejected alternate regions
- Rights status
- Output dimensions
- Crop hash

# PART V — PROMPT CONSTRUCTION

## 19. Prompt completion contract

Every provider-ready prompt must be complete, specific and paste-ready.

A shot prompt must include:

- Start pose and frame composition.
- Exact allowed subject motion.
- Exact camera movement.
- Character appearance, clothing and prop details.
- Scene location, era and P/H/F mode.
- Lighting and colour treatment.
- Facial expression and emotional intensity.
- Environment motion.
- Transition into and out of the shot.
- Duration and 16:9 requirements.
- Prohibited changes.
- Source and likeness constraints.
- Any platform-specific control/seed/reference instructions actually available.

Do not present a generic example as an episode-specific prompt.

## 20. Prompt structure

```text
[MODEL-SPECIFIC MODE]

Animate or edit one authorized reference image for a Classies Chronicles media clip.

Source revision: [exact A/challenge/canon/comic revision]
Shot: [shot ID]
Beat: [exact narrative consequence]

Beginning frame:
[Exact composition, subject pose and spatial positions]

Subject motion:
[Only explicitly permitted motion]

Camera:
[Locked or exact controlled camera operation]

Environment:
[Only source-supported ambient movement]

Duration:
[Actual provider-supported length]
Output:
[16:9 widescreen, 1920x1080 or provider-supported equivalent]

Character continuity:
[Exact approved face, age, hair, skin, clothes and props]

Negative/failure avoidance:
[Wrong identity, face drift, anatomy defects, extra limbs,
invented text, changed costume, new people, unwanted location,
unearned action, stretched image]

End state:
[Exact final pose or held frame]

Do not add dialogue, new dialogue text, narration, labels, logos,
answer hints or story consequences not in the authorized beat.
```

## 21. Negative prompt policy

Where supported, tailor negatives to the specific shot:

- changed face or ethnicity
- age drift
- altered hairstyle or costume
- lost or gained limbs
- distorted hands or fingers
- extra people
- invented on-screen text
- fake news headline
- changed location or clock
- unapproved vehicle or technology
- stretched, mirrored or warped source
- excessive camera shake
- fabricated answer or hint
- added decorative logo
- background movement that contradicts the scene

Do not use one universal negative field for every shot.

## 22. Character image prompt

```text
Preserve the exact approved appearance of [character name]
using the supplied canon reference. Maintain [face proportion,
hair, skin tone, age, wardrobe, insignia and permitted injury].
For this shot only, [exact expression] and [exact physical action]
may change. Keep the body grounded and physically plausible.
Do not change any canon-supported feature or introduce a real-person
likeness not present in the authorized source.
```

## 23. Comic panel prompt

```text
Use the supplied crop from [comic page/panel ID] only as the
source composition. Preserve the depicted subject, costume,
setting and spatial arrangement. Convert the portrait crop to
16:9 using [F1/F2/F3/F4/F5]. Add only [named restrained motion].
Keep all speech, story text and terminal challenge unchanged.
Do not invent dialogue, erase story-critical art or add a new subject.
```

## 24. Stationary/edited still prompt

```text
Do not animate the depicted subject. Preserve every depicted
person and prop exactly in place. Add only [named environmental
movement or restrained camera movement]. Keep all facial features,
costume, text, era and clock state unchanged. Make no physical
action or causal transition beyond the depicted beat.
```

# PART VI — TIME AND STUDIO SEQUENCE

## 25. Timegrid rule

Choose the exact commissioned duration first.

If the source is mapped to ten-second acts:

- One 160-second version = sixteen acts.
- One 200-second Studio reference = twenty acts.
- A daily chronicle may use a different exact runtime.
- Provider clips may be 5, 8 or 10 seconds and must be segmented deliberately.

The public Challenge A must remain the final meaningful audiovisual and subtitle content.

## 26. Typical Studio pipeline

```text
STORY
  ↓
DAILY MANUSCRIPT / SOURCE LOCK
  ↓
SCRIPT
  ↓
CHARACTER / CANON REFERENCE
  ↓
COMIC / PANEL / STILL REFERENCE
  ↓
STORYBOARD / SHOT CARDS
  ↓
PROMPT PACK
  ↓
SHORT CLIPS / EDITOR MOTION
  ↓
VOICE / MUSIC / SFX
  ↓
CAPCUT OR AUTHORIZED EDITOR
  ↓
CAPTIONS / QA
  ↓
HUMAN APPROVAL
  ↓
AUTHORIZED EXPORT
```

Do not attempt an entire story in one free-generation call.

## 27. Clip segmentation

For a clip shorter than an act:

- Join only as one continuous editorial action.
- Maintain the same source frame, cast and spatial geography.
- Do not repeat the same action.
- Record every segment and overlap explicitly.
- Prefer editor-held still or subtle motion over forced provider continuation.

## 28. Workstation allocation

- **ENVY:** OBS master, host presentation and main program output.
- **Pavilion:** communications, AI Desk, REAPER stems and controlled AI/TTS use.
- **Samsung S24 Ultra:** B-roll and field capture.
- **IO Crest:** archive only, disconnected during live recording.
- **Reaper:** source stems and recovery.
- **CapCut:** editorial assembly and final social derivatives.
- **OBS:** master recording of live or mixed presentation only.

Do not claim a workstation exists or is available when it is not observed.

# PART VII — PROVIDERS AND FREE CREDIT ROUTING

## 29. Renewable free-credit policy

No provider is assumed to offer a daily, monthly or permanent allowance until the exact signed-in account is inspected.

The provider register has four evidence classes:

- **A:** vendor-documented recurring allowance with a verified still/image-to-motion route.
- **B:** vendor-documented recurring allowance, but exact video model or I2V availability remains conditional.
- **C:** evidence is unclear, promotional or region/account dependent.
- **D:** no credible evidence of renewing free I2V credits.

A/C tier is a routing candidate, not a promise.

## 30. Provider verification card

Before every real clip record:

- Provider and exact URL
- UTC verification date
- Account region
- Logged-in tier
- Model/version
- Source of free allowance
- Reset interval
- Remaining balance
- Per-generation cost
- Still-image support
- Maximum references
- 16:9 support
- Maximum duration
- Resolution/FPS
- Watermark
- Commercial/derivative terms
- Upload/privacy terms
- Card or phone requirement
- Retention/training policy
- Provider UI control names
- Retry reserve
- Evidence screenshot or official documentation reference

Commercial rights are not established merely because free credits exist.

## 31. Credit arithmetic

```text
available_balance = verified remaining credits
cost_per_success = model-specific measured or vendor-published cost
retry_reserve = owner-authorized reserved credits
safe_attempts = floor((available_balance - retry_reserve) / cost_per_success)
```

Do not calculate a retry reserve below existing provider minimum or from an account other than the one being used.

- Licensed TTS class

- Dialogue/narration
- Music
- Ambience
- Foley
- Sound effects
- Mix reference
- Accessibility/mix-minus

Target human intelligible dialogue and defensible loudness for the actual delivery platform. 48 kHz is a target; never silently alter source sample rate without a readback check.

## 37. Captions and description

- Generate VTT/SRT from final audio.
- Recheck after every final edit.
- Keep text inside safe margins.
- Preserve names and exact public Challenge A.
- Do not put the challenge answer in a caption or alt text.
- Provide transcript and optional audio description when commissioned.

## 38. Public safety

Block or stop for:

- Central-source approval failure
- Key/canon contradiction
- Essential rights or consent failure
- Materially false current/historical/probe claim
- Identity drift using a real person
- Challenge answer or revealing hint
- Unverified watermark/commercial license
- False provenance or availability claim
- Photosensitive or unsafe motion
- A public text/visual lock mismatch
